# DomainPlane 架构设计文档

面向架构师 / 部署方。描述系统的静态形态、模块划分、部署形态、运行时调用链路与配置总表。
领域规则、工具体系、检索、入库切片等深层设计见 `详细设计文档.md`；全部 HTTP / SDK 契约见 `接口文档.md`；场景与选型见 `用例文档.md`。

## 1 系统定位与交付形态

DomainPlane 是面向 **AI Agent 编排与工具治理** 的 Java 中间件。核心差异是**请求级装配**：同一套服务按每轮传入的「域」实时裁剪工具 / 提示词 / 模型 / 知识，越权时显式拒绝而不是静默降级。

交付形态：**一个服务端 + 三个按需引入的 SDK**。

| 交付物 | 模块 | 部署位置 |
| --- | --- | --- |
| 服务端（独立进程） | `domainplane-server` | 客户自部署，端口 `9527`（`server.port` / `DOMAINPLANE_SERVER_PORT`） |
| 对话 SDK | `domainplane-chat-client` | 引入调用方业务应用，提供 `DomainPlaneAgentFactory`（唯一入口：`forDomain` → `ask`/`stream`/`events`/`resume`/`stop`） |
| 知识库 SDK | `domainplane-kb-client` | 引入调用方业务应用，提供 `KnowledgeBaseClient`（上传 / 列表 / 删除） |
| 工具 SDK | `domainplane-tool-provider` | 引入工具提供方应用，把本地方法注册到服务端（开关 `domainplane.tools`） |
| 客户端底座（传递） | `domainplane-client-core` | WebClient / 凭证 / 错误翻译 / 启动探测，被对话与知识库 SDK 共用 |
| 共享契约层（传递） | `domainplane-sdk-core` | 对外契约 + 公共异常 + 服务端连接配置（`domainplane.server` / `username` / `password` / `tools`） |

形态约束：

- 服务端不提供开箱业务 Controller，只暴露 `AgentService` 契约；消费侧对应 **`DomainPlaneAgent` 门面**（`forDomain(...)` 时绑定域，之后 `ask`/`stream`/`events`/`resume`/`stop` 都不带域参数）。裸 HTTP 入口接受 `domain`（必填，见 `接口文档.md` §2.3）。
- 服务端 **不内置任何业务知识文档**；文档由部署方通过上传接口导入。
- 服务端不做 SaaS：**单实例部署**——工具注册表在进程内存、知识库导入为进程内串行锁、判死扫描为进程内定时器，因此多实例不成立；扩容只能纵向。
- 停机为**优雅停机**（`server.shutdown=graceful`，等待上限 30s）：先停止接收新请求，在途请求（含 SSE 长连接）收尾后再退出。
- 工具可来自两个位置——调方进程内的本地 Bean，或独立进程的工具实例（通过 HTTP 注册）。

## 2 模块划分

| 模块 | 职责 | 主要包 |
| --- | --- | --- |
| `domainplane-api` | 对外契约：错误码、注解、`ToolDescriptor`、`AgentRequest`/`AgentEvent`、`TraceId`、`AgentService`、`Tool` 注解全家桶 | `api.code` `api.annotation` `api.tool` `api.agent` `api.support` |
| `domainplane-common` | 异常基类与通用工具 | `common.exception` `common.util` |
| `domainplane-domain` | 领域能力：知识检索、混合检索与融合排序、会话记忆约束、域注册表 | `domain.capability.knowledge` `domain.rag` `domain.memory` `domain` |
| `domainplane-infrastructure` | 外部依赖适配：ES 检索器与索引管理、文档摄取与切片、Redis 记忆与检查点、向量化 | `infrastructure.elasticsearch` `infrastructure.ingestion` `infrastructure.redis` `infrastructure.embedding` |
| `domainplane-runtime` | 运行时内核：编排图、工具注册表与路由、实例注册表、流式上下文、提示词解析、取消、模型解析 | `runtime.graph` `runtime.tool` `runtime.stream` `runtime.prompt` `runtime.cancellation` `runtime.orchestration` `runtime.model` `runtime.domain` |
| `domainplane-server` | 服务端：配置装配、管控接口、鉴权、设置存储、异常处理出口、静态管控台、模型档案与域管理 | `server.config` `server.controller` `server.auth` `server.settings` `server.knowledge` `server.advice` `server.prompt` `server.model` |
| `domainplane-sdk-core` | 共享契约层：被三个 SDK 共同依赖，承载对外契约（`api`）、公共异常（`common`）与服务端连接配置 | `sdkcore` |
| `domainplane-client-core` | 客户端底座：`WebClient` 装配、`ClientCredential`（凭证换取与缓存）、传输层错误翻译、启动期连通性探测 | `clientcore` |
| `domainplane-chat-client` | 对话 SDK：`AgentServiceClient`（内部通道）、**唯一入口** `DomainPlaneAgent` | `chatclient` |
| `domainplane-kb-client` | 知识库 SDK：`KnowledgeBaseClient`（上传 / 列表 / 删除） | `kbclient` |
| `domainplane-tool-provider` | 工具实例 SDK：注解扫描、注册与心跳、反向调用端点 | `toolprovider` |

依赖方向：`api → common → domain → infrastructure → runtime → server`；`sdk-core` 依赖 `api` + `common`；`client-core` 依赖 `sdk-core`；`chat-client` 与 `kb-client` 都依赖 `client-core`（两者互不依赖）；`tool-provider` 只依赖 `sdk-core`（与服务端只通过 HTTP 报文耦合）。

消费侧依赖边界：三个 SDK **按需引入、互不依赖** —— 要对话引 `domainplane-chat-client`，要知识库引 `domainplane-kb-client`，要当工具方引 `domainplane-tool-provider`；同时引多个也不冲突，因为公共底座（`client-core` 的 WebClient / 凭证 / 启动探测）与公共契约（`sdk-core`）都是传递依赖，且以 `@ConditionalOnMissingBean` 装配，只会装配一份。工具能力仍默认关闭：`domainplane.tools` 未开启时不注册回调端点、不启动心跳、不建任何工具实例 Bean。**Web 容器始终归宿主**：三个 SDK 都只用 `spring-web` 的注解模型与出站 `WebClient`，不引容器；宿主已有 Servlet 栈时共存仍判定为 SERVLET，若把容器写进 SDK，纯 WebFlux 宿主会被判成 SERVLET 而失去 `DispatcherHandler` 装配。

## 3 部署形态

### 3.1 前置与约束

| 项 | 要求 |
| --- | --- |
| 运行时 | JDK 21+（镜像已内置 JRE 21） |
| 端口 | 默认 `9527`，可用 `SERVER_PORT` 环境变量 / `-Dserver.port=` / `--server.port=` 覆盖 |
| 实例数 | **单实例**（见 §3.4） |
| 依赖 | Elasticsearch（9.x 已验证 / 8.x 可用 / 更低需自验，需 IK 分词器）、Redis 6+、一个 OpenAI 兼容模型服务（对话 + 向量） |
| 存储 | ES / Redis **可与业务共用**：Redis key 统一 `domainplane:` 前缀、ES 索引统一 `domainplane_` 前缀，连接各自独立 |

依赖不是启动前置：ES / Redis / 模型全都没配也能启动（知识库索引都是按需创建的，启动期无事可做），进去填完即生效。这是刻意设计——否则会形成"起不来 → 管控台打不开 → 配置填不上"的死锁。

### 3.2 落盘与配置

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `domainplane.settings.path` | `/var/lib/domainplane/config` | 账号、模型设置、存储连接、域提示词 |
| `domainplane.logging.path` | `/var/log/domainplane` | 只在开启文件日志时使用 |
| `domainplane.export.path` | `/var/lib/domainplane/chunks` | 切片预览 txt（上传后每文档一个，供人工核对切点） |
| `domainplane.logging.level` | `INFO` | 根日志级别 |

- 三个目录都是**服务器绝对路径**，不随"从哪个目录启动"漂移；目录不存在时由写入方自动创建。
- 可用环境变量 `DOMAINPLANE_SETTINGS_PATH` / `DOMAINPLANE_LOG_PATH` / `DOMAINPLANE_EXPORT_PATH` 覆盖。
- **本机开发务必覆盖 `DOMAINPLANE_SETTINGS_PATH`**，否则会写到本盘根目录下的 `var/lib/...`。
- 落盘的四个 json：`accounts.json`（账号，BCrypt 哈希）、`llm-settings.json`（模型与 Key）、`infra-settings.json`（ES / Redis 连接）、`prompts.json`（域提示词）。

为什么配置不存 ES/Redis：配置正是用来「找到 ES/Redis 的」；一旦存进中间件，地址填错就再也读不出来，管控台失联 → 死锁。文件是本机唯一无外部依赖的介质。

### 3.3 部署方式

服务端是**平台无关的单文件 fat jar**：一份构建产物，在 Linux / Windows / macOS（含其他 Unix 类）上直接 `java -jar` 即可运行，无需为目标系统重新构建。

**启动期自动探测运行系统**（`RuntimeEnvironment` 在 Spring 装配前判定 OS 族，自动选定配置 / 日志 / 切片导出目录并提前建好）：

- Linux / 其他 Unix：`/var/lib/domainplane/config`、`/var/log/domainplane`、`/var/lib/domainplane/chunks`
- Windows：`%ProgramData%\DomainPlane\config`、`%ProgramData%\DomainPlane\logs`、`%ProgramData%\DomainPlane\chunks`
- macOS：`/Library/Application Support/DomainPlane/config`、`/Library/Logs/DomainPlane`、`/Library/Application Support/DomainPlane/chunks`

**覆盖优先级**：命令行 `--key` ＞ JVM 系统属性 `-Dkey` ＞ 环境变量 ＞ 平台默认。

**容器部署**：Docker / K8s 只需换对应基底镜像（如 `eclipse-temurin:21-jre`），jar 不变；容器运行时（kubernetes / docker / podman）会在启动横幅中显示，便于排障。
- 配置目录必须挂卷（用命名卷，别 bind mount 到宿主目录——uid 不匹配会写不进去）。
- 日志默认走 stdout，`docker logs` 直接可用；要落盘再加 `--logging.config=classpath:logback-file.xml` 并挂 `/var/log/domainplane`。
- K8s 探针：`/health` 只表示"进程能对外服务"，**不检查 ES / Redis / 模型**；`replicas` 只能填 `1`。

**裸机（systemd）** 与 **容器 / docker-compose** 的配置示例见原 `DEPLOYMENT.md`（已并入本文定位，示例略，按实际路径替换即可）。

### 3.4 单实例契约与扩容

**当前版本只支持单实例部署**，原因不在"能不能起两个进程"，而在状态：

- **会话协调状态全部在进程内存** —— 会话占用闸门、停止标志、流注册表都是 `ConcurrentHashMap`，没有跨实例协调。两个实例共用一个 Redis 时，同一会话打到两边，两边的"占用"闸门都会通过 → 并发执行 → 记忆丢更新、断点互相覆盖；
- **`stop` 可能停错实例** —— 停止标志设在收到请求的那个实例，真正在执行的那个看不到它，任务会跑完并写进记忆，而接口返回 `stopRequested: true`（用户以为停了，其实没停）；
- 工具注册表在进程内存 —— 两个实例各自维护一份，外部实例必须向**每一个**实例注册；
- 知识库导入是进程内串行锁 —— 多实例之间不互斥，会出现同名文档并发写入；
- 判死扫描是进程内定时器 —— 各扫各的，实例视图会分叉。

这类失败的共同点是**不报错**，等发现时用户数据已经串了。因此启动时做一次**单实例守卫** —— 在 Redis 上以 `SET NX` 抢一个带 TTL（90s）的运行权租约，抢不到就直接拒绝启动。优雅停机时会释放租约，因此正常重启不会被自己的租约挡住。确实需要临时绕过：`domainplane.single-instance-guard=false`（绕过前请先确认 Redis 上真的只有一个 DomainPlane 在跑）。

**纵向扩容（加 CPU / 内存 / 提高线程池）是当前唯一受支持的扩容方式**。K8s 里 `replicas` 固定 `1`；滚动升级会短暂中断服务（每次只有一个实例，没有冗余）。

### 3.5 容量与限流现状

- **已实现**：编排线程池满时拒绝并回报 `SYSTEM_BUSY(20002)`；同一 `sessionId` 并发直接拒绝 `SESSION_BUSY(30003)`；会话记忆到上限拒绝新一轮 `SESSION_MEMORY_FULL(30004)`（换 `sessionId`，平台不代为切换）。
- **未实现**：入口限流（`RATE_LIMITED 20000`）、大模型侧限流映射（`LLM_RATE_LIMITED 20001`）、并发会话数上限（`CONCURRENT_LIMIT 20003`）—— 三个码已定义但代码中不会发出。
- **Redis 容量的硬要求**（记忆是长期存储，默认不过期）：
  - 必须给 Redis 设 `maxmemory-policy noeviction` —— 否则内存紧张时 Redis 直接淘汰记忆 key = 随机丢用户历史；
  - 但 `noeviction` 下写满会导致写入失败（对话报错 `70002`），因此 `maxmemory` 必须按容量预估配置，并对 `used_memory / maxmemory` 做 80% 告警；
  - 量级参考：单会话上限约 **60–120 KB**（100 条 / 30k token）；**1 万个封顶会话 ≈ 0.6–1.2 GB**；
  - 必须开持久化：`appendonly yes` + `appendfsync everysec`（最坏丢 1 秒）。启动期自检会检查这两项并告警（`RedisPersistenceAudit`，只提醒不阻断；受管 Redis 禁用 `CONFIG` 时跳过）；
  - 归档/清理目前没有自动机制：封顶会话的数据要清只能手工 `DEL domainplane:chat:memory:*`。

### 3.6 备份与恢复

**要备份的只有 `domainplane.settings.path` 这一个目录**——它是唯一状态，工具注册与域都不落盘。

```bash
# 备份（配置很小，直接打包即可；里面有 API Key，注意存放权限）
tar czf domainplane-config-$(date +%F).tgz -C /var/lib/domainplane config
# 恢复：停服务 → 覆盖目录 → 启服务（权限要与运行用户一致）
```

| 场景 | 处置 |
| --- | --- |
| 配置目录整体丢失 | 用最近备份恢复；无备份则回落种子账号，模型与存储配置需重填 |
| 只是忘了密码 | 删 `config/accounts.json` 后重启 → 回落 `domainplane / domainplane`（唯一的找回路径） |
| 账号文件读不出来（`10007`） | 服务端会拒绝一切受保护请求且不开放初始化入口；修好或删除该文件后重启 |

## 4 运行时调用链路

```
调用方（业务应用，含 starter）
  │  POST /api/agent/chat    Header: X-DomainPlane-Credential
  ▼
ServerAgentController ──► AgentOrchestrationService ──► agentExecutor 线程池
                                    │
                                    ▼
                        LangGraph4j 编排图（检查点存 Redis）
                        ┌─────────────┐
                        │  agentNode  │ 注入 SystemMessage + 本轮可见工具集
                        └──────┬──────┘
                               │ 有工具调用
                        ┌──────▼──────┐        ┌──────────────┐
                        │  toolsNode  │───────►│  ToolRouter   │  实时读注册表
                        └──────┬──────┘        └──────┬───────┘
                               │                      │ 本地 Bean / 远程实例
                               │ 命中审批策略          ▼
                        ┌──────▼──────┐        POST {endpoint}
                        │ reviewNode  │        （工具实例）
                        └─────────────┘
                               │ 中断
                               ▼
                 SSE 事件流（TOKEN / TOOL_CALL / TOOL_RESULT / INTERRUPT / STOPPED / ERROR / DONE）
```

- 会话身份：`sessionId` 由调用方提供，作为域内唯一键；状态按 `(域, sessionId)` 隔离——同一个 `sessionId` 可在不同域各用一份。裸 HTTP 通道每轮显式带 `domain`；SDK 在取门面（`forDomain`）时绑死域，方法签名里不再出现。
- 每个执行单元（一次 `orchestrate` 及其全部 `resume`）内，`domain` 与提示词冻结；单元之间取最新值。`resume` 必须带与 `chat` 相同的 `domain`，否则找不到断点（`30001`）。
- 记忆、检查点、流式上下文三者相互独立：记忆存 Redis（`domainplane:chat:memory:*`），检查点存 Redis（`graph:checkpoint:*`），事件流只走 HTTP 响应。
- 主循环形状不变：`agent → 条件边(exit|auto|review) → tools → agent`。

## 5 域：核心抽象（高层）

> 完整规则见 `详细设计文档.md` §1。此处仅给架构视角。

**域（domain）＝一次对话的场景**，同时绑定【工具集 + 系统提示词 + 知识范围 + 模型】四个维度。域是一棵**树**，标识是**从根域 `default` 出发的完整路径**（点分，如 `default.sales.order`）。主键与展示同形，不存在"同名不同父"的歧义。

- 四个维度共用同一套**沿链累加**语义：工具可见性（声明命中自身或祖先）、知识库（自身 ∪ 全部祖先）、提示词（从根到自身依次拼接）、模型绑定（自身没绑就向上找最近的绑定）。公共内容只需在根域写一次。
- 两种角色：**可调用单元**（能作为入口）与**装配节点**（只把能力传给后代，不能当入口）。硬约束是**叶子规则**：**只有叶子域（无子域）才能作为可调用单元**；根域同样服从这条规则。
- 三个**来源**（`BUILTIN` 根域 / `MANUAL` 人工创建 / `DERIVED` 工具声明派生）**同级，不构成等级**；差异只在生命周期。

## 6 管控台

| 项 | 规定 |
| --- | --- |
| 入口 | `http://localhost:9527/admin.html`（转发到 `console/overview.html`）；登录页 `console/login.html` |
| 页面 | 8 项：概览、模型设置、存储配置、域空间、在线实例、提示词设定、知识库、账号 |
| 静态资源 | `static/admin.html` + `static/console/*.html` + `console/assets/console.css`、`console/assets/console.js`；零依赖、不引 CDN |
| 导航 | 由 `console.js` 的 `renderSidebar()` 渲染；新增页面＝落一个 HTML + 在导航数组加项 |
| 登录守卫 | 在 `console.js` 中统一实现（加载时查 `/admin/session`，收到 `10002` 跳登录页） |
| 同源要求 | 必须从服务端地址打开：凭证是 Cookie，跨站时不保存也不携带 |
| 服务端依赖 | 页面不内置任何配置数据，全部经 `/admin/**` 读取 |

## 8 快速开始

### 8.1 环境要求

- JDK 21+、Maven 3.8+
- Elasticsearch 9.x（已验证；8.x 可用；更低版本需自行验证）—— 需安装 IK 分词器插件
- Redis 6+
- 一个 OpenAI 兼容的模型服务（对话模型 + 向量模型）

ES / Redis **可与业务系统共用同一套实例**：数据层通过私有命名空间隔离（Redis key 统一 `domainplane:` 前缀、ES 索引统一 `domainplane_` 前缀），双方各自建立独立连接，互不影响。

### 8.2 启动服务端

```bash
# 方式一：直接跑（开发时用）
mvn -pl domainplane-server -am install
mvn -pl domainplane-server spring-boot:run          # 默认端口 9527

# 方式二：打成 fat jar 跑（部署时用）
mvn -DskipTests package
java -jar domainplane-server/target/domainplane-v1.0-beta.1.jar
```

**不需要预先准备配置文件**。服务端在未配置状态下即可启动，启动后打开管控台填写：

```
http://localhost:9527/admin.html      # 默认账号 domainplane / domainplane
```

依次在「模型设置」添加对话模型与向量模型（向量模型从已添加的向量档案里选一个）、「存储配置」填 ES 与 Redis。

### 8.3 接入你的应用

```xml
<!-- 对话：只要"能问 AI"就引这个 -->
<dependency>
    <groupId>com.zzkingcc</groupId>
    <artifactId>domainplane-chat-client</artifactId>
    <version>v1.0-beta.1</version>
</dependency>
<!-- 知识库：要把文档传进去就再引这个 -->
<dependency>
    <groupId>com.zzkingcc</groupId>
    <artifactId>domainplane-kb-client</artifactId>
    <version>v1.0-beta.1</version>
</dependency>
```

```yaml
domainplane:
  server: http://localhost:9527   # 对话 SDK / 知识库 SDK / 工具实例共用这一份
  username: domainplane
  password: domainplane
```

> **服务端必须先启动**。引入 starter 的应用在启动完成前会换取签名凭证并探测服务端健康状态，连不上或账号密码错误会**直接中断启动**。凭证不设有效期，正常路径下登录只发生一次；服务端改过密码后客户端会自动重登一次，仍失败则中断启动并提示原因。

### 8.4 注入一个 Bean，问一句话

SDK 只提供一个入口 `DomainPlaneAgent`：**先绑域，再调用**。

```java
@Service
public class MyService {
    private final DomainPlaneAgent agent;                 // 已绑定域，可缓存复用、线程安全

    public MyService(DomainPlaneAgentFactory factory) {
        this.agent = factory.forDomain("default.customer");   // 必须是叶子域的完整路径
    }

    public String ask(String sessionId, String question) {
        return agent.ask(sessionId, question);
    }
}
```

命中人工审批时 `ask` / `stream` 抛 `ApprovalRequiredException`（带待审批工具清单），用户确认后 `agent.resume(sessionId, true)` 继续。

### 8.5 端到端最小跑通

1. 起服务端：`java -jar domainplane-v1.0-beta.1.jar`（默认 9527）。
2. 打开管控台登录，在「模型设置」与「存储配置」两页填好配置。
3. 在「域空间」建一个叶子域（如 `default.customer`）。
4. 写接入方应用：引 `domainplane-chat-client`，配好地址，`forDomain` 取门面后 `ask`。
5. 验证工具：再加 `domainplane-tool-provider`、打开 `domainplane.tools=true`，用 `@Tool` 声明方法，到「在线实例」确认。
6. 验证知识库：管控台「知识库」上传文档并选归属域，再在该域对话检索。
