# 向量维度 / 向量模型变更 · 分支梳理

面向"改维度、换模型时到底该提示什么、知识库要不要重建"这一组决策。
所有结论都对着当前代码（AdminModelProfileController / LlmModelHolder / KnowledgeBaseService）。

## 一、前提：维度必须"三处同源"

维度是向量链路上唯一改不回来的契约，它同时活在三个地方：

| # | 位置 | 谁写入 | 能不能改 |
|---|---|---|---|
| 1 | 档案声明的 dimensions（config/models.json） | 卡片「更改」/ 弹窗「保存」 | 随时可改 |
| 2 | 运行期 EmbeddingModel 的 dimensions | LlmModelHolder.rebuildEmbedding() | 改完档案要 refreshEmbedding() 才生效 |
| 3 | ES 索引 mapping 的 dims | KnowledgeBaseService.ensureIndex() | 建好就改不了，只能删索引重建 |

三种错配的后果不一样，这是判断"要不要重建"的全部依据：

- 2 落后于 1：运行期还在用旧配置算向量 —— 表现为"改了没生效"。
- 3 落后于 2：写入被 ES 以维度不符拒绝，检索一起报错。
- 3 与新模型的向量空间不同（换了模型但维度一样）：不报错，检索质量静默下降，最难发现。

因此"要不要重建"的正确判据是：**索引实际维度（currentVectorDims）与即将生效的新维度是否相等**。
注意不是"索引里有没有切片"—— 空索引的 mapping 一样是旧维度，一样会挡住新维度写入。

## 二、六个入口

| 入口 | 前端动作 | 接口 | 服务端方法 |
|---|---|---|---|
| A 新建 / 覆盖档案 | 弹窗「保存」 | POST /admin/model-profiles | AdminModelProfileController.save() |
| B 卡片改参数 | 卡片「更改」 | POST /admin/model-profiles/params | saveParams() |
| C 启用 / 切换向量模型 | 卡片「启用」 | PUT /admin/embedding-model | selectEmbeddingModel() |
| D 保留原文重灌 | 无前端入口 | POST /admin/embedding-model/rebuild | rebuildKnowledge() |
| E 丢弃全部知识库 | 无前端入口 | POST /admin/embedding-model/purge | purgeKnowledge() |
| F 删除档案 | 卡片「删除」 | DELETE /admin/model-profiles?alias= | delete() |
| G 清空重建（知识库页） | 「重建索引」按钮 | POST /admin/kb/rebuild | AdminController.rebuildKnowledgeIndex() |

D、E 两个接口没有前端调用方；知识库页那个按钮走的是 G，语义是"删掉重建、索引清空、文档要重新上传"。

## 三、四个判定变量

| 变量 | 来源 | 含义 |
|---|---|---|
| isEmb | profile.isEmbedding() | 档案是不是向量档案（endpoints 含 embedding） |
| isActive | alias == registry.embeddingAlias() | 是不是当前启用的那一个 |
| dimChanged | !Objects.equals(旧维度, 新维度) | 维度变了没（null 与值互转也算） |
| hasVectors | existingIndices() > 0 且 totalIndexedDocuments() > 0 | 索引里是不是真有切片 |

ES 读不到时，索引数与文档数都按 0 降级（只记 WARN），于是 hasVectors = false —— 所有二次确认被静默跳过。

## 四、分支矩阵

### A 新建 / 覆盖档案（save）

| 条件 | 探测 | 二次确认 | 知识库动作 | 提示 |
|---|---|---|---|---|
| 未声明维度，或非向量档案 | 跳过 | 无 | 无 | 保存成功 |
| 声明了维度，探测通过 | 必须通过 | 无 | 无 | 保存成功 |
| 声明了维度，探测失败 | 拒绝 | — | — | 报错 + 原因 |
| 别名与当前启用向量模型同名（覆盖） | 同上一行 | 无 | 无 | 保存成功 ← 缺口 2 |

save() 传 existing = null，所以"声明了维度"就一律要探测，没有"值没变就跳过"这条捷径。

### B 卡片「更改」（saveParams）

| # | 档案类型 | 当前启用 | 维度变化 | 知识库 | 结果 |
|---|---|---|---|---|---|
| B1 | 非向量 | — | 提交了维度 | — | 拒绝：只有向量模型（endpoints 含 embedding）才能设置 dimensions |
| B2 | 向量 | 否 | 没变 | — | 保存，无探测，无知识库动作，提示「参数已更新」 |
| B3 | 向量 | 否 | 变了 | — | 探测通过后保存，无知识库动作，提示「参数已更新」 ← 缺口 5 |
| B4 | 向量 | 是 | 没变 | — | 保存，跳过探测，提示「参数已更新」 ← 缺口 3 |
| B5 | 向量 | 是 | 变了 | 无切片（含空索引、ES 读不到） | 保存 + refreshEmbedding，提示「向量维度已更新」，不重建 ← 缺口 1 |
| B6 | 向量 | 是 | 变了 | 有切片 | 见下方 B6 流程 |

B1 在 UI 上到不了（非 embedding 档案不渲染维度输入框），只有直接打接口才会命中。

B6 流程：

1. 首次请求不写任何东西，返回 requiresConfirmation + previousDimensions / nextDimensions / affectedIndices / documentCount。
2. 前端把 message 拼成确认框：确定 = rebuild，取消后二次确认 = purge，再取消 = 什么都不做。
3. mode = rebuild 时重发：保存 → refreshEmbedding → rebuildPreservingText(新维度)，提示「向量维度已更新」。
4. mode = purge 时重发：保存 → refreshEmbedding → purgeAll，提示同上。
5. 用户取消：不发请求，维度不保存。

把维度清空（提交 null）也走 B5 / B6 同一套，只是跳过探测。

顺序上 refreshEmbedding 在重灌之前，反了就会拿旧模型算一遍。

### C 启用 / 切换向量模型（selectEmbeddingModel）

| # | 场景 | 结果 |
|---|---|---|
| C1 | 档案不存在 / 非向量 / 不可用 | setEmbeddingAlias 里拒绝 |
| C2 | 与当前 alias 相同 | changed = false，提示「向量模型没有变化」，不动知识库 |
| C3 | 换了模型，无切片 | 直接生效 + refreshEmbedding，提示「（知识库暂无内容，直接生效）」 ← 缺口 1 |
| C4 | 换了模型，有切片，无 mode | 撤销单选 + requiresConfirmation |
| C5 | 同上，mode = rebuild | 生效 + refresh + rebuildPreservingText |
| C6 | 同上，mode = purge | 生效 + refresh + purgeAll |
| C7 | alias = null（取消配置），有切片 | 同 C4 弹确认，但选 rebuild 会抛 NotConfiguredException ← 缺口 4 |

C4/C7 的确认框文案由 describeSwitchImpact() 生成：说明旧模型、新模型、有几个索引有内容，然后给"用新向量重灌"和"直接丢弃"两条路。

C6 之后索引被全删；C5 保留原文，不用重新上传。

### F 删除档案（delete）

- 级联把所有域绑定里的该别名摘掉，被摘空的域立即进入"无可调用"。
- 若删的正是当前向量模型：一并撤销配置 + refreshEmbedding，之后 isEmbeddingConfigured() = false（灌库与向量检索停用）。
- 索引与已灌库的向量**保留不动**，索引 mapping 维度也不变。
- 前端只弹一句 confirm 提示，没有 rebuild / purge 选择。

之后再启用别的模型，走 C 入口，有内容就会弹确认 —— 这条兜住了。

## 五、知识库到底要不要重建

| 场景 | 需要重建 | 现状行为 |
|---|---|---|
| 改维度，索引里有切片 | 需要 | 重建（B6） |
| 改维度，索引为空 / 无索引 | 空索引也要重建 mapping | 不重建（B5）← 缺口 1 |
| 换模型，维度相同，有切片 | 需要（向量空间变了） | 重建（C5） |
| 换模型，有切片 | 需要 | 重建（C5） |
| 换模型，索引为空 | 空索引也要重建 mapping | 不重建（C3）← 缺口 1 |
| 只改温度 / topP 等非维度参数 | 不需要 | 不动 |
| 新建一份新别名的档案 | 不需要 | 不动 |
| 删除当前向量模型 | 不需要（索引原样保留） | 不动 |
| 覆盖同名档案（A 入口） | 需要 | 完全不动 ← 缺口 2 |

## 六、提示文案对照

| 出现位置 | 文案 |
|---|---|
| B2 / B3 / B4 | 参数已更新 |
| B5 / B6 | 向量维度已更新 |
| B6 确认框 | 向量维度由 X 改为 Y，已灌库的向量会因长度不符而作废 |
| B6 确认框补充 | 确定 = 用新向量重灌（文档无需重新上传）；取消 = 丢弃全部知识库内容 |
| C2 | 向量模型没有变化 |
| C3 | 向量模型已由 A 切换为 B（知识库暂无内容，直接生效） |
| C4 确认框 | 向量模型将由 A 变为 B，知识库中已灌库的向量会全部作废（附两条处理方式） |
| C5 | 向量模型已切换为 B，知识库原文已按新向量重灌（文档无需重新上传） |
| C6 | 向量模型已切换为 B，并已按你的选择丢弃全部知识库内容 |
| F | 已删除档案 X（它正是当前向量模型），向量配置一并取消：知识库检索与灌库已停用 |
| G | 已按维度 X 重建 N 个索引；索引已清空，请重新上传知识库文档 |

## 七、缺口清单

按影响面排序，前两条会直接导致"三处不一致"。

1. 空索引挡住重建（B5、C3）
   hasVectors 只看有没有切片，不看索引 mapping 的实际维度。有索引但没切片时改维度 / 换模型都不重建，
   而索引 mapping 还是旧维度，refreshEmbedding 之后运行期按新维度算向量 —— 下次灌库直接被 ES 拒绝。
   判据应改成 currentVectorDims() != 新维度。AdminController.checkEmbeddingDimension 已经是这么做的，
   档案页这两处没跟上。

2. 覆盖同名档案既不确认也不刷新运行期（A 入口）
   save() 只做探测就落盘：不判断是不是当前启用的那个，不 refreshEmbedding，不碰知识库。
   别名与当前启用向量模型同名时会写出"档案已改、运行期没改、索引也没改"的三方不一致。
   现在靠前端派生别名 + 查重绕开了，但接口本身没有这道防线。

3. 维度与原值相同时跳过探测（B4）
   历史被放行过的错值一旦写进档案，再点「更改」永远不会重探，用户会以为"校验过了"。
   可以让"维度非空 + 点了更改"就重探一次，或在卡片上给一个显式的"重新检测"。

4. 取消向量配置时选 rebuild 会抛异常（C7）
   alias = null 且知识库有内容：弹确认 → 用户选 rebuild → effectiveEmbeddingDimension() 抛
   NotConfiguredException（模型已卸载，无从取维度）。取消配置应当只给"保留索引但停用检索"和
   "清空索引"两个选项，rebuild 没有意义。

5. 提示文案不区分"启用中"与"没启用"（B3）
   改没启用的向量档案维度时，回报的是「参数已更新」，看不出维度已经改了。
   文案应按"维度是否变化"决定，而不是按"是否当前启用"。

6. ES 读不到时按"无内容"降级（B5、C3）
   existingIndexCount() / totalIndexedDocuments() 失败一律按 0 处理，二次确认被静默跳过。
   若 ES 只是临时不可达，用户会看到"没有内容"的假象，而实际有一堆索引停在旧维度上。

7. "保留原文重灌"没有手动入口
   /admin/embedding-model/rebuild 没有前端调用方；知识库页的按钮走 /admin/kb/rebuild，
   语义是删掉重建、索引清空、文档要重新上传。所以 B5 / C3 漏掉重建之后，用户没有任何
   "不重新上传就能修回来"的按钮。

## 八、判定顺序建议（供改代码时对照）

saveParams 里理想的判定顺序：

1. 维度为空 → 直接保存（但若原本有值且是启用中的模型，仍要按"维度变化"走确认）。
2. 非向量档案 → 拒绝。
3. 维度与原值相同 → 跳过探测。
4. 探测：先取原生维度，相等即通过；不等则带参探测，失败一律拒绝。
5. 取 indexDims = currentVectorDims()，needsRebuild = indexDims != null 且 indexDims != 新维度。
6. isActive 且 needsRebuild 且未确认 → 返回 requiresConfirmation。
7. 保存 → refreshEmbedding() → 按 mode 重灌或清空。
