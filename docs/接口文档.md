# DomainPlane 接口文档

适用对象：接入方（业务应用）、工具实例提供方、运维（管控台接口）。
内部设计背景见 `架构设计文档.md` 与 `详细设计文档.md`。

---

## 1 通用约定

### 1.1 基地址与端口

服务端默认监听 `9527`。本文所有路径均为相对路径，示例基地址 `http://localhost:9527`。

### 1.2 鉴权

| 接口组 | 载具 | 说明 |
| --- | --- | --- |
| `/api/agent/**` | 请求头 `X-DomainPlane-Credential` | 凭证由 `POST /api/agent/login` 获取 |
| `/admin/**` | Cookie `domainplane_admin` | 无 Cookie 时回退读 `X-DomainPlane-Credential` 请求头，供程序化调用 |

免鉴权路径：`/api/agent/login`、`/admin/login`、`/admin/init`、`/admin/session`、登录页与静态资源（`/admin.html`、`/login.html`、`/console/**`）、`/error`、`/favicon.ico`。`OPTIONS` 请求一律放行。

`GET /health`（存活探测）不在上述任一拦截前缀下，天然免鉴权。

拦截器另有两条全局前置规则，先于免鉴权清单判定：

| 状态 | 行为 | 依据 |
| --- | --- | --- |
| 账号文件存在但无法解析 | 拒绝一切受保护请求，返回 `10007 AUTH_STORE_CORRUPTED`（HTTP 503） | `CredentialAuthInterceptor:58-63` |
| 服务端尚无账号（未初始化） | 放行且不校验凭证，首次 `POST /admin/init` 因此可达 | `CredentialAuthInterceptor:65-71` |

即"免鉴权"只在账号已初始化之后才是真正的鉴权边界。凭证无效时统一返回 `10002 AUTH_REQUIRED`（HTTP 401），`detail` 按"未携带凭证"与"凭证已失效"两种情形区分。

凭证格式：`base64url(payload) + "." + base64url(HMAC(派生密钥, payload))`；派生密钥由主密钥与当前密码哈希导出，改密码后全部旧凭证立即失效。凭证无有效期。

### 1.3 响应体

非流式失败响应（`ServerGlobalExceptionHandler` 输出）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | int | 错误码，见第 5 节 |
| `codeName` | String | 错误码枚举名，前端应以它分支 |
| `error` | String | 枚举默认文案 |
| `detail` | String | 具体原因（调试用） |
| `retryable` | boolean | 是否可退避重试 |
| `action` | String | 建议动作 |
| `traceId` | String | 排障标识 |
| `timestamp` | long | 毫秒时间戳 |

成功响应结构不统一：`/admin/**` 多数返回自定义字段并带 `code=0`；表结构、文档列表等接口返回业务字段本身。前端不应假设统一的 `{code,message,data}` 包装。

唯一例外是 `40004 CLIENT_CANCELLED`（用户中断请求）：该分支不走统一构造，`retryable` 硬编码为 `false` 且不带 `action` 字段（`ServerGlobalExceptionHandler:207-222`）。

### 1.4 编码与状态码

- 请求与响应统一 UTF-8。
- 时间戳字段为毫秒整数。
- HTTP 状态码是建议值，业务判定一律以响应体或事件中的 `code` 为准。

### 1.5 存活探测 `GET /health`（免鉴权）

| 项 | 值 |
| --- | --- |
| 用途 | 容器编排与负载均衡的存活探针（K8s `httpGet`、Docker `HEALTHCHECK`、compose `healthcheck`） |
| 响应 | `{"code":0, "status":"UP", "service":"domainplane-server", "version":"v1.0-beta.1"}` |
| 语义 | 只表示进程能对外服务，不检查 ES / Redis / 模型服务 |

进程存活与"依赖是否可用"是两件事：把依赖写进探针，会让刚部署、还没填配置的实例被判为不健康而反复重启；而已配置但依赖抖动时，重启进程也修不好依赖。依赖状态见启动横幅与管控台「存储配置」页。

## 2 接入方接口 `/api/agent/**`

### 2.1 `POST /api/agent/login`

用账号密码换取凭证。响应体返回凭证，不写 Cookie。

请求：`{"username": "...", "password": "..."}`

响应：`{"code":0, "success":true, "username":"...", "credential":"...", "expiresAt":null}`

### 2.2 `GET /api/agent/health`

响应：`{"code":0, "status":"...", "service":"...", "version":"..."}`

### 2.3 `POST /api/agent/chat`

请求体 `AgentRequest`：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `sessionId` | String | 是 | 会话唯一键（域内唯一：不同域可用同一个 sessionId，服务端状态按 `(域, sessionId)` 隔离；不得含 `|`） |
| `message` | String | 是 | 用户消息 |
| `domain` | String | 是 | 域（完整路径，如 `default.sales`）。为空 / 空白直接失败（`10009`），**绝不归一化为根域**；该域不存在（`10004`）或不是可调用单元（`10010`）都会被拒绝 |

响应：`text/event-stream`，事件见第 3 节。

> **输入安全拦截（不走错误码）**：请求消息先过注入特征检测（指令覆盖 / 角色混淆 / 分隔符注入 / 提示词窃取 / 编码绕过五组正则，见 `InputSanitizer`）。命中时不返回错误响应，而是**照常开启 SSE 流（HTTP 200），下发一句固定话术的 `TOKEN` 事件 + `DONE`**——与一次普通回答完全同构：前端按增量文本渲染，SDK 累积成 answer 后收到 DONE。该轮不进编排、不写会话记忆、不调模型。固定话术为「抱歉，这个问题我无法回答。你可以换个说法，或继续问我其他问题。」；命中哪条规则只进服务端日志，不下发。参数校验（缺 `sessionId` / `message` / `domain`）先于拦截，缺参仍是 400；输入超长（上限 2000 字符）也不走此通道，仍以 `40005 INPUT_TOO_LONG` 返回 400 JSON（可操作的参数错误，需调用方缩短重发）。

> **会话记忆与上限**：记忆按 `(域, sessionId)` 存在 Redis，只增不淘汰（每轮存"提问 + 最终回答"，工具调用与结果不入记忆）。到达上限（100 条 / 30000 token）后，该会话拒绝新一轮并返回 `30004 SESSION_MEMORY_FULL`——拒绝发生在入口，不写记忆、不建断点、不调模型；判定是粘性的，之后每次调用都同样被拒。平台不代为切换会话：请由调用方换一个新的 `sessionId` 重新开始，旧会话数据仍保留（默认不过期），只是不再接受写入。

### 2.4 `POST /api/agent/resume`

恢复一次因审批而中断的执行。

| 参数 | 位置 | 必填 | 说明 |
| --- | --- | --- | --- |
| `sessionId` | query | 是 | 会话键（域内唯一） |
| `approved` | query | 是 | boolean，是否批准待执行动作 |
| `domain` | query | 是 | 会话所属的域，需与 `chat` 时一致；断点存在键 `(域, sessionId)` 下，用别的域 resume 找不到断点（`30001`） |

无请求体。`domain` 必须与中断时一致——响应同为 `text/event-stream`。

> **不回审批、直接发起新的 `chat` = 用户拒绝了那次审批**：新对话不会被拒（不返回 `30002`），服务端会为该轮补一条占位回答（"（用户未确认，该次需要审批的操作已取消）"）让这一轮成为完整轮次，并删除断点——那个待授权动作就此永久作废，之后也无法再被 `resume` 执行。

### 2.5 `POST /api/agent/stop/{sessionId}`

| 参数 | 位置 | 必填 | 说明 |
| --- | --- | --- | --- |
| `sessionId` | path | 是 | 会话键（域内唯一） |
| `domain` | query | 否 | 会话所属的域，建议与 `chat` 一致；省略按根域 `default` 算（只能停根域上的会话） |

无请求体。

响应：`{"code":0, "sessionId":"...", "stopRequested":true}`

语义：仅置取消标志，由编排层在下一个检查点抛出并结束本轮，非抢占式。

### 2.6 `POST /api/agent/tools/register`

工具实例的注册与心跳（同一个端点，整包上报）。

请求体：

```json
{
  "instanceId": "order-svc-1",
  "endpoint": "http://10.0.0.12:8080",
  "manifest": [
    {
      "name": "queryOrder",
      "description": "查询订单",
      "category": "default",
      "version": "1.0.0",
      "domains": ["default.sales"],
      "sideEffect": "READ",
      "idempotent": true,
      "toModel": true,
      "requiresApproval": false,
      "approvalMode": "NONE",
      "approvalReason": "",
      "parameters": {}
    }
  ]
}
```

| 顶层字段 | 必填 | 说明 |
| --- | --- | --- |
| `instanceId` | 是 | 实例标识，缺失报 400 |
| `endpoint` | 是 | 工具调用回流地址（`POST /domainplane/invoke` 的完整 URL） |
| `manifest` | 是 | 必须是数组，承载本次声明的全量工具；不是数组直接报 400 |

`manifest[]` 单项被服务端读取的字段（`ToolManifest:102-149`）：

| 字段 | 缺省 | 说明 |
| --- | --- | --- |
| `name` | — | 必填；缺失的条目跳过，同名重复按首条处理 |
| `description` | `""` | |
| `category` | `default` | |
| `version` | `1.0.0` | |
| `domains` | 根域 | 授权边界，完整路径；留空＝挂根域＝全树可见 |
| `sideEffect` | `READ` | 接受 `READ`/`WRITE`/`DESTRUCTIVE` 枚举名，也接受布尔（false=READ、true=WRITE） |
| `idempotent` | `true` | |
| `toModel` | `true` | |
| `requiresApproval` | `false` | 为 `false` 时审批字段全部忽略 |
| `approvalMode` | — | 留空或 `NONE` 且 `requiresApproval=true` 时按 `ALWAYS` 处理 |
| `approvalCondition` | `""` | |
| `approvalReason` | `""` | |
| `approverRoles` | 空 | 数组 |
| `approvalTimeoutSeconds` | `300` | |
| `parameters` | 空 | JSON Schema，对应 SDK 的 `ToolSpec.parameters` |

| 响应 | HTTP | 体 |
| --- | --- | --- |
| 受理 | 200 | `{"accepted":true, "toolNames":["..."]}` |
| 被强制下线 | 410 | `{"accepted":false, "reason":"force_offline"}` |
| 报文不合法 | 400 | `{"accepted":false, "reason":"...", "hint":"see docs/接口文档.md §2.6"}` |
| 工具名与本地冲突 | 400 | `{"accepted":false, "reason":"...", "hint":"工具名与服务端本地工具冲突，请改名后重新心跳"}` |

400 分支不走统一错误响应体（无 `code`/`codeName`），判定依据是 `accepted=false`。

语义：本次上报即该实例的完整声明；未出现在本次 `manifest` 中的工具视为该实例已撤下。

## 3 流式事件契约

`chat` 与 `resume` 返回 `text/event-stream`，每帧数据为一个 `AgentEvent`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `type` | String | 事件类型，见下表 |
| `sessionId` | String | 会话键（域内唯一；事件里回显调用方声明的值） |
| `content` | String | 主要载荷（文本或工具名），部分事件为 null |
| `payload` | String | 附加载荷（JSON 字符串），部分事件为 null |
| `code` | Integer | 错误码，仅 `ERROR` 非空 |
| `codeName` | String | 错误码枚举名，仅 `ERROR` 非空 |
| `traceId` | String | 仅 `ERROR` 非空 |
| `timestamp` | long | 毫秒时间戳 |

| `type` | `content` | `payload` | 说明 |
| --- | --- | --- | --- |
| `TOKEN` | 增量文本 | null | 流式输出片段 |
| `TOOL_CALL` | 工具名 | 参数 JSON | 模型决定调用某个工具 |
| `TOOL_RESULT` | 工具名 | 结果文本 | 工具返回 |
| `INTERRUPT` | null | 待授权工具列表 JSON | 命中审批，本轮挂起，需调 `resume` |
| `STOPPED` | null | null | 本轮被用户停止 |
| `ERROR` | 可读文案 | null | `code`/`codeName`/`traceId` 必填 |
| `DONE` | null | null | 本轮结束 |

约定：只有 `ERROR` 事件携带 `code`；过程事件不带。调用方必须显式处理 `ERROR` 事件——错误是通过事件表达的，不会抛出异常，HTTP 状态已是 200。

## 4 管控台接口 `/admin/**`

### 4.1 账号

| 方法 | 路径 | 入参 | 响应要点 |
| --- | --- | --- | --- |
| POST | `/admin/init` | body `Credentials{username, password}` | `code`、`success`、`message`；仅无账号时可用 |
| POST | `/admin/login` | body `Credentials` | `code`、`success`、`username`、`credential`、`defaultCredential`；同时写 Cookie |
| POST | `/admin/logout` | — | `code`、`success` |
| GET | `/admin/session` | — | `code`、`initialized`、`corrupted`、`authenticated`、`accountFile`（未初始化或已认证时返回）、认证后追加 `username`、`lastLoginAt`、`lastLoginFrom`、`defaultCredential` |
| POST | `/admin/password` | body `PasswordChange{oldPassword, newPassword}` | `code`、`success`、`message`；成功后全部旧凭证失效 |

### 4.2 模型设置

| 方法 | 路径 | 入参 | 响应要点 |
| --- | --- | --- | --- |
| GET | `/admin/settings` | — | `chatBaseUrl`、`chatApiKeyMasked`、`chatApiKeySet`、`chatModelName`、`chatTemperature`、`chatMaxTokens`、`chatCapabilities`、`embeddingBaseUrl`、`embeddingApiKeyMasked`、`embeddingModelName`、`embeddingDimensions`、`embeddingCapabilities`、`chatConfigured`、`embeddingConfigured`、`settingsFile` |
| POST | `/admin/settings` | body `LlmSettings`；query `rebuildIndex`（默认 false） | 成功：`success`、`chatConfigured`、`embeddingConfigured`、`chatApiKeyMasked`、`chatApiKeySet`、`embeddingApiKeyMasked`、`rebuilt`、`message`；失败分支见下表 |
| DELETE | `/admin/settings/{kind}` | path `kind`（`chat` / `embedding`，大小写不敏感） | 成功：`success` 等状态字段；`kind` 非法 → `40000 INVALID_PARAMETER`；持有者拒绝清空 → `success:false` + `error` |
| POST | `/admin/settings/test` | body `LlmSettings`（可空）；query `type`（`chat`/`embedding`，默认 `chat`） | chat/embedding 探测结果 |
| POST | `/admin/models` | body `LlmSettings`（可空）；query `type`（默认 `chat`） | 成功：`success`、`models`；失败：`success`、`message`、`error`、`detail` |

约定：`apiKey` 不回显，留空表示保持原值；向量模型的地址与 Key 留空时回落文本模型配置。

`POST /admin/settings` 的失败分支（`success:false`，均带 `error`，无 `code`）：

| 情形 | 追加字段 | 语义 |
| --- | --- | --- |
| 声明维度与实测不符 | `declaredDimension`、`newDimension` | 模型不支持该维度，直接拒绝保存，不受 `rebuildIndex` 影响 |
| 维度变化但未确认重建 | `requiresRebuild: true`、`indexDimension`、`newDimension` | 本次保存不生效，配置保持原样 |
| 索引重建失败 | `saved: true`、`rebuilt: false` + 三个 Key 状态字段 | 配置已落盘并生效，仅索引重建失败，需另行重试 |

#### 4.2.1 模型档案与域绑定（多 LLM）

模型档案（`config/models.json`）与「域 → 模型」绑定。对话模型只来自这里的自建档案，没有内置 `default` 模型别名：域未绑定任何可用档案 → 调用时抛 `NotConfiguredException`（`90005`）。

| 方法 | 路径 | 入参 | 响应要点 |
| --- | --- | --- | --- |
| GET | `/admin/model-profiles` | — | `code`、`profiles[]`、`domainBindings`、`embeddingAlias`、`embeddingProfiles[]`、`settingsFile`；命中适配的对话档案另带 `adapter` = `{id, label, docUrl, params[], items[]}`（`params` 是 chat 族参数 schema，含 `type` / `wire` / `wireWrap` / `enabledWhen` / `display` / `default` 等声明 —— `default` 是官方默认值，供控件空态显示「默认 X」，没写才显示「服务商默认」；`items` 只列当前有值的项，不含 default） |
| POST | `/admin/model-profiles` | body `ModelProfile`（`alias` / `apiKey` 必填） | `code`、`action`、`target`、`settingsFile`；`alias` 已存在则整体覆盖。**`endpoints` 留空 = 服务端读服务商模型清单（`GET /models`，不发推理请求，零 token）**，读到的端点族决定档案归入「模型」段还是「向量模型」段，读到的输入 / 输出模态落档供卡片展示。读不到（清单里没这个模型 / 清单是标准 OpenAI 规范 / 服务商不提供 `/models`）→ 仍保存，端点族与模态留空，响应另带 `note` 说明原因；读失败（连不上 / `401` / `403` / `5xx` / 非 JSON）→ `40000` 拒绝保存。显式传 `endpoints` 则原样采用，且不发起读取 |
| PUT | `/admin/model-profiles/tuning` | body `{alias, params?, temperature?, maxTokens?}` | `code`、`action`(`tuned`)、`target`、`message`、`settingsFile`、`profile`（新视图）；**只改调优参数**，连接信息（`baseUrl` / `apiKey` / `modelName`）与端点族、模态从既有档案原样带过 —— 接口压根不收这些字段。三项均为**整份替换**：`null` / 空对象 = 清除（回到服务商默认）。未命中适配 → `40000`；`temperature` / `maxTokens` 按适配 schema 的 `min`/`max` 复核，越界 → `40000`；**条件参数（`enabledWhen`）在条件不成立时带值 → `40000`**，文案带参数 key 与不适用的原因 |
| POST | `/admin/model-profiles/test` | query `alias` | `code`、`alias`、`success`、`reply`：用档案配置发一条极短请求验证连通 |
| DELETE | `/admin/model-profiles` | query `alias` | 级联清理：删除档案并把它从所有域绑定里摘掉 |
| PUT | `/admin/model-bindings/{domain}` | path `domain`；body `{aliases:[...]}`（可空＝解绑） | `code`、`action`（`bound`/`unbound`）、`target`、`aliases`、`sourceDomain`、`domainBindings`、`settingsFile`；`default` 不能作为别名绑定；域未登记 → `40000 INVALID_PARAMETER` |

约定：
- 档案 `endpoints` 可多选；空 = 未声明。落盘结构无 `type` 字段。两个判据分开：`isChat()` = `endpoints` 含 `chat`（**已确认**是对话模型）；`mayBeChat()` = `isChat()` 或 `endpoints` 为空（**可能**走对话端点）。绑定 / 解析 / 卡片调优框一律用 `mayBeChat()`，向量判据 `isEmbedding()` 仍只看 `embedding`。
- 端点族与输入 / 输出模态不再由管控台表单采集（类型下拉已删除）：保存时为空按两级取 —— **① 适配文件**：`match` 按**模型名**命中时，端点族取登记了参数的族名、模态取文件里的 `input` / `output`，**不发任何上游请求**（内置 9 个模型走这条）；host 兜底命中不给声明 —— 那只说明"这家服务商登记过"，照抄会把 `text-embedding-3-*` 说成 text→text。**② 服务商元数据**（`ModelMetadataReader`，只发 GET、零 token），识别链由强到弱：`architecture`（OpenRouter 风格）→ 模态是**完整枚举**，覆盖档案里的旧声明；`?sub_type=` 过滤反推端点族（须先证明过滤器生效）→ 模态是**端点规范基线值**，只能并进旧声明；标准 OpenAI 规范（只有 `id/object/created/owned_by`，OpenAI / DeepSeek 官方都是这种形态）→ 一律留空。**不自动补成 chat**：清单里同样列着向量 / 生图模型，猜错会让它们能被绑到域却用不了，且全程不报错。已知边界：不花 token 就读不出多模态输入（VLM 走 `chat`，能吃图片但清单只说明它是 chat）。
- **「未声明」不等于「确定不是对话」**：`endpoints` 为空时绑定 / 解析 / 卡片绿色调优框一律按"可以当对话模型用"处理，否则标准 OpenAI 规范的服务商（预设里唯一有适配的两家）既绑不了域、也解析不出模型 —— 等于建了一份永远用不了的档案。已声明为向量 / 生图 / 语音等非对话族的档案仍照旧拒绝绑定。
- **调优参数的两条路**：`POST /admin/model-profiles`（新建 / 整体覆盖，要重填明文 Key）与 `PUT /admin/model-profiles/tuning`（只改调优，不需要 Key —— 卡片上只有脱敏值）。调优接口不发 `endpoints`，也就不会触发元数据读取（改个温度不该多花上游往返）。
- `bind` 的 `aliases` 为空/全空白＝解绑，该域进入"无可调用"状态；列表首个为当前使用的对话模型。
- `chatConfigured`（`/admin/settings`）= llm-settings 的 chat 已配置 或 任一可用对话档案存在（`registry.hasChatModel()`）。
- 向量维度：档案声明了 `dimensions` 时，保存前额外发一条极短的 `POST /embeddings` 实测（向量链路最硬的契约），实测不一致或没探成一律拒绝保存。

域是一棵树，标识是从根域 `default` 出发的完整路径。域有三个来源（`BUILTIN` 根域 / `MANUAL` 人工创建 / `DERIVED` 工具声明派生），同级、不构成等级；差异只在生命周期——`MANUAL` 落盘重启仍在，`DERIVED` 重启随声明重建。登记时沿链补齐缺失祖先，不留悬空节点；删除递归带走全部子孙，不向上提升，只有根域不可删。

域有两种角色：
- **可调用单元**：能作为入口被调用，是"这一个 AI 切片"的入口；
- **装配节点**：只把工具/提示词/模型绑定/知识传给后代，不能直接当入口。

硬约束是叶子规则：只有叶子域（没有子域）可以作为可调用单元，一个域一旦有了子域就降级为装配节点。

`DELETE /admin/domains/{id}` 的清理顺序是硬要求（`AdminDomainController:144-200`），除第 5 步外任一步失败都会中止且域一个没动：
1. 校验域存在、且不是根域（根域不可删）；牵连范围＝自身＋全部子孙；
2. 删该范围内各域的知识库索引（含切片预览文件），失败 → `60000 KNOWLEDGE_BASE_ERROR`，域未删除；
3. 失效对应索引的检索器缓存；
4. 清提示词、模型绑定、工具声明派生记录；
5. 清 Redis 会话记忆与图检查点：对范围内每个域按 `{域}|` 前缀 `SCAN` 后删除。此步失败只告警、不阻断删域；
6. 删域并落盘人工声明。

返回的 `removedIndices` 是第 2 步实际删掉的索引名列表。

### 4.5 知识库

| 方法 | 路径 | 入参 | 响应要点 |
| --- | --- | --- | --- |
| GET | `/admin/kb/documents` | — | `code`、`count`、`exportDir`、`documents[{docId, fileName, chunks, domain, exportPath}]` |
| POST | `/admin/kb/documents` | `multipart/form-data`，`file`（必填）、`replace`（默认 false）、`domain`（可选，单个） | `code`、`success`、`docId`、`fileName`、`size`、`chunks`、`domain`、`sections`、`droppedLines`、`encoding`、`exportPath` |
| DELETE | `/admin/kb/documents/{docId}` | path `docId` | `code`、`success`、`docId`、`deleted` |
| GET | `/admin/kb/status` | — | `code`、`indexCount`、`documents`、`chunks`、`indices[{index, domain, documents, chunks}]` |
| POST | `/admin/kb/rebuild` | — | `code`、`success`、`indices`、`dimensions`、`message` |

`domain` 声明该文档归属的域，与 `@Tool(domains = {...})` 同构：必须是完整路径，判定按累加——挂在某域则其全部后代域都能检索到；留空/不传 → 挂根域 `default`＝全域可见。无通配写法，路径非法直接拒绝。一个文档只属一个域：知识库是一域一索引，域即索引。

约定：上传为同步（切片与向量化完成后才返回）；同一域内同名不区分大小写，默认拒绝，`replace=true` 先删后写；`rebuild` 会清空全部知识库索引，之后需重新上传文档。

上传只接受 `domainplane.rag.allowed-extensions` 白名单内的类型，当前是 `txt` / `md` / `markdown` / `docx` / `doc` / `pdf` / `xls` / `xlsx`。文本类按入口探测的编码（BOM → 严格 UTF-8 → GB18030）统一转成 UTF-8 后再入库；二进制类不做编码探测，原始字节直接交给对应解析器。

`sections`（识别到的标题数）、`droppedLines`（清洗删掉的行数）、`encoding`（实际识别的源编码）是切片质量诊断值。`exportPath` 是切片预览 txt 的落盘路径（默认 `%ProgramData%\DomainPlane\chunks`）。

| | `list()` → `List<DocumentItem(docId, fileName, chunks)>` |
| | `delete(String docId)` |

客户端异常统一为 `DomainPlaneException`（携带 `ErrorCode`）；启动探测失败抛 `DomainPlaneStartupException`；`ask`/`stream` 命中人工审批时抛 `ApprovalRequiredException`（带 `sessionId`/`domainId`/`tools`/`traceId`）。

### 6.4 裸 HTTP / SSE 调用（不走 SDK）

`chat`/`resume`/`stop` 都是标准 HTTP，事件以 `text/event-stream` 下发。无 Java SDK 的客户端（前端、其他语言）直接调。

**发起对话（curl）**

```bash
curl -N -X POST http://localhost:9527/api/agent/chat \
  -H "Content-Type: application/json" \
  -H "X-DomainPlane-Credential: <凭证>" \
  -d '{"sessionId":"s-001","message":"我的订单 FR2024001 到哪了","domain":"default.customer"}'
```

**前端消费 SSE（fetch + ReadableStream）**

```javascript
const resp = await fetch('/api/agent/chat', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json', 'X-DomainPlane-Credential': credential },
  body: JSON.stringify({ sessionId, message, domain })
});
const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buf = '';
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buf += decoder.decode(value, { stream: true });
  const frames = buf.split('\n\n');
  buf = frames.pop();
  for (const f of frames) {
    const line = f.split('\n').find(l => l.startsWith('data:'));
    if (!line) continue;
    const ev = JSON.parse(line.slice(5).trim());
    if (ev.type === 'TOKEN') process.stdout.write(ev.content);
    if (ev.type === 'INTERRUPT') showApprovalDialog(ev);   // 调 /api/agent/resume
    if (ev.type === 'ERROR') alert(`[${ev.codeName}] ${ev.content}`);
  }
}
```

**审批恢复（resume）**

```bash
curl -N -X POST "http://localhost:9527/api/agent/resume?sessionId=s-001&approved=true&domain=default.customer" \
  -H "X-DomainPlane-Credential: <凭证>"
```

## 7 工具实例 SDK（`domainplane-tool-provider`）

与对话/知识库 SDK 相互独立；开启开关是 `domainplane.tools=true`（不在本组前缀下）。

### 7.1 注解

工具实例侧只认一套注解：

- **`@Tool` 全家桶**：`desc` 为唯一必填，配套 `@ToolParam`（说明/名字/必填三字段）/ `@ToolDomains`（类级默认域）/ `@ToolAdvanced`（示例、枚举白名单、敏感参数，一律 `参数名=值`），审批写在 `@Tool(approval=..., approvalReason=...)` 上。字段与示例见下文契约表。

两种生效场景：
- 工具实例侧（本 SDK）：方法所在类注册为 Spring Bean 即可，由 `ToolProviderScanner` 在装配期扫描注册；参数 schema 由方法签名推导。
- 服务端进程内：任意 Spring Bean 即可（`DomainPlaneToolProvider` 为可选标记）。

开关 `domainplane.tool-instance.scan-annotated`（默认 `true`）。

### 7.2 配置

服务端地址与账号读 `domainplane.server`（默认 `http://localhost:9527`）与 `domainplane.username`/`password`，与对话/知识库 SDK 共用同一份。

前缀 `domainplane.tool-instance`：

| 键 | 默认值 | 说明 |
| --- | --- | --- |
| `domainplane.tools` | `false` | 开启开关不在本组：必须显式写 `domainplane.tools=true`，否则整组配置不生效 |
| `scan-annotated` | true | 是否扫描 `@Tool` 注解方法并自动注册；关闭后只认 `ToolInstanceContributor` 编程式注册 |
| `instance-id` | — | 实例标识 |
| `endpoint` | 推导 | 本实例对外可达地址，服务端反向调用用；留空按 `http://localhost:{本进程端口}/domainplane/invoke` 推导，跨机部署必须显式填写 |
| `heartbeat-interval-seconds` | 5 | 心跳周期 |
| `max-backoff-seconds` | 20 | 连续失败退避上限 |
| `request-timeout-millis` | 10000 | 出站请求超时 |

### 7.3 核心类型

| 类型 | 说明 |
| --- | --- |
| `ToolInstanceClient` | `register(ToolSpec, ToolHandler)`、`start()`、`stop()`、`invoke(JsonNode)` |
| `ToolHandler` | `handle(String argumentsJson)` |
| `ToolSpec` | 工具声明（序列化为注册报文的 `manifest` 项） |
| `ToolInstanceConfig` | 实例身份配置 |
| `ToolRegistrar` | 注册扩展点 |
| `ToolProviderScanner` | 扫描 Spring 容器里带 `@Tool` 的方法，转成 `ToolSpec` + 反射执行体并注册 |

### 7.4 工具注解契约

**`@Tool`**（写在方法上，唯一必填字段 `desc`）

| 字段 | 类型 | 默认 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| `desc` | `String` | — | 是 | 给模型的用途说明。写清"何时调用 / 何时不要调用"，比参数描述更重要 |
| `value` | `String` | `""` | 否 | 工具名。留空取方法名；全局唯一，重名注册直接失败 |
| `domains` | `String[]` | `{}` | 否 | 可用域（授权边界），完整路径；无通配写法；判定按累加；留空＝挂根域＝全树可见；可继承类级 `@ToolDomains` |
| `effect` | `Effect` | `READ` | 否 | `READ`/`WRITE`/`DESTRUCTIVE`。写与破坏性操作建议配 `approval` |
| `approval` | `Approval` | `NONE` | 否 | `NONE`/`ALWAYS`。当前只有这两种真正生效 |
| `approvalReason` | `String` | `""` | 否 | 展示给审批人的原因 |

不在注解上的字段：`category`（默认 `"default"`，只用于管理页分组）、`version`（默认 `"1.0.0"`）、`idempotent`（默认 `true`）、`toModel`（默认 `true`）只在 `ToolSpec`/上报 manifest 里；`condition`/`approverRoles`/`timeoutSeconds` 当前不生效，只登记。

**`@ToolParam`**（写在形参前 或 参数 DTO 的字段上）

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `value` | `String` | `""` | 参数说明（强烈建议写） |
| `name` | `String` | `""` | 参数名。留空取形参名 |
| `required` | `boolean` | `true` | 是否必填。`Optional<T>` 自动视为非必填 |

**`@ToolDomains`**（类级默认域）：`value` 为 `String[]`，该类的所有 `@Tool` 方法默认可用域；方法级 `domains` 优先。

**`@ToolAdvanced`**（方法级，高级可选）

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `example` | `String[]` | `{}` | 参数示例，按参数名对应（`orderNo=FR2024001`），不做位置对齐 |
| `allowValues` | `String[]` | `{}` | 枚举白名单，按 `name=...` 形式给出 |
| `sensitive` | `String[]` | `{}` | 需要脱敏的参数名清单（日志/事件/审批 payload） |

两个载体、一个优先级：形参注解 ＞ 字段注解（就近覆盖）。服务端本地 Bean 与工具实例侧共用同一份 `ParamSchemaResolver` 产出参数树，两侧对同一段工具代码给出完全一致的 schema。名字写错不报错、只静默不生效；只有"不是 `参数名=值` 形式"的条目会在启动期打 WARN。

### 7.5 最小工具示例

```java
@Service
public class OrderTools {

    // 唯一必填：desc
    @Tool(desc = "按订单号查询订单状态。用户追问发货、物流时调用")
    public OrderVO queryOrder(@ToolParam("订单号，如 FR2024001") String orderNo) {
        return orderRepository.findByNo(orderNo);
    }

    // 写操作 + 每次调用前中断等人工确认
    @Tool(desc = "按订单号退款。仅在用户明确要求退款时调用",
          value = "refundOrder",
          effect = Tool.Effect.WRITE,
          approval = Tool.Approval.ALWAYS,
          approvalReason = "退款会真实出金，需人工确认")
    public String refundOrder(@ToolParam("订单号") String orderNo,
                              @ToolParam("退款金额，单位：元，须 ≤ 订单实付") BigDecimal amount) {
        return refundService.refund(orderNo, amount);
    }
}
```

### 7.6 反向调用协议（服务端 → 实例）

实例侧端点：`POST /domainplane/invoke`

请求体：

| 字段 | 说明 |
| --- | --- |
| `requestId` | 请求标识 |
| `toolName` | 工具名 |
| `arguments` | 参数（JSON） |
| `tenantId` / `userId` / `traceId` | 调用上下文 |

响应体：

| 情况 | 响应 |
| --- | --- |
| 成功 | `{"requestId":"...", "success":true, "result":...}` |
| 业务失败 | `{"requestId":"...", "success":false, "error":"...", "retryable":true/false}` |

约定：实例必须同步返回；服务端仅在传输层失败（超时、连接失败）时换副本重试，业务失败直接返回给模型。HTTP 层永远返回 200，业务失败写在响应的 `success=false` 里，以区分"实例不可达（该换副本重试）"和"工具执行失败（直接回喂模型）"。

> 端点 `/domainplane/invoke` 不自带鉴权，接入方负责收敛暴露面（在网络可信范围内可达即可）；把实例端口当作只在可信网络内可达的服务端口。
