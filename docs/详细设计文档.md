## 1 域与工具可见性

### 1.1 域树与标识

域是一棵**树**，标识是**从根域出发的完整路径**（点分，如 `default.sales.order`）。主键与展示同形，因此不存在"同名不同父"的歧义。根域是 `default`，即基层域。

| 项 | 规定 |
| --- | --- |
| 定义 | 域＝一次对话的场景，同时绑定【工具集 + 系统提示词 + 知识范围 + 模型】 |
| 两种角色 | **可调用单元**（能作为入口）与**装配节点**（只把工具/提示词/模型/知识传给后代，不能当入口）。可调用性的硬约束是**叶子规则**：**只有叶子域（无子域）才能作为可调用单元**。需要"父域整体"的入口时，应另建一个没有子域的域 |
| 结构与路径 | 标识必须是完整路径；登记时**沿链补齐**——链上缺失的祖先一并建出，不留悬空节点。单段只允许 `[A-Za-z0-9_-]`，自身链上不得重复段 |
| 可调用性的判定 | **读取时派生**：`isCallable = 显式标记可调用 ∧ 无子域`。写入侧存的是**意图**，这里算的是**生效** |
| 根域 | 根域**没有豁免**，同样服从叶子规则 |
| 创建与销毁 | 三个**来源**（`BUILTIN` 根域 / `MANUAL` 人工创建 / `DERIVED` 工具声明派生）**同级**，差异只在生命周期；**只有根域不可删**，删域递归带走全部子孙 |
| 可见性判定 | **累加**：工具声明命中该域或它的任一祖先即见；**没有通配写法**，全域可见＝挂根域 |
| 维度数量 | 域是工具可见性的 **唯一维度**，不叠加第二个权限维度 |
| `domain` 为空 / 空白 | fail-fast 返回 `10009 DOMAIN_REQUIRED`，**绝不归一化为根域**（空域是漏传权限同类的错误形态，后果更直接） |
| `domain` 非空但域不存在 | fail-fast 返回 `10004`，**绝不回退为全量工具** |
| `domain` 存在但不是可调用单元 | fail-fast 返回 `10010`（有子域的域不能当入口），文案带出当前可调用集合 |
| 域全集 vs 可调用集 | `knownDomains()` 是**展示/排障**口径，不是门禁；入口只认**可调用集**（`DomainRegistry.isCallable`）。客户端清单 `/api/agent/domains` 只返回可调用域 |
| 写入收口 | 工具 manifest 的 `domains`、本地 `@Tool(domains=...)`、知识库归属域、提示词、模型绑定：域要么**格式合法**（前两者，非法整包拒绝/启动失败），要么**必须已登记**（后三者） |
| 同源性约束 | 模型可见工具集与需审批工具集必须来自同一判定（`ToolRegistry.toolSpecifications` 与 `toolsRequiringApproval` 同源）；拒绝文案分两种：域外 `10001`、工具已下线 `80001` |
| 工具视图不取快照 | 每轮实时读注册表；不缓存工具集快照 |
| 会话状态隔离 | 记忆 / 图检查点 / 取消 / 流注册的键是 **`(域, sessionId)`**（`SessionKeys`）：不同域可以用同一个 sessionId 而互不影响 |

四个维度共用同一套**沿链累加**语义：工具可见性（声明命中自身或祖先）、知识库（自身 ∪ 全部祖先）、提示词（从根到自身依次拼接）、模型绑定（自身没绑就向上找最近的绑定）。公共内容只需在根域写一次。

路径运算（`parentOf` / `chainOf` / `ancestorsOf` / `validatePath`）是 `Domains` 上的**静态纯函数**，不依赖任何注册表——基础设施层因此能自行展开祖先链，无需反向依赖运行期容器。

### 1.2 域的命名：代码与契约统一用 domain

`domain` / `domainId` 既是代码侧的正式词根，也是 HTTP / SDK 契约字段（`AgentRequest.domain`、裸 HTTP `chat`/`resume`/`stop` 的 `domain` 参数、`ErrorCode.DOMAIN_*`）。不存在"代码叫 domain、契约叫 profile"的两套词——历史上 `profile` 曾作契约字段，现已统一重命名为 `domain`。`ModelProfile*` 是另一回事：它是"模型档案 / 模型别名"义（见 §7），与"域"无关，保留 profile 命名。

## 2 工具体系

### 2.1 注解契约（`domainplane-api/annotation`）

工具注解只有一个入口：**`@Tool` 全家桶**（`@Tool` / `@ToolParam` / `@ToolDomains` / `@ToolAdvanced`）。

| 注解 | 目标 | 字段 | 默认值 |
| --- | --- | --- | --- |
| `@Tool` | METHOD | `desc` | **必填**（唯一必填；给模型的用途说明） |
| | | `value` | `""`（工具名，留空取方法名；全局唯一，重名注册失败） |
| | | `domains` | `{}`（每项为完整路径；留空＝挂根域＝全树可见；无通配） |
| | | `effect` | `Effect.READ`（`READ`/`WRITE`/`DESTRUCTIVE`） |
| | | `approval` | `Approval.NONE`（`NONE`/`ALWAYS`，当前仅此两态生效） |
| | | `approvalReason` | `""`（`approval != NONE` 时建议填写，展示给审批人） |
| `@ToolParam` | PARAMETER / FIELD / RECORD_COMPONENT | `value` | `""`（参数说明，推荐写法；不写会被统计为"未描述"并 WARN） |
| | | `name` | `""`（留空取形参名 / 字段名） |
| | | `required` | `true`（`Optional<T>` 自动判为可选） |
| `@ToolDomains` | TYPE | `value` | `{}`（类级默认域；方法级 `domains` 就近覆盖） |
| `@ToolAdvanced` | METHOD | `example` | `{}`（参数名=示例值，如 `{"orderNo=FR2024001"}`） |
| | | `allowValues` | `{}`（参数名=值1\|值2，如 `{"channel=SMS\|APP"}`） |
| | | `sensitive` | `{}`（需掩码的参数名清单） |

> `@ToolParam` 只保留"每个参数都该写"的三项（说明 / 名字 / 必填）；示例、白名单、脱敏属于长尾，统一在方法级的 `@ToolAdvanced` 上写，三个字段一律 `参数名=值`，**不做位置对齐**。

实际生效范围（当前实现）：

- 扫描：`ToolProviderScanner` 只识别 `@Tool`（服务端进程内与工具实例 SDK 两侧规则一致）；`DomainPlaneToolProvider` 仅作可选标记。
- 参数结构由反射推导（`String`/`int`/`boolean`/`enum`/`List<T>`/`record DTO` → JSON Schema 的 `type`/`properties`/`required`）；`@ToolParam` 只补说明。
- `@ToolAdvanced` 在参数树建好后**按名字**套上（名字既可是形参名，也可是 DTO 展开出的字段名）：`allowValues` → 模型 schema 的 `enum`；`example` → `Param.example` **并追加进模型可见的参数说明**；`sensitive` → `Param.sensitive` + 事件与审批 payload 的**值掩码**。
- 审批判定只看 `@Tool#approval` 是否非 `NONE`；新注解只暴露 `NONE` / `ALWAYS` 两态。
- 仅登记、不参与运行行为：`idempotent`、`toModel`、`ToolDescriptor.Approval` 的 `condition`/`approverRoles`/`timeoutSeconds`。
- 域归属合并：`@Tool(domains=)` 与 `@ToolDomains`（类级默认）合并判定，方法级优先。

### 2.2 工具来源

| 来源 | 触发时机 | 注册路径 | 副本表示 |
| --- | --- | --- | --- |
| 本地 Bean | 启动期扫描 | Spring Bean（可选实现 `DomainPlaneToolProvider`）→ `AnnotatedToolScanner`（服务端）/ `ToolProviderScanner`（实例侧） | 单元素 `local` |
| 远程实例 | 运行期整包心跳 | `POST /api/agent/tools/register` | `instanceId` + `endpoint` |

两个来源写入同一个内存注册表 `ToolRegistry`；注册表不落盘。本地工具与远程工具对模型和管控台完全透明。

### 2.3 注册表结构

| 项 | 规定 |
| --- | --- |
| 条目 | `Registered(ToolDescriptor descriptor, ToolSpecification specification, ToolExecutor executor, List<InstanceEndpoint> endpoints)`，不可变 |
| 副本端点 | `InstanceEndpoint(String instanceId, String endpoint)` |
| 反向索引 | `byInstance`：`instanceId → 该实例声明的工具名集合` |
| 更新语义 | 按 `instanceId` 整包替换：本次心跳的声明为准（地址无条件校对；描述、域归属等变更以本次为准） |
| 移除语义 | 只删该实例的副本；副本列表为空才整条移除条目，域随之消失 |
| 重名 | 同名工具的多个实例＝多副本；路由在副本间轮选，传输层失败换下一个副本（最多 `invoke-max-attempts` 次，默认 2）；业务失败不重试 |
| 并发 | 不可变对象 + `compute` 原子替换；读端无锁 |
| `.source()` | 本地 `包名.类名#方法名`；远程 `remote://{instanceId}@{endpoint}`（仅排障展示，不参与路由） |
| 声明不一致 | 多副本声明不一致时取首份，其余仅告警 |

### 2.4 实例生命周期

| 状态 | 含义 |
| --- | --- |
| `ONLINE` | 在线，副本可路由 |
| `DRAINING` | 已判死，正在清理副本（不截断会话） |
| `OFFLINE` | 清理完成，从在线表移除；重新心跳可回 `ONLINE` |
| `FORCE_OFFLINE` | 管理员强制下线：立即清副本，再次心跳返回 `410`；标记有保留窗，过期后可重新注册 |

| 参数 | 默认值 | 行为 |
| --- | --- | --- |
| 心跳周期 | 5s | 实例侧定时整包上报 |
| `domainplane.instance.timeout-seconds` | 35 | 超过该时长未收到心跳即判死（≈心跳×7） |
| `domainplane.instance.scan-interval-ms` | 5000 | 服务端定时扫描判死，与流量解耦 |
| `domainplane.instance.force-offline-retention-seconds` | 3600 | 强制下线标记保留时长 |
| `domainplane.instance.invoke-timeout-ms` | 30000 | 单次反向调用超时 |
| `domainplane.instance.invoke-max-attempts` | 2 | 传输层失败时尝试的不同副本数上限 |

- 实例下线 **不截断会话**：会话属于域，不属于实例。
- 同一实例的状态标记与副本清理必须在同一把实例锁内一次完成。

### 2.5 工具执行与审批

- 执行前检查取消标志；工具不可见或已下线时不执行，回文本给模型。
- 命中审批的工具：发出 `INTERRUPT` 事件并中断图，等待调用方 `resume`。
- `resume` 必须携带 `domain`（必填 query 参数，需与 `chat` 时一致）；执行 `resume` 时按**本次域**重新校验工具可见性（工具已下线也拦下）。
- `resume` 只接受中断时的那个域；域不一致时按新域找不到断点（`30001`）。
- 请求入口若发现断点停在审批点（说明用户没回复审批就开了新对话）→ **视为用户拒绝了那次审批**：该轮 `chat` 照常处理，同时补一条占位回答并**删掉断点**（那个待授权动作永久作废）。
- 请求入口若发现会话记忆已达上限 → 直接拒绝该轮（`30004`），**零副作用**（不写记忆、不清断点、不调模型）；调用方需换 `sessionId`。
- 同一 `sessionId` 不允许并发：已在执行时直接拒绝（`30003`），不排队。

## 3 会话、记忆与检查点

| 项 | 规定 |
| --- | --- |
| 会话键 | `(域, sessionId)`（`SessionKeys`，分隔符 `\|`）；**`sessionId` 由调用方提供、域内唯一**，不得含 `\|` |
| 记忆内容 | 仅用户消息与最终 AI 回答；工具调用与工具结果不进记忆（它们只在检查点里） |
| 记忆约束 | `domainplane.memory.max-messages`＝100 条、`max-tokens`＝30000；**只增不淘汰** |
| 到上限 | 入口拒绝新一轮（`30004 SESSION_MEMORY_FULL`，零副作用），**粘性**：只要还满着就每次拒绝；平台不代为切换，**调用方换 `sessionId`**。上限只约束入口——最终回答永远可写 |
| 记忆保留期 | `domainplane.memory.ttl`＝**永久**（null）。记忆是长期存储，靠 Redis RDB+AOF 保住；启动期 `RedisPersistenceAudit` 自检持久化与淘汰策略，只告警不阻断 |
| 检查点 | LangGraph4j 检查点存 Redis，`domainplane.memory.checkpoint-ttl`＝24h；正常跑完由框架 `releaseThread(true)` 删除 |
| 挂起未批 | 用户不回审批而是直接开新对话 = **视为拒绝**：补占位回答让那一轮完整，并**删除断点**，新对话照常处理 |
| 停止语义 | `stop` 只置取消标志，由 `agentNode.onPartialResponse` 与 `toolsNode` 在工具执行前检查后抛出；随后回滚本轮记忆、清检查点、推 `STOPPED`、结束流 |

消息通道：图的 `messages` 通道使用去重被禁用的追加器，允许同内容消息重复入列。

## 4 系统提示词

| 项 | 规定 |
| --- | --- |
| 组成 | **沿域链拼接**：从根域到当前域依次取出每段片段，拼成一条 `SystemMessage`。根域的片段即基底，后代的追加在后 |
| 来源与优先级 | `config/prompts.json`（高） > yaml（`domainplane.ai.prompt.prompts.*`，低）。**没有 `base` 这一层**，根域片段就是 `prompts["default"]` |
| 拼接标记 | 无边界标记 |
| 缺省 | 整条链都为空时不下发系统提示词，并记一条 WARN |
| 生效时机 | 执行单元内冻结；单元之间取最新值；`resume` 沿用中断时注入的那份 |
| 替换语义 | 整体替换，不支持追加 |
| 注入方式 | 编排层注入"提示词解析器"而非提示词字符串 |

提示词是软引导，不构成能力边界：工具不可见时不会出现在提示词与工具集中。

## 5 知识库与检索

### 5.1 一域一索引

**一个域 = 一个 ES 索引**，与域树、工具可见性、提示词共用同一套沿链累加语义。

| 项 | 规定 |
| --- | --- |
| 索引粒度 | 每个域一个独立索引；文档"属于哪个域"＝它被上传到哪个域的索引 |
| 索引名 | 由域路径**确定性派生**：`domainplane_kb_<安全前缀>_<8位哈希>`（`KbIndexes.nameOf`，纯函数、不依赖任何注册表）。不用域路径直连做索引名——点号在 ES 通配 / 日期数学 / 隐藏索引场景下有歧义，且大小写敏感的域转小写后会撞名，故用哈希后缀保证唯一 |
| 索引创建 | **按需创建**：首次向该域上传文档时建出，映射含 IK 中文分词配置与向量维度——域在运行期由用户创建，索引跟着域走 |
| 通配 | `domainplane_kb_*` 覆盖全部知识库索引（枚举、ES 连接探测、重建用） |
| 删除 | 删域时**先删该域及全部子孙的索引**，删不干净则拒绝删域（顺序不能反） |
| 重建 | 删掉全部知识库索引并按当前维度重建；一个都没有时建出根域的索引。**索引会被清空，文档需重新上传** |

### 5.2 文档模型

| 项 | 规定 |
| --- | --- |
| 导入方式 | 部署方上传（管控台 / HTTP / starter），服务端不内置文档 |
| 支持类型 | `domainplane.rag.allowed-extensions`：`txt` / `md` / `markdown` / `docx` / `doc` / `pdf` / `xls` / `xlsx`。txt 靠正则**猜**结构；其余**读**结构 —— md 自研解析、docx 与 doc 直连 POI（XWPF / HWPF，段落样式加**大纲级别**取标题层级）、pdf 直连 PDFBox（抽行取坐标与页码）、xls/xlsx 直连 POI（`WorkbookFactory`）。**不引 Tika**：实测它对 docx 丢标题层级、对 pdf 丢字号。docx / doc 的分节只认标题（没有标题就整篇一节）；pdf 本轮不做字号推断标题，按「页」分节（`section_path = 文件名 > 第N页`）；excel 按**工作表**分节（`文件名 > 工作表名`） |
| 大小上限 | `domainplane.rag.max-file-size`，默认 5MB。**须与 `spring.servlet.multipart.max-file-size` 保持一致** |
| 单文件切片上限 | `domainplane.rag.max-chunks-per-document`，默认 2000 片 —— 超限直接拒绝并提示拆分 |
| 字符集 | **只对文本类生效**：入口探测一次（BOM → 严格 UTF-8 → GB18030）并转码；判不出编码则**拒绝该文件**，不猜。**docx / doc / pdf / xls / xlsx 是二进制，不解码** —— 原始字节直接交给 POI / PDFBox |
| 归属域 | 上传时指定单个域（完整路径，留空＝根域 `default`）；路径非法直接拒绝 |
| 同一性判定 | **同一域内**同名不区分大小写；默认拒绝，带 `replace=true` 则先删旧再写入 |
| 删除语义 | 删除该文档全部切片，并释放文件名。docId 里看不出所在域，故逐个索引查找 |
| 唯一键 | `doc_id`（UUID，删除与聚合的依据）与 `file_name`（展示与同名校验） |
| 切片元数据 | `doc_id`、`file_name`、`file_name_lower`、`upload_time`、`domain`、`section_path`、`section_title`、`chunk_seq`、`chunk_total`、`page_from`（仅 pdf）、`content_hash`。`metadata` 在 mapping 里是 `dynamic:false` + 全部显式声明 |
| 去重键 | `content_hash = SHA256(切片正文)`，**不含文件名** —— 改了文件名重传也算同一份内容 |
| 切片规则 | 分两层：**格式适配层**（每格式一套，产出统一 `Block` 流）+ **通用切片层**（全格式共用）。切片长度（max-chars）是**上限不是固定长度**（撞标题即断）。表格由 `MarkdownTable` 统一渲染成 markdown，整块独占一片、超长按数据行切且每片重复表头 |
| 切片预览 | 上传后把该文档的切片写成 UTF-8 txt 落到 `domainplane.export.path`（默认 `%ProgramData%\DomainPlane\chunks`），管控台只展示路径 |
| 并发 | 导入全局串行，等待上限 `domainplane.rag.ingest-lock-wait-seconds`（默认 60s） |
| 失败处理 | 导入失败回滚本次已写入的切片；失败必须上抛，不得返回成功计数 |

### 5.3 检索：按域解析通道 + 双轨融合

检索域 D 时，召回通道 = **`chainOf(D)` 上每个索引 × 两路模态**（自身 + 全部祖先，含根域）。

| 项 | 规定 |
| --- | --- |
| 域边界 | 由"查哪些索引"保证，**不再做 `metadata.domains` 过滤** |
| 通道 | `域链长度 × 2` 条：每张索引一条向量路（余弦）、一条关键词路（BM25）。索引不存在时通道安静返回空（检索器开 `ignoreUnavailable` / `allowNoIndices`），不预探测 |
| 未绑定域 | 非对话路径（管控台预览、诊断）未绑定检索域 → 对 `domainplane_kb_*` 做通配检索，保持"全库检索"行为 |
| **双轨融合** | 实际**有命中**的来源（索引）数 ≤ 1 → `DefaultFusionStrategy`（**分数制**）；≥ 2 → `RrfFusionStrategy`（**排名制**）。切换由 `AdaptiveFusionStrategy` 自动完成。判据是"有命中的来源数"而不是"通道里出现过几个来源" |
| 为什么多索引必须换 RRF | BM25 的 idf 用**本索引**的文档频率计算，同一个词在不同索引里量纲不同——多索引 BM25 分池化后做 min-max 会把"小索引里稀有词被抬高的分"当成 max，把其余结果压扁。RRF 只看名次，天然免疫 |
| RRF 公式 | `score(d) = Σ_L w_L / (k + rank_L(d))`，`k` 默认 10（`domainplane.retrieval.rrf-k`） |
| 权重均摊 | 每张向量表 `w = vectorWeight / 向量表数`，每张关键词表 `w = keywordWeight / 关键词表数`——否则祖先域越多、向量表越多，关键词那路被越压越扁。**空表不占份额** |
| 层级衰减 | 表权重再乘 `ancestor-decay ^ depth`（depth = 距查询域的距离，0 = 自身），同模态内重新归一化（总量守恒）。默认 0.7：本域自有知识优先于从祖先继承的；`1.0` = 等权 |
| 召回条数 | `vector-top-k`＝30（每张索引）、`keyword-top-k`＝20（每张索引），均须 ≥ `top-n` |
| 向量阈值 | `vector-min-score`＝0.35 |
| 权重 / 增益 | `vector-weight`＝0.6、`keyword-weight`＝0.4、`top-n`＝15 |
| 标题 / 文件名增益 | `title-boost`＝0.15、`file-name-boost`＝0.10，是**乘法**（`分 × (1 + 该值)`）不是加分 |
| 关键词查询字段 | multi_match（BestFields）字段权重：`text^1.0`、`text.standard^0.8`、`metadata.section_path^1.5`、`metadata.section_title^2.0` |
| `minimum-should-match` | `50%`。**在真实 ES 上量出来的值**：ik_smart 把「会员退款的时效说明」切成 5 个词，60% 要求命中 3 个词 → 正常问题**零命中**；30% 及以下等于没限制。有效区间 40%~50% |
| 排序稳定性 | 融合分相同按 `chunk_seq` 升序再按内容哈希 —— 同一问题两次检索必须给同一份答案 |
| 注入收口 | `inject-top-n`＝8（每次最多注入几片）；`max-context-chars`＝3000（正文总字符预算，逐条累加，超预算即停，**首条无论如何都收**） |
| 超时 | `domainplane.retrieval.timeout-ms`＝5000（始终为有限值）；全通道失败会抛错，与"真没命中"区分开 |
| 空结果 | 返回"未检索到相关内容"文本；服务不可用返回"知识库检索服务当前不可用…"——两态分离 |

知识检索以 `KnowledgeSearchService` 形式提供，由部署方通过 `@Tool` 暴露为工具；服务端不自带示例工具。

**域对知识仍是两层约束**（与工具不同）：① 工具层——检索工具本身声明到哪些域，决定"这个域的对话能不能检索"；② 内容层——文档上传到哪个域，决定"能检索时，能查到哪些文档"。

## 6 入库切片设计

> 规则来自实测（POI 5.4.1 + PDFBox 3.0.8），不采信文档与直觉。md（①）、docx（②）、入口叉分 + 白名单 + 切片上限（③）、pdf（④）、旧版 .doc（⑥）、Excel（⑦）已落地；**pdf 字号推断标题（⑤）未做** —— 现在 pdf 按「页」分节。

### 6.1 两层架构

txt 的管线是「**猜**结构」（靠正则认标题）；md/doc/pdf 的管线是「**读**结构」（格式里本来就有标题、表格、页边界）。把现有四步拆成两层：

```
格式适配层（每种格式一套，产出统一的 Block 流）  →  通用切片层（全格式共用，一行不改）
```

**只有格式适配层是新的，切片规则（认标题之外的打包、重叠、去重、导出）全部复用 txt 那套。** 引入中间表示 `Block`：

```java
record Block(Kind kind,     // TITLE / PARAGRAPH / LIST_ITEM / CODE / TABLE / IMAGE / QUOTE
             int    level,  // 仅 TITLE：1~6（0 = 无层级）
             String text,   // 正文；TABLE = markdown 表格文本；IMAGE = 占位描述
             int    pageNo) // PDF 用；其余 0
```

格式适配层只做一件事：`文件字节 → List<Block>`，标题层级由格式自己给出。通用切片层：`TITLE` → 更新标题路径栈；`PARAGRAPH/LIST_ITEM/QUOTE` → 攒成可切正文喂 `Chunker`；`CODE/TABLE` → 不可切块，整块独占一片，块内按行切、不加重叠（表格超长按数据行切、每片重复表头）；`IMAGE` → 占位文本并入紧随其后的正文片。

**关键点：`Chunker` 一行不改。** txt 管线是"格式适配层退化成纯文本"的特例。

### 6.2 入口叉分（文本类 vs 二进制类）

- 文本类（txt/md）走"解码 → 文本"：`TxtNormalizer`（BOM → 严格 UTF-8 → GB18030，判不出就拒）。
- 二进制类（docx/doc/pdf/xls/xlsx）走"字节 → 解析器"，**不解码** —— 否则要么乱码入库，要么报错误的"编码判不出"。

### 6.3 各格式适配规则

| 格式 | 分节依据 | 关键点 |
| --- | --- | --- |
| txt | 正则猜（**数字编号必须带分隔符**才算标题） | 只两级；重叠单位是句 |
| md | 自研解析（`#` 后有空格才算标题） | 1~6 级确定；代码块（```` ``` ````）不解析内部标记、不被切断；表格整片 |
| docx | POI XWPF：`getStyleID()`（样式名，中文版要归一化）+ `outlineLvl`（大纲级别，兜底）；表格 → markdown；**页眉页脚根本不读** | 顺序不能反：先样式名再大纲级别 |
| doc（Word 97–2003） | POI HWPF：样式名（**本地化不可靠，仅正向信号**）+ `getLvl()`（**可靠，语言无关**）+ 表格 | 顺序不能反；7 个真实样例里只有 1 个带标题样式，其余整篇一节 |
| pdf | PDFBox 抽行（text + y坐标 + 主字号 + 页码）→ 删页眉页脚（数字归一化后跨页同位置重复判定）→ 跨页拼接 | 不分标题，按「页」分节（`文件名 > 第N页`）；**明确不做表格还原 / 双栏还原 / 扫描件（无文本直接报错）** |
| excel | POI `WorkbookFactory`（按文件头认型）；公式格必须传 `FormulaEvaluator`；合并格按区域回填 | 按**工作表**分节（`文件名 > 工作表名`）；全空工作表报错 |

文本类入口探测编码；**二进制类绝不解码**。表格由 `MarkdownTable` 统一渲染成 markdown，docx/doc/excel 共用一份（检索侧表长得一样，BM25 字段权重才能统一）。图片只留占位符（`[图片: alt]`），不做 OCR（扫描件无文本 → 报错而非"导入成功、0 切片"）。

### 6.4 切片规则（通用层）

- 切片长度上限 max-chars＝400 字（中文约 400 token），是上限不是目标长度；撞标题立即断开（不跨标题拼接）。
- 相邻切片重叠 1 句（overlap-sentences＝1）；尾片短于 min-chars＝60 则并进前一片。
- 去重键 `content_hash = SHA256(切片正文)`，不含文件名。
- 单文件切片上限 max-chunks-per-document＝2000，超限直接拒绝。

### 6.5 切片元数据

| 字段 | 例子 | 用途 |
| --- | --- | --- |
| `text` | `第一章 会员规则 > 一、注册` + 空行 + 正文 | 给模型看的文本；同时喂 BM25 与向量 |
| `metadata.section_path` | `第一章 会员规则 > 一、注册` | BM25 单独加权、预览展示 |
| `metadata.section_title` | `一、注册` | 末级标题 |
| `metadata.chunk_seq` / `chunk_total` | `2` / `3` | 预览「2/3」 |
| `metadata.content_hash` | `SHA256(text)` | 去重，只算正文不含文件名 |
| `metadata.page_from` | 仅 pdf | 回引原文页码 |
| 其余 | `doc_id` / `file_name` / `upload_time` / `domain` | 与现状一致 |

ES mapping：`metadata` 加 `dynamic:false`，所有字段**全部显式声明**。

## 7 模型配置

模型接入分两层：**「模型设置」页的全局配置**（`config/llm-settings.json`，一套对话模型 + 一套向量模型）与**多 LLM 模型档案**（`config/models.json`，域可绑定到不同 OpenAI 兼容端点的档案）。

> 对话模型只来自用户自建的模型档案：一个域若没有显式绑定任何可用的对话档案，调用时直接抛 `NotConfiguredException`（`90005` 类）。全局对话模型配置仅作为"解析器未装配"时的兜底。

### 7.1 模型档案（多 LLM，`config/models.json`）

| 项 | 规定 |
| --- | --- |
| 单元 | `ModelProfile`：一个 OpenAI 兼容端点的**一份**配置（别名 `alias` 唯一；同一模型可配多份档案，域绑的是档案而非模型名） |
| 字段 | `alias`、`endpoints`(端点族 List，空 = 未声明)、`input` / `output`(模态 List)、`baseUrl`、`apiKey`、`modelName`、`temperature`(Double，可空)、`maxTokens`(Integer，可空)、`dimensions`(Integer，仅 embedding 用，可空)、`capabilities`(布尔能力 List：`streaming` / `tools`)、`fallbacks`(降级链，暂只存不生效) |
| 采样参数默认值 | 两个参数都是「**留空 = 取默认值**」，且默认值由**平台**定：`effectiveTemperature()` 未声明时返回 `0.5`；`effectiveMaxTokens()` 未声明时返回 `null`（不限制）。取 0.5 而非 0：0 接近贪心解码，工具调用与结构化输出时重复/卡死概率更高 |
| 类型从哪来 | **只读提供商元数据，不发试探请求**（唯一例外见下）。读不到绝不猜 |
| 模态词表 | `text` / `image` / `audio` / `video` / `file` / `embedding` / **`score`**（重排端点产出的相关性分数，唯一对应重排端点） |
| 探测的规范化 | 模型名先精确匹配，再按「去空白 + 忽略大小写 + 忽略 `vendor/` 前缀」匹配；地址缺 `/v1` 而 `/models` 返回 404 时补一次 `/v1` 重试 |
| 写回合并语义 | 端点族：读到就覆盖；输入/输出模态：仅当读数是**完整枚举**才覆盖，`sub_type` 给的是**基线值**只能并集；布尔能力：并集 |
| 维度的例外 | `GET /models` 按规范不给向量维度，故**向量档案**的「读取」额外发**一条**极短 `POST /embeddings` 实测维度 |
| 是否对话模型 | 无 `type` 字段；用 `isChat()` = `endpoints.contains("chat")` 判定；向量档案靠 `endpoints.contains("embedding")` |
| 必填 | `baseUrl` / `apiKey` / `modelName` 三者齐备才 `isUsable()` |
| 能力声明 | `capabilities` 由使用者显式写出；未声明 `tools` → 该域模型**不会调用任何工具** |
| 绑定规则 | **档案不自动绑定域**；一个域可绑一组有序的模型别名（整体覆盖，列表首个为当前使用的对话模型）；**空列表＝该域"无可调用模型"** |
| 解析顺序 | `ModelProfileRegistry#resolveAliases(domain)` 返回该域显式绑定的别名列表（有序）；列表为空 → 抛 `NotConfiguredException`；列表按序试：首个 `isUsable()` 且 `isChat()` 的档案即命中 |
| 域绑定 | `bind(domain, aliases)`：`aliases` 空 / 全部空白＝**解绑**；列表整体覆盖 |
| 删除 | **级联清理**：删除档案时先把它从所有域的绑定里摘掉、摘空的域绑定直接移除，再删档案本身 |
| 客户端缓存 | `ModelClientFactory` 按**档案指纹**（含 `baseUrl + modelName + 温度 + maxTokens + SHA-256(apiKey)`）缓存；轮换 Key / 端点 → 自然换实例 |
| 落盘 | `ModelProfileStore` → `config/models.json`；先改内存再整体落盘，落盘失败抛异常 |

### 7.2 服务商连接库（`config/provider-connections.json`）

| 项 | 规定 |
| --- | --- |
| 一条 = 什么 | `name`（唯一）+ `baseUrl` + `apiKey`（**可空**）。**地址与密钥合成一条**而不是拆成两个库 |
| 定位 | **取连接快捷方式，不是引用关系**。用户在档案表单选中 → 地址与密钥被填进表单 → 保存档案时**仍按原样把明文写进 `models.json`** |
| 唯一性 | 名称**不能重复**（在写入层 `ProviderConnectionStore.add` 判定，不只控制器） |
| 比较口径 | 去首尾空白后**精确匹配，不折叠大小写** |
| 密钥可空 | 本地 Ollama / vLLM 没有真密钥，**空密钥是合法状态** |
| 地址校验 | 只卡"根本不是一个可请求的 http(s) 地址"；**刻意不校验也不追加 `/v1`** |
| 明文出口 | **只有一处**：`POST /admin/provider-connections/resolve?name=`，且只在用户点了具体某个名称时才调用一次 |
| 没配密钥时选中 | `resolve` 返回 `hasApiKey:false`，前端**只填地址、不去动用户已填好的 Key** |

### 7.3 「模型设置」全局配置（`config/llm-settings.json`）

| 项 | 规定 |
| --- | --- |
| 配置来源 | `config/llm-settings.json`（运行时，高） > yaml `domainplane.ai.*`（低） |
| 文本模型字段 | `chatBaseUrl`、`chatApiKey`、`chatModelName`、`chatTemperature`（0~2，默认 0.5）、`chatMaxTokens`（默认 2048）、`chatCapabilities` |
| 向量模型字段 | `embeddingBaseUrl`、`embeddingApiKey`、`embeddingModelName`、`embeddingDimensions`（可空）、`embeddingCapabilities` |
| 回落规则 | 向量模型地址与 Key 留空时复用文本模型的值 |
| 空值语义 | 留空＝保持原值不变 |
| 状态三态 | `未配置` / `已配置·未验证` / `已连接` |
| 指纹 | `baseUrl + modelName + SHA-256(apiKey)`，文本与向量各存一份 |
| 装配方式 | `LlmModelHolder` 委托代理：`openAiChatModel` / `openAiStreamingChatModel` / `openAiEmbeddingModel`；热替换为原子替换，注入点不变 |

### 7.4 向量维度契约

维度取值的**唯一入口**是 `LlmModelHolder#effectiveEmbeddingDimension()`，以下三处必须同源：① 测试连接读取的实测维度；② 运行时 `EmbeddingModel` 构建时传入的 `dimensions`；③ ES 建索引时的 `dense_vector` 维度。

| 用户输入 | 行为 |
| --- | --- |
| `embeddingDimensions` 留空 | 请求不带 `dimensions`，索引取实测默认维度 |
| 显式声明 | 请求带 `dimensions=声明值`；实测与声明一致才通过 |

保存时的四态预检：`OK` / `NEEDS_REBUILD`（索引维度≠实测，需二次确认后保存并重建）/ `DECLARED_MISMATCH`（拒绝保存）/ `UNKNOWN`（无法实测，放行并提示）。

> ⚠️ **chat 模型可以按域随便切，embedding 不行**：embedding 维度 → ES 索引的 dense_vector dims（建索引时定死）→ 已写入的向量全部按该维度生成。让"域按 chat 的方式绑 embedding"会导致模型 A 写 1024 维、模型 B 查 768 维，检索不会报错，只会**悄悄全错**。当前做到：注册多个 embedding 档案（可切换），但同一时刻仍只有一个生效。

## 8 存储配置（Elasticsearch / Redis）

| 项 | 规定 |
| --- | --- |
| 配置来源 | `config/infra-settings.json`（高） > yaml / 环境变量（低） |

## 9 鉴权与凭证

| 项 | 规定 |
| --- | --- |
| 账号 | 单一账号，无角色、无权限分级。默认种子 `domainplane` / `domainplane`，由 `classpath:accounts-seed.json` 落盘为 `config/accounts.json` |
| 密码存储 | BCrypt 哈希 |
| 凭证格式 | `base64url(payload) + "." + base64url(HMAC(派生密钥, payload))` |
| 派生密钥 | `HMAC(主密钥, passwordHash)` ⇒ 改密码后全部旧凭证立即失效 |
| 有效期 | 无 TTL |
| 载具 | `/api/agent/**` 用请求头 `X-DomainPlane-Credential`；`/admin/**` 用 HttpOnly Cookie `domainplane_admin`，无 Cookie 时回退读同一请求头（供 starter / ETL 程序化调用） |
| 免检路径 | 被拦截前缀内的免检项：`/api/agent/login`、`/admin/login`、`/admin/init`、`/admin/session`、登录页与静态资源、`/error`、`/favicon.ico`；`OPTIONS` 一律放行。`GET /health` 不在被拦截前缀下，天然免鉴权 |
| 账号文件两态 | 文件不存在（合法初始态）→ 放行并开放 `/admin/init`；文件存在但解析失败 → 一律拒绝（`10007`），且不开放初始化入口 |
| 登录写盘 | 仅记录最后登录时间与来源，写盘失败只告警，不阻断登录 |
| 恢复路径 | 唯一恢复手段是删除 `config/accounts.json` 后重启；无密保、无重置接口 |

## 10 错误处理

| 项 | 规定 |
| --- | --- |
| 错误码载体 | `domainplane-api` 的 `ErrorCode`，五元组：`code` / `message` / `httpStatus`（建议值，非契约） / `retryable` / `action` |
| 码段 | `10xxx` 权限与鉴权 / `20xxx` 限流与容量 / `30xxx` 编排与会话 / `40xxx` 客户端与入参 / `50xxx` 系统通用 / `60xxx` 知识库 / `70xxx` 记忆与检查点 / `80xxx` 工具调用 / `90xxx` 大模型与外部依赖 |
| 三条通道 | SSE 事件的 `code`；非流式响应体的 `code`；starter 侧异常携带的 `ErrorCode` |
| 非流式出口 | `ServerGlobalExceptionHandler`（`@RestControllerAdvice`） |
| 流式出口 | `AgentEvent.ERROR` 帧（HTTP 状态已是 200，`code` 是唯一真相） |
| 响应体字段 | `code`、`codeName`、`error`、`detail`、`retryable`、`action`、`traceId`、`timestamp` |
| 成功响应 | 统一带 `code=0` 的接口：`health`、`stop`、`init`、`login`、`logout`、`session`、`changePassword`、`agentLogin` |
| 日志级别 | 默认记录 ERROR；以下降级为 WARN 且不打堆栈：`NotConfiguredException`、`AuthException`、`CancellationException`、`NoResourceFoundException`、参数与请求体类异常 |
| 存储类失败判定 | 按异常栈中是否出现 `Swappable*` 或 ES / Redis 客户端包名判定，映射 `90004`；未配置映射 `90005` |

## 11 日志

| 项 | 规定 |
| --- | --- |
| 控制台格式 | `时间 级别 [traceId] [线程] logger - 消息`，ANSI 着色 |
| 配色 | DEBUG/TRACE 不上色、INFO 蓝、WARN 黄、ERROR 红；traceId 青；线程名不上色 |
| 默认输出 | **仅控制台**。应用只写"事件流"，落盘、轮转、保留与采集交给部署平台 |
| 文件输出（可选） | 加启动参数 `--logging.config=classpath:logback-file.xml` 切换到文件形态 |
| 文件与滚动 | `{path}/domainplane-server.log` 全量（按天 + 单文件 50MB，保留 30 天 / 总量 2GB）；`{path}/domainplane-server-error.log` 仅 ERROR（保留 60 天 / 总量 1GB） |
| 审计 | 独立 logger 名 `AUDIT`，格式 `action=… operator=… result=… ip=…`；文件形态下另写 `{path}/domainplane-server-audit.log`（保留 180 天）。**只记变更类请求**（`/admin/**` 的非 GET/HEAD/OPTIONS 与工具实例注册） |

| 级别 | `domainplane.logging.level`，默认 INFO |
| 是否已启用文件输出 | 以 root logger 上是否挂着文件 appender 为准（运行事实），不读配置文本 |
| 级别准则 | 需要人工介入＝ERROR；需关注或已自愈降级＝WARN；关键节点＝INFO；排查细节＝DEBUG |
| 未配置的表达 | 启动期只以横幅 INFO 陈述；调用期未配置才 WARN（`90005`）；配了但连不上为 ERROR（`90004`） |

| 第三方降噪 | 默认压到 WARN：`dev.langchain4j`、`org.apache.http.wire`、`io.netty`、`reactor.netty`、`org.elasticsearch`、`co.elastic.clients`、`io.lettuce`、`org.springframework.web` |

| 线程池 | 位置 | 线程名 | core / max / queue | 拒绝策略 | 销毁 |
| --- | --- | --- | --- | --- | --- |
| 图编排 | `GraphConfiguration` | `domainplane-agent-N` | 8 / 32 / 200 | AbortPolicy | daemon + `shutdownNow` |
| 混合检索 | `RetrievalConfiguration` | `domainplane-retrieval-N` | 4 / 16 / 200 | AbortPolicy | daemon + `shutdown` |
| 知识库导入 | `KnowledgeBaseService` | `domainplane-kb-ingest-N` | 2 / 2 / 16 | AbortPolicy | daemon + `@PreDestroy` |

线程池参数外置：`domainplane.agent.*`、`domainplane.retrieval.*`、`domainplane.rag.ingest-pool-size`、`domainplane.rag.ingest-queue-capacity`。

| 同步原语 | 位置 | 保护的临界区 |
| --- | --- | --- |
| 条带锁 `StripedLocks`（固定 64 槽） | `InstanceRegistry`、`ToolRegistry` | 同一 `instanceId` 的心跳、判死、强制下线、副本替换 |
| `synchronized(this)` | `ClientCredential`、`ToolInstanceClient`、`AccountStore`、`SwappableRedisConnectionFactory` | 换凭证、账号读写、连接工厂热替换 |
| `synchronized(writeLock)` | `AuthService` | 初始化 / 登录写盘 / 改密码的整段"读-改-写" |
| `Semaphore(1)` | `KnowledgeBaseService` | 知识库导入串行与重名校验 |
| `ConcurrentHashMap` + `compute` | `ToolRegistry`、`CancellationRegistry`、`DomainSystemPromptResolver` | 条目原子替换、停止标志、告警去重 |

必须串行的边界：同一 `sessionId` 的对话；知识库导入；同一实例的注册表更新；账号与配置的写盘。配置写盘一律经 `AtomicFiles`（临时文件 + `ATOMIC_MOVE`）。

## 14 命名规范

> 只写**代码里已经做到的**约定，每条都能在 `src/main/java` 找到实例。

1. **缩略词按单词处理**：首字母大写 + 其余小写，禁止 `ESIndexManager` / `LLMSettings` / `PDFReader`。正确：`EsIndexManager` `LlmSettings` `PdfReader` `RagProperties`。
2. **三个"文档"词根各管一段**：`Ingest*`（导入过程）/ `Document*`（文档实体）/ `Doc*`（具体文件格式）。
3. **域在代码和契约里都叫 domain**：`domain`/`domainId` 是代码侧正式词根，也是契约字段（`AgentRequest.domain`、裸 HTTP 的 `domain` 参数、`DOMAIN_*` 错误码）。`ModelProfile*` 是另一回事——"模型档案 / 别名"义（见 §7），与"域"无关，保留 profile 命名。
4. **访问器 record 风格**（去 `get` 前缀）：`sessionId()` 而非 `getSessionId()`。豁免：`@ConfigurationProperties` 绑定、覆写第三方接口、Jackson 序列化契约（`AgentRequest.getSessionId()` 等改名会静默丢字段）。
5. **嵌套类型必须带业务前缀**：`DomainDeleteResult`、`DocParseResult`、`DomainBinding`、`ScanBinding` 等，避免 `Result`/`Binding` 跨包重名。
6. **作用域遮蔽**：新增嵌套类型前确认同包没有同名顶层类。
7. **常量与字段**：`static final` → `UPPER_SNAKE_CASE`（唯一豁免 `Logger` 字段叫 `log`）；普通字段 → `lowerCamelCase`；方法名禁止下划线/数字后缀（`sha256` 除外）；测试类以 `Test` 结尾。
8. **布尔方法一律 `is`/`has`/`can` 前缀**（Google Style）。
9. **跨模块同名类要加区分**：`ToolRouter` 与 `ToolProviderScanner` 是不同实现。
10. **零反模式前缀/后缀**：全库无 `I` 前缀接口、无 `*Utils`/`*Helper`/`*Manager`/`*Impl`/`*Adapter`/`*Wrapper`。

## 15 明确未实现 / 不支持的能力

写对外材料与做排障时，下列**必须主动排除**，否则会被懂行的人一问就穿：

| 项 | 真实状态 |
| --- | --- |
| **按终端用户身份鉴权** | 唯一授权维度是**域**。`tenantId`/`userId` 只透传给远程工具执行与日志，**不参与任何判定**。用户→域的映射仍要业务后端做 |
| **部门/岗位/项目/数据范围/临时授权** | 无主体、无属性、无策略引擎。域是工具可见性的**唯一维度**，不叠加第二个权限维度 |
| **记忆策略体系** | 无按部门/角色/敏感级别的保留周期、聚合范围、脱敏规则；键含 `sessionId` → 跨会话共享天然做不到。ttl 是全局永久 |
| **对话与工具调用的统一审计** | `AUDIT` 只记 `/admin` 变更类 + 工具实例注册，**不记对话与工具调用**；账号体系是"单一账号，无角色、无权限分级" |
| **集群 / 多实例** | **明确不支持**（单实例守卫，抢租约失败即拒绝启动） |
| **MCP** | 未实施 |
| **入口限流 / 并发上限** | 码已定义（`20000`/`20001`/`20003`）但**代码不发出** |
| **条件式审批**（按金额阈值等） | 未实施；`ToolDescriptor.Approval` 的 `condition`/`approverRoles`/`timeoutSeconds` 仅登记 |
| **PDF 字号推断标题** | 未做，当前 pdf 按「页」分节 |
| **Word 6 / Word 95 的 `.doc`** | 另有一套 API，实测会抛 `OldWordFileFormatException` → 报错并提示另存为 .docx |
| **图片 OCR / 扫描件文字抽取** | 不做（默认留占位符 `[图片]`）；扫描版 PDF 识别为"无文本"并报错 |
| **PDF 表格还原 / 双栏顺序还原** | 不做（PDF 只有文本流，硬做必然错） |
