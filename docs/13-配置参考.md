# 配置参考

分三类：**改行为的 yaml 键**、**管控台里改的运行时配置**、**落盘文件**。三者的真相源不同，排障时先分清改的是哪一类。

---

## 1. 覆盖优先级

```
命令行 --key=value  ＞  -Dkey=value  ＞  环境变量  ＞  application.yaml
```

`-D` 必须在 `-jar` 之前，否则会被当成应用参数静默忽略。

## 5. 编排与超时

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `domainplane.agent.virtual-threads` | `true` | 编排执行器用虚拟线程。置 `false` 才回落到下面三个池参数 |
| `domainplane.agent.core-pool-size` | `8` | 回落模式的核心线程 |
| `domainplane.agent.max-pool-size` | `32` | 回落模式的最大线程 |
| `domainplane.agent.queue-capacity` | `200` | 回落模式的队列 |
| `domainplane.agent.keep-alive-seconds` | `60` | 回落模式非核心线程空闲存活 |
| `domainplane.agent.concurrency-limit` | `200` | 并发闸门上限（`ConcurrencyGate`，不排队）。**虚拟线程下这是唯一的背压来源** |
| `domainplane.timeout.model-wait-ms` | `600000` | 等模型终态的总上限 |
| `domainplane.timeout.model-wait-slice-ms` | `200` | 等模型的分片；决定停止响应延迟，**不得大于总上限** |
| `domainplane.timeout.planner-wait-ms` | `60000` | 规划调用上限 |
| `domainplane.timeout.tool-invoke-ms` | `30000` | 本地工具 |
| `domainplane.timeout.vision-call-ms` | `60000` | 看图 |
| `domainplane.timeout.capability-call-ms` | `120000` | 生图/生视频/语音 |
| `domainplane.planning.enabled` | `false` | 规划前置总开关 |

编排执行器默认走虚拟线程（每任务一条），上面前两行的池参数只在 `virtual-threads=false` 时生效。

另外两个隔离池不走 `AgentProperties`，各自读一个独立键（`@Value`，无 yaml 声明时就取冒号后的默认值）：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `domainplane.vision.pool-size` | `8` | 看图隔离池线程数（零队列，满即拒） |
| `domainplane.capability.pool-size` | `8` | 能力调用隔离池线程数（零队列，满即拒） |
| `domainplane.capability.video-wait-ms` | `90000` | 生视频提交后的单次等待预算，**必须小于 `capability-call-ms`** |

## 10. 落盘文件

`domainplane.settings.path` 下：

| 文件 | 内容 | 带版本号 |
| --- | --- | --- |
| `accounts.json` | 管理员账号（BCrypt 哈希 + 主密钥） | 否 |
| `infra-settings.json` | 连接（关键字 ES / 向量 Qdrant / 原文 s3）与知识体、Redis | 否 |
| `provider-connections.json` | 服务商连接（地址 + 密钥） | 否 |
| `models.json` | 模型档案与域绑定 | 否 |
| `llm-settings.json` | 模型兜底设置 | 否 |
| `domains.json` | 域声明、可调用标记、软删标记 | **是** |
| `domains-history/v<N>.json` | 每次变更的快照 | 是（目录） |
| `prompts.json` | 域提示词 | 否 |
| `mcp-connections.json` | MCP 连接与域绑定 | 否 |

只有 `domains.json` 带版本与历史：它是所有派生状态的上游，需要能回滚、能在损坏时回退。

## 11. 三对"必须一起改"的配置

| 组合 | 不一致的后果 |
| --- | --- |
| `spring.servlet.multipart.max-file-size` ↔ 业务层 5MB | 容器先拦，用户拿到与"文件太大"无关的 500 |
| `domainplane.domain.delete-grace` ↔ `memory.checkpoint-ttl` | 域已删断点在，或白留垃圾 |
| `timeout.model-wait-slice-ms` ↔ `timeout.model-wait-ms` | 分片大于总上限时，"停止"永远等不到下一次唤醒 |
| `capability.video-wait-ms` ↔ `timeout.capability-call-ms` | 单次等待预算超过隔离池上限时，等待还没结束就被掐断 |

另一半边不在 yaml 里、但同样是"改一个要改两个"的：

- 动态工具判据（binder 与执行侧各一份）。
- 模型能力判据（同样两份）。
- 前端两套树（源码与产物）。

## 12. 日志

| 键 | 默认 |
| --- | --- |
| `logging.level.com.zzkingcc.domainplane` | `${DOMAINPLANE_LOG_LEVEL:INFO}` |
| `dev.langchain4j` | `WARN` |
| `org.apache.http` / `org.apache.http.wire` / `io.netty` / `reactor.netty` | `WARN` |
| `org.elasticsearch` / `co.elastic.clients` | `WARN` |
| `io.lettuce` / `org.springframework.web` / `org.springframework.boot.autoconfigure` | `WARN` |

`application.yaml` 里 `domainplane.logging.level` 与 `logging.level.com.zzkingcc.domainplane` 指向同一个环境变量 `DOMAINPLANE_LOG_LEVEL`，只改一处就够；`domainplane.logging.level` 是平台自己读的值，`logging.level.*` 才是日志框架真正生效的那份。

第三方默认压到 WARN 是有代价的：ES/Qdrant 的连接细节只有 INFO 以上才看得到，排障时要临时开到 INFO。
