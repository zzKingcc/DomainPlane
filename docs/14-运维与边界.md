# 运维与边界

上线前该知道的、出问题时该先看哪、以及哪些事现在**故意不支持**。

---

## 1. 部署形态：单实例

这不是"暂时没做"，是当前架构的硬约束：

| 运行态 | 位置 | 多实例后的问题 |
| --- | --- | --- |
| 取消标志 `CancellationRegistry` | JVM 堆 | `stop` 打到 A 节点，请求在 B 节点跑，停不掉 |
| 流出口 `StreamSinkRegistry` | JVM 堆 | 事件流绑在接请求的那台机器上，无法跨节点续 |
| 指标环形缓冲 | JVM 堆 | 每台只看到自己的 |
| 域版本巡检 | 只告警 | 配置改了不广播，其他节点保持旧值 |

`domainplane.single-instance-guard` 是**租约守卫**：抢到 Redis 里的租约才允许启动，抢不到就拒绝启动并提示。它的作用是防止"两台机器同时跑同一套配置与 Redis"，不是支持多实例。置 `false` 只用于人工接管（例如正在迁移、要临时起第二台做验证）。

### 容器化

```bash
docker run -d --name domainplane -p 9527:9527 \
  -v domainplane-config:/var/lib/domainplane/config \
  -v domainplane-chunks:/var/lib/domainplane/chunks \
  -v domainplane-blobs:/var/lib/domainplane/blobs \
  domainplane-server:v1.0-beta.2
```

| 卷 | 不挂的后果 |
| --- | --- |
| `config` | 重建容器 = 账号回落种子，全部配置重填 |
| `blobs` | 切片原文与媒体附件丢失，索引成孤儿 |
| `chunks` | 切片预览丢失（可重建，但要重灌） |

镜像内建 `HEALTHCHECK`，打免鉴权的 `GET /health`。端口用 `--server.port=` 覆盖。

## 2. 备份与恢复

### 必须备份

| 对象 | 为什么 |
| --- | --- |
| `settings.path`（8 个 JSON + `domains-history/` 目录） | 账号、模型、域、知识体、MCP 全在这里；丢一个就要重配一类 |
| `storage.path`（Blob） | 切片原文与附件字节。索引可重建，原文不可再生 |

### 可以重建

| 对象 | 重建方式 | 代价 |
| --- | --- | --- |
| ES / Qdrant 索引 | 管控台"重灌" | 全量重新向量化，耗时按文档量算 |
| 切片预览 txt | 重灌时顺带生成 | 同上 |
| 会话记忆 / 检查点 | 不可重建 | 丢了就是丢了（这是"档案"的代价） |

备份 `settings.path` 时注意 `domains-history/` 目录要一起打——只备 `domains.json` 的话，权威文件损坏时就没有回退快照。

### 忘记密码

唯一出口：删掉 `config/accounts.json` 后重启，回落种子账号 `domainplane` / `domainplane`。

这个动作会**同时让所有已发出的凭证失效**（`derivedKey` 依赖 passwordHash + masterKey，两者都变了）。属于预期行为。

## 3. 日志与观测

| 项 | 位置 / 值 |
| --- | --- |
| 日志目录 | `domainplane.logging.path`（默认 `/var/log/domainplane`） |
| 级别 | `DOMAINPLANE_LOG_LEVEL`，默认 INFO |
| 业务包 | `com.zzkingcc.domainplane` |
| traceId | 每轮生成，出现在日志与 `ERROR` 事件体里 |

排障顺序建议：`traceId` 定位一轮 → 看这一轮的 ERROR 码 → 按码查段位（10xxx 权限 / 60xxx 知识 / 70xxx 记忆 / 90xxx 上游）。

指标：

| 端点 | 内容 |
| --- | --- |
| `GET /admin/metrics` | 当前快照（采样间隔 `domainplane.metrics.sample-ms`，默认 10s） |
| `GET /admin/metrics/history` | 趋势 |

指标在进程内，重启清零，不跨实例聚合。Micrometer / OTel 未接——要接监控只能拉这两个接口自己转。

## 4. 后台任务

| 任务 | 频率（键） | 干什么 | 停了会怎样 |
| --- | --- | --- | --- |
| `InstanceLifecycle.scan` | 5s（`instance.scan-interval-ms`） | 摘掉超时实例的副本、标记强制下线 | 掉线的工具实例一直显示在线，调用才失败 |
| `MetricsSampler.sample` | 10s（`metrics.sample-ms`） | 采样指标 | 趋势图断点 |
| `McpCoordinator.reconcile` | 30s（`mcp.reconcile-ms`） | 建连、重盖章工具目录 | MCP 工具不更新、新连接不上线 |
| `DomainVersionWatcher.check` | 30s（`domain.version-check-ms`） | 比对域版本号（只告警） | 多实例落后不告警（单实例无影响） |
| `DomainPurgeScheduler.purgeExpired` | 60s（`domain.purge-scan-ms`） | 宽限期到 → 硬删域 | 删域永远停在第一阶段 |
| `ChunkArchiveReconciler.reconcileAll` | 5min（`knowledge.archive-reconcile-ms`） | 切片档案对账 | 原文缺失不被发现 |
| `MediaBlobSweeper.sweepOrphanBlobs` | 5min（`vision.blob-sweep-ms`） | 回收无主附件字节 | Blob 只增不减 |

七个定时任务全部是 `fixedDelay`（上一轮跑完才开始计时），由 `InstanceConfiguration` 上的 `@EnableScheduling` 启用，没有任何自定义 `TaskScheduler`，因此走 Spring Boot 默认的**单线程**调度器——任何一个任务阻塞，其余六个都会跟着推迟。`McpCoordinator` 除外：它另起一条 `mcp-init-reconcile` 线程做启动后首次建连，不占用调度线程。

七个里有三个会**删东西或改状态**（域清理、孤儿回收、实例摘除），都带年龄/超时护栏，不需要额外调度配置。

## 5. 执行器与背压

| 执行器 | 规模 | 队列 | 满时行为 |
| --- | --- | --- | --- |
| `agentExecutor` | 虚拟线程（每任务一条） | 无 | 无上限；背压由 `ConcurrencyGate`（`agent.concurrency-limit`，默认 200）给，超了发 `20002`。回落模式（`virtual-threads=false`）才变成 core 8 / max 32 / queue 200（默认拒绝策略 `AbortPolicy`） |
| `retrievalExecutor` | core 4 / max 16 | 200 | 拒绝 → 该路召回失败（`domainplane.retrieval.parallel=false` 时压根不提交） |
| `toolExecutorService` | `max(8, agent.max-pool-size)` | 0（`SynchronousQueue`） | 满即拒 → 工具返回失败给模型 |
| `visionCallExecutor` | `vision.pool-size`，默认 8 | 0 | 满即拒 |
| `capabilityCallExecutor` | `capability.pool-size`，默认 8 | 0 | 满即拒 |

只有检索池有队列，其余都是"满即拒"。这是刻意的：工具与多模态调用的排队只会把超时往后推，不如让模型立刻知道"这次没成"，它可以换个做法。

背压的两个外在表现：

| 现象 | 码 | 说明 |
| --- | --- | --- |
| 并发闸门饱和 | `20002 SYSTEM_BUSY` | 全平台容量满 |
| 同会话已有在跑的轮次 | `30003 SESSION_BUSY` | 调用方该等或该 stop |

## 6. 升级流程

版本号只有一个源头：根 `pom.xml` 的 `<version>`。改版时要同步的派生位置：

| 位置 | 改什么 |
| --- | --- |
| `pom.xml` | `<version>` 与 `<domainplane.version>` |
| `docs/assets/badge-version.svg` | `aria-label` / `<title>` / 显示文本 / 画布宽度四处 |
| `README.md` | 示例里的 Maven 坐标与 jar 名 |
| `Dockerfile` | `COPY … .jar` 的文件名 |

`domainplane-server/pom.xml` 的 `finalName` 取 `${project.version}`，不用手改。

**配置兼容性**：`domains.json` 带版本号，字段只增不删；其余 JSON 没有版本字段，新增字段必须能有默认值，否则老文件读出来是 null。

## 7. 已知边界

| 项 | 现状 |
| --- | --- |
| 多实例部署 | 不支持。三个运行态注册表在堆里；关掉守卫不等于支持 |
| 入口限流 / 并发会话上限 | 错误码已定义（`20000` / `20003`），代码不发出 |
| 归档 / 记忆自动清理 | 无（只增不减是有意设计），只有删域会级联 |
| 滚动摘要 TTL | 无（有损数据按档案对待） |
| MCP `LEGACY_SSE` | 已实现，**未对真实旧 server 验证** |
| MCP 协议版本 | 落后主流一个大版本（新版本的无状态核心未追） |
| PDF 深度解析 | 不做字号推标题、表格还原、双栏、扫描件 OCR |
| 向量模型 | 全局只能一个，不支持按域不同 |
| 官方 Maven 仓库 | 无，接入方必须自建或本地 install |
| 监控接入 | 未接 Micrometer / OTel，只有进程内指标 |
| 对象存储 | 只有本地 BlobStore，OSS/COS/S3 未做 |
| 工具实例回调鉴权 | 不做（内网假设） |
| 登录限流 | 无 |

## 8. 故障处置手册

### 对话完全不通

1. `GET /health` —— 服务活着吗？
2. `90005` → Redis 没配（存储配置页）。
3. `10010` → 域不是可调用叶子域。
4. `91001` → 这轮带了图片，域（含祖先域）没绑视觉模型。
5. `90006/90007` → 上游欠费/凭证问题，看事件体里的上游原文。

### 知识库搜不到

1. 域是否绑了知识体（没绑 → 静默不检索，不报错）；绑了但体两路空着 / 连接没填地址，同样不检索（绑定只落盘不校验）。
2. `GET /admin/kb/stats` 看该域"可检索"数字是否为 0。
3. 数字是 0 但文档表有记录 → 绑的是另一个体，或祖先链上没覆盖。
4. 数字非 0 但检索仍空 → 看 `minimumShouldMatch` 是否被调大、`minScore` 是否过高。
5. 索引列表整个为空 → 可能是 `listCollections` fail-open 吞了连接错误，查服务端日志。

### 工具突然不可见

1. 域是否还是叶子域（加了子域后父域自动失去可调用性）。
2. 动态工具（检索 / 能力类）的判据是否还成立：体是否可用、模型档案是否还有对应端点族。
3. 远程实例是否掉线（`GET /admin/instances`，35s 无心跳判死）。
4. MCP 连接是否被 disable，或工具目录重建后名字变了。

### 配置改了不生效

1. 改的是 yaml 还是管控台？两边有优先级（管控台的连接优先于 yaml）。
2. 是不是 `-D` 写在了 `-jar` 后面。
3. 是不是需要重启的项：`knowledge.strategy` 与后端类型变更会影响 bean 图，需要重启；其余支持热切换。
4. 前端改了没生效 → 是不是只改了 `frontend/src` 没构建。

### Redis 抖动导致大面积 70004

调 `domainplane.redis.timeout`（默认 5s）。跨机房部署时 2s 太紧，一次抖动就变成检查点读写失败，表现为"刚聊两句就报会话状态读取失败"。
