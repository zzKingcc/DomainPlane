# 域与能力装配

域（Domain）是这个项目唯一的"场景"载体。它决定这一轮对话能看见哪些工具、读哪几个知识体、用哪个模型、拼哪段提示词。本文只讲"域怎么定义、怎么合并、被删时会发生什么"。

---

## 1. 域的形态

一个点分全路径字符串：`default.customer.aftersale`。

规则全部在 `api.agent.Domains.validatePath` 里，只有六条，但每条都有代价：

| 规则 | 值 | 为什么 |
| --- | --- | --- |
| 首段固定 | `default` | 保证全平台共享一个根，索引名前缀统一，不需要"根域叫什么"的配置项 |
| 段字符集 | `[A-Za-z0-9_-]` | 域路径要进会话键、配置键和 URL，中文 / 空格会带来归一化歧义。索引名曾由域路径派生，v2 起改由知识体派生，这条限制保留 |
| 单段长度 | ≤ 64（`MAX_SEGMENT_LENGTH`） | ES 单个索引名限长 255，留出前缀与哈希后缀的余量 |
| 全路径长度 | ≤ 256（`MAX_PATH_LENGTH`） | 同上 |
| 不许重复段 | `a.b.a` 非法 | 重复段会让"沿链向上"的遍历出现歧义 |
| 允许隐式父域 | `a.b.c` 存在即 `a.b`、`a` 是节点 | 建子域不用先建父域，否则配置一个深层场景要先点三下 |

报错优先级就是校验顺序：空 → 超长 → 不从 `default` 出发 → 空段 → 单段超长 → 字符集 → 重复段。

域有两个来源，注册表取并集：

- **显式声明**：管控台建的域，落 `domains.json`。
- **隐式派生**：工具注解 `@Tool(domains = {...})`、MCP 域绑定里出现的路径。这类域不在 `domains.json` 里也能存在，也能被软删——所以软删标记单独存一份，不塞在域声明里。

## 2. 四维合并语义

一轮对话进入域 D 后，四类能力沿 `D → 父 → … → default` 这条链取：

| 维度 | 语义 | 具体规则 | 反向不成立的地方 |
| --- | --- | --- | --- |
| 工具 | 累加 | 工具声明在 D 或 D 的任意祖先 → D 可见 | 声明在子域的工具，父域看不见 |
| 知识 | 累加（向上） | 检索域 = D + 全部祖先，各域绑定的知识体都查，结果融合 | **召回不向下**：子域的文档父域查不到 |
| 提示词 | 累加 | 从根往叶子拼，根域片段即基底，无"公共基线"这一层 | 改一段只影响该域及其后代 |
| 模型 | 就近覆盖 | 链上第一个绑定了模型的域胜出，找到即停 | 子域绑了就完全盖掉父域，不合并端点族 |

这条"三累加一覆盖"不是随手定的：

- 工具、知识、提示词都是**能力供给**，父域提供的东西子域理应能用，否则每建一个子域都要复制一遍配置。
- 模型是**资源绑定**，一个域只能用一份档案（模型名、上下文长度、参数都是一套）。合并端点族会造出"图的端点来自 A、文本来自 B"的怪档案，因此只取最近的一个。

### 知识这一维有两件事必须分开看

| 问题 | 答案 | 机制 |
| --- | --- | --- |
| 用哪个知识体（连哪台机器） | **不继承** | `DomainStore.bodyOf(domain)` 纯查表，没绑就是空；`bodiesOf` 也不会去父域借 |
| 查得到谁的数据 | **沿链向上累加** | `RetrievalPlan.channels` 对 D 与每个祖先分别开通道 |

看起来矛盾，其实是一件事的两面：知识体回答"写和读落在哪套存储"，域链回答"允许看哪些索引"。如果让知识体继承，子域的文档会写进父域的库，用户完全看不出来——这比"多查了几条"危险得多。

## 3. 可调用性：为什么必须传叶子域

判定只有一条：**显式标记为可调用 ∧ 没有子域**。

`default` 预置为可调用，所以单域部署开箱即用；一旦建了 `default.customer`，`default` 自动失去可调用性，请求会报 `10010 DOMAIN_NOT_CALLABLE`。

这个设计的动机是防"半配置状态"：如果父域也能当入口，用户会在父域上配一半能力、在子域上配另一半，然后拿到一个谁都解释不清的混合装配结果。把入口钉在叶子上，"这个域的全貌"就等于"这张卡上的内容"。

代价是建域顺序有讲究：**先建子域再标可调用**，别先标父域。管控台的建域流程按这个顺序引导，接口层不做自动降级。

## 4. 会话键：`(域, sessionId)`

会话键是 `SessionKeys.of(domain, sessionId)`，用 `|` 拼成 `default.customer|session-001`。

- 同一个 `sessionId` 在不同域下是**两段完全独立的会话**（记忆、检查点、取消标志都分开）。
- `resume` 与 `stop` 都必须带与 `chat` 相同的 `domain`，否则会打到另一段会话上——`resume` 的表现是 `30001 会话不存在`，`stop` 的表现是返回 `false`。
- SDK 侧 `forDomain()` 绑死域，就是为了让调用方不可能漏传。

## 5. 域数据的存储与版本

`domains.json` 是**唯一带版本号的文件**，因为它是所有派生状态的上游（工具可见域、知识通道、提示词拼接都从它算）。

| 机制 | 行为 |
| --- | --- |
| 版本号 | 每次成功落盘 `version + 1`，单调递增 |
| 历史快照 | 每次变更写一份 `domains-history/v<N>.json` |
| 启动容错 | 权威文件读坏 → 自动回退最近一个可读快照，服务继续起，下次落盘自动修复 |
| 全部不可读 | 拒绝启动（fail-closed），不当空配置放行 |
| 回滚 | 一次普通的新变更（`version+1`），不是时间倒流 |

"回滚也是新版本"这条很关键：如果回滚改成"把 version 改回去"，多节点的版本比较就会永远对不上，而版本比较正是跨节点唯一的一致性信号。

跨节点只有**告警**没有同步：`DomainVersionWatcher` 每 30s 比对 Redis 里的域版本号，落后就标记 `behind` 并打日志。真正的配置同步没做——单实例部署下它没有意义。

## 6. 删域：三阶段

删域要清 Redis 里的会话状态，但**不碰知识库存储**（v2 起知识体是独立的数据实体），所以拆成三段：

```
DELETE /admin/domains/{id}
  ├─ 阶段一：打软删标记（deletedAt）——整支树一起打
  │    · 域立即不可用：新会话报 10011 DOMAIN_PENDING_DELETE
  │    · 在途会话继续跑（不能半路砍断）
  │    · 可撤销：POST /admin/domains/{id}/restore（整支树一起恢复）
  │      · 撤销被拒（10012 DOMAIN_DELETE_BLOCKED）：清理已在跑，或宽限期已到
  ├─ 阶段二：宽限期到（domain.delete-grace，默认 24h）
  │    · DomainPurgeScheduler 每 60s 扫一次到期项（domain.purge-scan-ms）
  │    · 立即硬删不走这条路：DELETE 带 ?force=true，或 delete-grace=0
  └─ 阶段三：级联清理
       · Redis：记忆、检查点、历史检索索引、摘要、会话归档（失败即抛，域不删）
       · 知识体：只解绑（随域声明一起落盘），原文与索引一个字节不动
       · 配置：域属性、模型绑定、MCP 绑定、工具域声明
       · 注册表：从域树摘除
```

`10012` 只在 `restore` 被拒时抛出，不是"进入清理就主动发的事件"——删域请求本身不会返回它。

两个数字必须对齐：`domain.delete-grace` 与 `memory.checkpoint-ttl` 是"同一时钟的两半"。宽限期短于检查点 TTL，会出现"域已硬删、断点还在"，之后 `resume` 报的错会指向一个不存在的域；反过来则白留垃圾。改一个就要改另一个。

删之前可以先预演：`GET /admin/domains/{id}/delete-impact` 返回子孙域、会被解绑但完整保留的知识体（含文档 / 切片数）、模型与 MCP 绑定；`knowledge.indicesDeleted` 恒为 0。预演不会写任何东西。

清理范围是**自身 + 全部子孙**，不是只有自己——删父域必须连子域一起清，否则会留下一棵挂不上树的孤儿子树。

## 7. 变更回调：只有一个，但可以挂多个

`DomainStore.onChange` 是一组监听器（`CopyOnWriteArrayList`），每次成功落盘后逐个回调，单个监听器抛异常只打 WARN。

它和 `versionListener` 分工不同，别混：

| 回调 | 范围 | 典型消费者 |
| --- | --- | --- |
| `versionListener` | 跨节点（Redis 广播） | 版本巡检 |
| `onChange` | 本节点 | 知识检索工具的可见域重算、能力工具可见域重算 |

历史上这里是个单值字段，第二个消费者会把第一个悄悄顶掉——所以现在写成了列表。挂监听器前先确认自己是"幂等派生状态重算"，不要在里面做写操作或远程调用。

## 8. 装配：域决定"给模型看什么"

一轮对话的上下文由四块拼成，其中三块受域影响：

| 块 | 来源 | 受域影响的方式 |
| --- | --- | --- |
| 系统提示词 | 沿域链拼接 | 只拼链上的片段 |
| 历史摘要 | 该会话的滚动摘要 | 不受域影响（会话键已含域） |
| 最近窗口 | 该会话最近 N 轮 | 同上 |
| 知识片段 | 检索工具在轮内调用产生 | 检索域 = 自身 + 祖先 |

注意最后一行：**知识不是装配期注入的**。装配只拼历史与提示词，知识片段是模型主动调 `searchKnowledge` 工具拿回来的。这样做的原因是"要不要查、查什么"本身就是一个决策，塞在装配期等于替模型做了决定。

预算怎么分、超了先丢谁，见 [05-记忆与上下文](05-记忆与上下文.md)；工具可见性怎么算，见 [06-工具体系](06-工具体系.md)。

## 9. 踩过的坑

**域路径拼错不会报"域不存在"，而是报"不可调用"。** 因为 `a.b.c` 里只要有工具声明过 `a.b.c.x`，父子链就自动成立，拼错的域常常"存在但没人标记可调用"。排查顺序是先看域是否在树里，再看 `callable`。

**索引名不可读，而且不属于域。** `domainplane_kb_<知识体 slug>_<sha8>`，建体时派生并冻结，域改名 / 删除都不影响它。看到一串 `domainplane_kb_sales_1a2b3c4d` 别指望从名字反推域——反查"这个集合归谁"用 `GET /admin/bodies`（每体带 `index`）或知识库页运维区的诊断。

**父域改提示词会立刻影响所有子域。** 这是累加语义的必然结果，不存在"改完只对之后的新会话生效"——提示词是每次请求现拼的。

**删父域时子域的在线会话会先卡住再被清。** 阶段一拒绝新会话、不断在途；阶段三才动 Redis。如果这时恰好有人 `resume`，会拿到 `30001`，属于预期。
