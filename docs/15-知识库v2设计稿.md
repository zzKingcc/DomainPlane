# 知识库 v2 设计稿：知识体成为数据实体、删域保留、原文落点可选

> **状态：P0 ~ P4 已落地；P5（运维区：诊断 / 无主认领 / 遗留清理 / 合并体）未做。**
> 「现状」一节记录的是写稿时（v1.0-beta.2）的旧代码，用于解释为什么要改；
> 当前语义以本文 §2 之后与 [`07-知识库.md`](07-知识库.md) 为准。
>
> 已实现：知识体 = 数据实体（唯一 slug + 创建时冻结的索引 + 两路落点 + 原文落点 + 文档）、
> 多域共用一个体、**删域只解绑（零存储 I/O）**、体级重建（从原文 / 清空）、
> 体级上传与文档管理、v1 索引零拷贝迁移（`KnowledgeLegacyMigrator`）、
> 原文档案权威化（对账不再因集合消失删档案）、管控台知识体卡片页。
>
> **P3 已落地**：`PUT /admin/bodies/{id}/routes` 换落点（预演 → 在新连接写满 → 校验条数 →
> 切指针；旧集合留作遗留不删）、`GET /admin/bodies/{id}/health` 三方维度对照。
> 与本文原设计的偏差：**不需要"迁移期间检索不可用"**——索引名固定，新旧两台可以并存同名集合，
> 写满之前指针仍指旧连接。未做：迁移的逐文档进度与暂停、诊断区与无主集合认领（P5）。
>
> **P4 已落地**：连接加 `s3` 类型（`InfraSettings.ObjectStorage`）+ `S3BlobStore`（AWS SDK v2，
> url-connection-client）+ `BlobStoreRegistry`（落点 → store，按连接配置指纹重建客户端）；
> `ChunkArchive` 按体的 `raw` 路由，新增原始字节 `kb/files/{index}/{docId}`；
> `PUT /routes` 的 `{raw:...}` 走"先搬后切"；「下载原文」= `GET /documents/{docId}/raw`；
> 存储页 2-3 段可新增 / 编辑 s3 连接，原文落点的可选值由 `InfraSettings.rawLocations()` 现算。
> 与本文原设计的偏差：**原始文件的键不带扩展名**（推断扩展名要 LIST 一次桶，不值得；
> 下载时用文档表里的 `fileName`）。
>
> **与本文原设计的偏差（有意为之）**：
> 1. 知识体**仍存在 `infra-settings.json` 的 `bodies` 里**，没有新建 `bodies.json`。
>    理由：体与连接是同一份配置生命周期、同一把锁、同一版本号，拆成两个文件只会多一处
>    "改了一半"的中间态；`slug` / `index` / `raw` 三个字段落进同一个 `KnowledgeBody` 记录即可。
> 2. 原文落点白名单**目前只有 `local`**（`InfraSettings.SUPPORTED_RAW_LOCATIONS`）。
>    S3 / COS / OSS / 文件服务连接要等 `BlobStore` 多驱动与连接类型扩展，
>    页面只显示真实可选项，不做假下拉。
> 3. 索引名格式为 `domainplane_kb_<slug>_<bodyId 短哈希>`（`KbIndexes.nameOfBody`），
>    从"域路径"改为"体唯一名"；老索引由迁移器**原样保留名字**登记，不搬数据。
>
> 一句话：**知识体从「存储路由」升格为数据实体**——它有自己的唯一名、由这个名字派生的
> 索引、自己的原文落点、自己的文档与生命周期；域只是绑定它的消费者，不再承担任何知识管理职能。
> 删域只解绑，不动知识数据。

## 1. 现状：三层模型，与它隐含的三个硬假设

今天的三层（`07-知识库.md` §1）：

```
Connection（一台具体 ES / Qdrant）
   ↓ 被引用
KnowledgeBody（知识体 = 纯路由：keyword 槽 + vector 槽 + modes）
   ↓ 被域绑定
域（domain）  ← 数据身份却长在它身上
```

数据落点**由域路径确定性派生**：

| 产物 | 落点 | 派生规则 |
| --- | --- | --- |
| 关键字索引 / 向量集合 | `domainplane_kb_<域路径安全化>_<SHA-256 前 8 位>` | `KbIndexes.nameOf(domain)` |
| 原文档案（切片 JSON，剥向量） | BlobStore `kb/chunks/{索引名}/{docId}.json` | 跟着索引名 |
| 切片预览 txt | 导出目录，按 docId | 跟着 docId |

三个硬假设，就是页面上「上传文档 / 索引重建 / 重灌到新后端」三张卡的由来：

1. **一个域 = 一份数据**（一域一索引）→ 上传必须选「归属域」；
2. **全站一个知识库视图** → 上传、重建、重灌只能是页面级全局按钮；
3. **原文只能落内置磁盘** → 存储页「2-3 原文」只有一行只读 `blob-local`。

### 1.1 它们与「知识体」对不上

知识体是**路由**，不是容器：它只回答"这类活该连哪台机器"。但页面把它当第一等对象，
于是出现两处说不通：

- **共用体 ≠ 共用知识。** 域 A、B 都绑 `kb-1`，索引仍是 `domainplane_kb_a_xxx` 与
  `domainplane_kb_b_yyy`，检索互不可见。卡片上写「绑定域 2」会让人以为两个域吃同一批
  文档 —— 实际只是共用机房。**这是"共用不麻烦"要解决的核心。**
- **删域 = 灭知识。** 数据身份在域上，删域必须连索引、原文档案、预览 txt 一起删
  （`DomainPurgeService` → `KnowledgeBaseService.deleteIndices`）。域是组织结构，知识是
  资产，两者生命周期本来就不同：**重组组织结构不该销毁资产**。

### 1.2 三张卡各自的问题

| 卡 | 现在做什么 | 为什么退场 |
| --- | --- | --- |
| 上传文档 | `POST /admin/kb/documents`，必选「归属域」 | 上传是**知识体内**动作；选域等于每次新建一份数据，没有"往同一份知识里再传一个文件"这条路 |
| 索引重建 | `POST /admin/kb/rebuild` → 删掉全部索引重建 | 把可重建的派生数据与权威原文一起扔掉，文档得重传。修复手段本身成了事故源 |
| 重灌到新后端 | `POST /admin/kb/reindex`，全站索引搬另一台连接 | 全有或全无、无法按体挑、没有进度与回滚；本质是"换落点"，应该长在知识体卡片上 |

还有一处结构性隐患：`ChunkArchiveReconciler` 每 5 分钟按「collection 还在不在」判断原文
是否孤儿，不在就删 —— **原文的生命周期被派生数据反控**。一旦开始"保留数据"，这条逻辑
就是数据销毁器，必须同步改造（§12）。

## 2. 目标模型：两个功能层，知识体是数据实体

```
Connection        一台具体存储实例（关键字 ES / 向量 Qdrant / 原文对象存储）   —— 存储页
     ↓ 三路引用
KnowledgeBody     知识体：唯一名 + 冻结索引名 + 三路落点 + 文档 + 绑定域 + 健康
                  ↑ 页面第一等对象，所有维护动作的起点                      —— 知识库页
     ↓ 多对多绑定
Domain            域：只声明"我读哪几个知识体"                            —— 域空间页
```

与上一稿（引入「知识库 / Library」并把它上面的「知识体」改名「存储组」）相比，
**少一层**：知识体自己就是数据实体，不再有"路由层 + 数据层"的二分。理由很直接：

- 路由（关键字/向量/原文连哪台）本来就是"这份数据落在哪"，与"这份数据是什么"是同一件事
  的两面，拆成两个对象只会让用户在两张页面之间来回跳；
- 共用诉求只需要一件事：**一份数据一个索引**。索引归知识体所有，多域绑定同一体即共用，
  不需要额外的容器对象；
- 域侧只剩一句声明，职责真正缩小（§7）。

四个不变量（写进代码注释，别只写在文档里）：

1. **知识体名唯一**（slug 唯一，建/改名都校验）；
2. **索引名在创建时按唯一名派生，之后冻结**（改名不搬数据）；
3. **三路落点可改，改落点 = 在新连接上从原文重建**（旧连接上的同名集合标"遗留"，不自动删）；
4. **域不持有任何知识数据概念**：没有上传、没有重建、没有落点配置、没有删除权。

### 2.1 术语对照

| 今天 | 目标 | 说明 |
| --- | --- | --- |
| Connection | Connection | 不变，但多一类：原文 |
| KnowledgeBody / 知识体 | **知识体（数据实体）** | 名字不变，语义升级：名字唯一、索引归它、原文落点归它、文档归它 |
| 域 → 知识体（单值） | 域 → 知识体列表（0..n） | 域成为消费者；多体 = 多来源 |
| 域即数据身份 | 知识体即数据身份 | 索引名 = f(知识体唯一名)，与域路径无关 |
| 索引 = f(域路径) | 索引 = 创建时 f(唯一名)，冻结 | 迁移时把现有索引名直接登记，零拷贝 |
| 原文 = 内置 BlobStore 固定 | 原文 = 知识体的一路落点（本地 / S3 兼容） | 卡片上可选、可迁移 |
| 「知识体」配置在存储页 | 「知识体」在知识库页成卡 | 存储页只剩连接池与容量 |

> 上一稿提到的「存储组」概念在本稿中**取消**：它就是本稿的知识体。

## 3. 命名、索引与落点

### 3.1 唯一名与索引

```
知识体 id      沿用现有键（如 kb-1），内部稳定，不出现在 URL 之外
唯一名 slug    [a-z0-9-]{2,40}，例如 products、aftersale-faq；页面显示中文名与 slug
索引名（新建）  domainplane_kb_<slug>_<id 哈希前 8 位>
               例：slug=products, id=kb-1 → domainplane_kb_products_37a8eec1
索引名（迁移） 沿用现有名 domainplane_kb_<域安全化>_<h8>（登记进体，不搬数据）
```

- **创建时派生一次，之后冻结**：名字可改（slug 跟着改，需唯一校验），但体上记录的
  `index` 不再变。改名的代价为零，也不会因为"改个名"把数据搬到另一个集合。
- 哈希后缀防撞：`a.b` 与 `a_b` 安全化后同名、超长截断撞名、以及不同体撞同一个 slug 的
  并发建。
- 一个体一组集合（关键字一个、向量一个，可能在不同连接上；原文一类对象）。
- 为什么仍 **collection-per-body**：隔离、删除、重建都在物理层完成，与现有
  `KnowledgeStore` 契约一致；代价是单后端体数有上限（几百量级，见 §14）。

### 3.2 原文落点与产物

原文落点 = 知识体卡片上的一个下拉：`本地盘` / `COS bucket` / `OSS bucket` / `MinIO` …
（连接定义在存储页，见 §6）。对象键：

| 产物 | 键 | 现状 | 目标 |
| --- | --- | --- | --- |
| 切片 JSON（剥向量） | `kb/chunks/{index}/{docId}.json` | 有 | 保留（index 归体后天然稳定，域变化不影响档案） |
| 原始文件字节 | `kb/files/{index}/{docId}{.ext}` | **没有** | 新增（默认开） |
| 切片预览 txt | 导出目录 `{文件名}.{docId}.chunks.txt` | 有 | 保留（人看的旁挂产物） |

原始字节的价值不只是"下载原文"：换解析器/改切片策略时能从原文重切；原文后端迁移时
可做字节级校验；「看文档」可从字节重渲染。代价：占用接近翻倍 → **决策点 D3**。

### 3.3 配置落盘（与今天相比的变化）

~~新增 `bodies.json`，把"知识体的身份 + 三路落点"从 `infra-settings.json` 里搬出来。~~

**实际做法：不拆文件。** `KnowledgeBody` 就地长出 `slug` / `index` / `raw` / `description`
四个字段，仍住 `infra-settings.json` 的 `bodies` 下 —— 体与连接共享一份配置、一把锁、
一个版本号，拆开只会多出"改了一半"的中间态。下面是**字段形态**（不是独立文件）：

```json
{
  "bodies": {
    "kb-1": {
      "slug": "products",
      "name": "商品资料库",
      "description": "客户可见的产品手册与报价口径",
      "index": "domainplane_kb_products_37a8eec1",
      "routes": { "keyword": "es-text01", "vector": "qdrant-text01", "raw": "cos-products" },
      "createdAt": "2026-11-04T02:35:08Z"
    }
  }
}
```

~~`infra-settings.json` 只留连接与 Redis：~~

实际 `infra-settings.json` 同时持有 `redis` / `connections` / `bodies` 三块；
原文落点 `raw` 当前只有 `local`（可选值由 `SUPPORTED_RAW_LOCATIONS` 白名单给出，
前端只渲染白名单里的项）。

- **绑定仍在域声明里**（`domains.json` 的 `body` 字段），不放在体上：删域只改域文件，体文件不动；
  体卡片上的「绑定域」由 `DomainStore.bodies()` 反查得到；软删宽限期内撤销时绑定根本没被改过，
  恢复天然正确。
- 域仍然**只绑一个体**（决策点 D2：现阶段不做多体绑定），`bodies: [...]` 留给未来版本；
  "共用"由「多个域绑同一个体」表达，不是「一个域绑多个体」。

## 4. 生命周期与「删域保留」新语义

### 4.1 知识体状态机

```
创建（只建元数据：空体没有集合是有意的）
  ↓ 首次上传 / 显式初始化
就绪 ──绑域──→ 使用中 ──解绑（含删域）──→ 未绑定
  ↑                                       │
  └──── 绑定到新域 ←─────────────────────┘
  └── 显式删除（危险动作，见 4.3）──→ 已删除（原文可保留）
```

「未绑定」是常态（用户先建体、后挂域），页面单独一段显示，带容量提示，**不自动清理**。

### 4.2 删域：删什么、留什么

| 数据 | 今天 | 目标 | 为什么 |
| --- | --- | --- | --- |
| 会话记忆 / 断点 / 归档 / 摘要 / 历史检索 | 删 | **删（不变）** | 属于"这个域的对话"，不清会复活旧上下文 |
| 域声明（提示词、模型绑定、工具、MCP） | 删 | **删（不变）** | 同路径域重建不该静默复活旧配置 |
| 域 → 知识体绑定 | 随索引一起毁 | **删绑定** | 域没了，引用自然失效 |
| 知识体（索引 + 集合） | 删 | **保留** | 资产；可被新域复用 |
| 原文档案（切片 JSON + 原始字节） | 删 | **保留** | 权威源；重建索引的唯一依据 |
| 切片预览 txt | 删 | **保留**（随体） | 旁挂产物，由体生命周期决定 |

流程（`DomainPurgeService` 第 4 步改写）：

```
3) Redis 记忆 / 归档 / 摘要 / 检索索引  —— 不变，失败即抛
4) 知识库：解绑，不删
     a. 读出受影响域（含子孙）绑定的知识体 id
     b. 从 domains.json 摘掉这些绑定（与域声明一起写，失败即抛）
     c. 不触达任何存储后端：==删域不再依赖 ES/Qdrant 可达性==
     d. 返回 retainedBodies: [{id, name, slug, index, documents, boundDomains:剩几位}]
5) 域属性清理 —— 不变
6) 域注册表删除 —— 不变
```

三个白捡的好处：

- **删域不再被存储黑洞挡住**：今天 ES 连不上就拒删；新语义下解绑是纯本地写；
- **软删撤销零成本**：宽限期内什么都没解绑（解绑发生在硬删）；
- **可解释**：接口能原话返回"保留了 2 个知识体、各多少文档、还有几个域在用"。

### 4.3 删体：唯一的危险动作

`DELETE /admin/bodies/{id}`，必须带 `confirmName`（输入体名或 slug）：

| 选项 | 行为 | 用途 |
| --- | --- | --- |
| `keepRaw=true`（默认建议） | 删关键字/向量集合，**保留原文档案** | 换落点前腾空；或以后从原文重建 |
| `keepRaw=false` | 全删（集合 + 原文 + 预览 txt） | 真的不要这批知识 |

执行顺序（与今天 `deleteIndices` 同口径，对象换成体）：

```
1) 仍有域绑着 → 拒绝（先解绑；或 ?force=true 一并解绑并返回清单）
2) 先删旁挂产物（按体的 index 列 docId → 预览 txt / 原始字节 / 切片 JSON[keepRaw=false]）
3) 再删集合（逐台；历史遗留可能同名集合在多台上都有）
4) 任何一步存储不可达 → 中止并如实回报"体仍存在、已删了什么"
```

## 5. 页面设计：知识库页（知识体为第一等）

### 5.1 信息架构

```
┌─ 顶栏 KPI ───────────────────────────────────────────────────────────────┐
│ 知识体 6（未绑定 1） │ 文档 128 │ 切片 1,842 │ 向量模型 bge-m3(1024) │ 健康 │
└──────────────────────────────────────────────────────────────────────────┘
┌─ 知识体（主区；默认「使用中 → 未绑定」排序） ───────────────────────────┐
│ ┌ 商品资料库  products  [就绪] [使用中]                                 │
│ │ 索引 domainplane_kb_products_37a8eec1                                 │
│ │ 关键字 es-text01 · 向量 qdrant-text01 · 原文 COS products/kb           │
│ │ 文档 8 · 切片 96 · 原文 1.2 MB                                        │
│ │ 绑定域 default · 售后（共用 2 个域）                                    │
│ │ [上传文档] [文档·8] [健康] [重建索引 ▾] [⋯ 设置 · 删除]                │
│ └───────────────────────────────────────────────────────────────────────┘
└──────────────────────────────────────────────────────────────────────────┘
┌─ 未绑定知识体（折叠，有内容才出现） ───────────────────────────────────┐
│ 报价口径 v3  quote-v3  文档 12  原文 3.4 MB  [绑定到域…] [删体]          │
│ ↳ 已没有任何域使用，数据仍在；绑定后立刻可检索，无需重传。               │
└──────────────────────────────────────────────────────────────────────────┘
┌─ 运维（折叠，默认收起；二次确认 + 影响面预览） ────────────────────────┐
│ 索引诊断 · 无主集合认领 · 遗留集合清理 · 合并知识体 · 从原文全量重建     │
└──────────────────────────────────────────────────────────────────────────┘
```

**三张旧卡整组移除**，全部改成以知识体卡片为起点：

| 旧卡 | 新入口 |
| --- | --- |
| 上传文档 | 卡片「上传文档」/ 体抽屉「文档」页签 |
| 索引重建 | 卡片「重建索引 ▾」（默认从原文，不再是删了重建） |
| 重灌到新后端 | 卡片「设置 → 落点」换连接，触发"在新连接上从原文重建"（§5.5） |

### 5.3 体抽屉（右侧 700px，三页签）

1. **文档**：库内文档表 —— docId / 文件名 / 切片数 / 关键字✓ / 向量✓ / 原文✓ / 更新时间 /
   操作（查看切片、下载原文、删除）。顶部固定上传区（拖入即传，显示落点、覆盖规则、预估）。
   关键改进：**每行三态打勾**，缺哪一路一眼可见（今天只看总数，看不出某篇缺档）。
2. **健康**：
   ```
   关键字索引  es-text01  ✓ 存在  mapping: dims=1024, analysis-ik ✓
   向量集合    qdrant     ✓ 存在  size=1024, distance=Cosine
   当前向量模型 bge-m3    原生维度 1024                     ✓ 三方一致

   ```
   三方维度对照是今天"探测全绿、检索报错"的高发来源，做成一张表。
3. **设置**：
   - 名称（唯一校验，提示"改名不改索引"）、slug、描述；
   - **三路落点下拉**（关键字 / 向量 / 原文）——每路带健康灯与"改这一路会发生什么"；
   - 危险区：删除知识体（keepRaw 选项 + 输名确认）。

[预演] "1 个集合 / 8 文档 / 96 切片；1 篇缺原文会被跳过" → [执行]
```

换落点（卡片设置里改某一路的连接，等价于"迁移这一路"）：

```

逐文档进度 ▓▓▓▓▓▓░░ 可暂停；失败逐条列出

        旧连接上的同名集合标「遗留」，由运维区清理（不自动删）

## 6. 存储页设计（瘦身：只剩连接池）

### 6.1 现在的样子

```
2-1 Redis
2-2 连接：关键字（ES）表 / 向量（Qdrant）表
2-3 原文：一行只读 blob-local      ← 不是连接、不能选、不能测
   知识体：两张槽的下拉            ← 本稿搬去知识库页
```

### 6.2 目标

```
2-1 Redis（不变）
2-2 连接：三类，同一套表格组件
    · 关键字  ES：host / port / scheme / 账号 / 口令 / 超时
    · 向量    Qdrant：uri / token / collectionPrefix / metric
    · 原文    对象存储：provider / endpoint / bucket / region / ak / sk / prefix / pathStyle / rootDir
2-3 容量与用量（P3 可选）：按连接汇总 体数 / 文档数 / 切片数 / 原文字节
```

知识体的三路落点不在存储页配，改由知识体卡片的「设置」承担（§5.3）：
**存储页回答"有哪些机器"，知识库页回答"这份数据落在哪台"**。

### 6.3 原文连接字段

| 字段 | 说明 | 本地盘 |
| --- | --- | --- |
| `provider` | `local` / `s3`（COS、OSS、MinIO、AWS 都走 S3 协议） | `local` |
| `endpoint` | 例 `https://cos.ap-guangzhou.myqcloud.com`、`https://oss-cn-hangzhou.aliyuncs.com` | — |
| `bucket` / `region` | 桶名；部分厂商 region 必填 | — |
| `accessKey` / `secretKey` | 脱敏回显（与 ES/Qdrant 同口径） | — |
| `prefix` | 对象键前缀，默认 `domainplane/`；多环境共桶靠它隔离 | — |
| `pathStyle` | MinIO/私有化常要开（`endpoint/bucket` vs `bucket.endpoint`） | — |
| `rootDir` | 本地盘专用路径 | ✓ |
| `publicBaseUrl` | 可选：为"下载原文"生成带签名临时链接 | — |

**只做一套 S3 驱动**，不为 COS/OSS 各写一个：两者都兼容 S3 协议，差异集中在 endpoint 与
极少数 header。这条写进文档，免得以后有人来加三个 `*Store`。

每类连接都要能「测试连通」：ES `GET /`、Qdrant `GET /collections`、
原文 `HEAD bucket` + `LIST prefix`。

## 8. 检索与缓存

```
域解析：域链（本域 + 祖先）→ 每域读 bodies[] → 并集按体 id 去重 → 体列表
每个体：三路落点 → 关键字连接 / 向量连接 → 体的 index
召回：每体两路并行召回 → 融合 → 按 (bodyId, docId, seq) 去重
```

- 「祖先域的知识也查」行为保留，单位从"域的索引"变成"知识体"；同一体被父子域同时绑定 →
  按体 id 去重，只查一次（今天是查各自索引，天然不重复，但也因此无法共用）；
- 未绑任何体 → 知识通道为空，`searchKnowledge` 不进入装配（与今天一致）；
- 缓存键 `(bodyId, index)` → 检索器；换落点/重建/删体/绑定变更时按体 `evict`
  （今天的 `domainChannelProvider.evict(indices)` 是域粒度，改体粒度）。

## 9. 统计、健康与快照

- 统计单位：`byBody`（文档/切片/字节）、`byDomain`（本域链可见文档数，按体去重）、
  `byConnection`（体数/用量）；
- 60s TTL + 失败冷却沿用；上传/删档/删体/绑定的变更都 `invalidate()`；
- 健康新增 `raw` 一路：落点可达 + 每体"有档文档数 / 总文档数"的欠账；
- **一致性权威**：知识体登记表。判断"这个 index 还该不该有原文"看体在不在，
  不看 collection 在不在（§12）。

## 12. 对账：权威源必须换（"保留数据"的前置）

`ChunkArchiveReconciler` 今天的判据是「collection 不在 → 档案是孤儿 → 删」。一旦允许保留
知识数据，这条就是潜在的数据销毁器：索引误删、迁移中断、连接临时指错，都会在 5 分钟内把
原文清掉。

```
权威：bodies.json 里活体的 index 集合
遍历：档案 inventory 的每个 index
  属于活体   → 正常；若 collection 缺失 → 只记 WARN + 计数（"体缺索引"），不删
  不属于任何体 → 才算孤儿；要求 "超过 minAge + 连续 N 轮" 才删（今天只有 minAge）
新增：files 与 chunks 交叉校验（有档无切片 = 半截写入，可重建）
```

「体缺索引」要成为页面上的一类状态（§5.2），不是日志里的一条 WARN。

## 13. 迁移方案（零拷贝 + 幂等）

1. **启动时一次性登记**（`KnowledgeBodyMigrator`，幂等可重跑）：
   - 枚举全部 `domainplane_kb_*`；
   - 对每个 index：用 `KbIndexes.nameOf(domain)` 反查是哪个域；
   - **每个旧索引登记为一个知识体**（一个域一个体，零拷贝）：`{id: kb_<索引哈希前 8>, slug: 由域路径安全化, name: 域路径可读名, index: 现名, routes: {keyword/vector: 该域现在绑的体的两槽, raw: 本地盘}}`；
   - 域声明改为 `bodies:[该体]`（保留 `body` 一个版本）；
   - 无对应域的 index → 留作"无主集合"，由运维区认领。
2. **检索切换**：改为"域 → 体 → index"，与迁移前一致（1:1），零行为变化。
3. **删域改造**上线：先只解绑。
4. **页面切换**：先上体卡片与未绑定区，再撤三张卡（避免"旧入口点进去 410"）。
5. **原文双份**：新上传开始写原始字节；存量补写只能"没有"（切片 JSON 还原不出原始字节），
   页面标注「无原始文件」。
6. **原文后端**：先上 `local` + `s3`；存量体继续指向本地盘，按需在卡片上迁移。
7. **合并知识体**（可选整理）：迁移后按域各一个体，同一业务想合并时用运维区「合并知识体」
   （从原文重灌到目标体），完成后源体 `keepRaw` 处理。

回滚：`body` 字段保留一个版本、旧页面文件保留一个版本；`bodies.json` 可被旧代码忽略
（旧代码继续读 `infra-settings.bodies`，迁移器写入时同步保留一份只读快照）。

## 14. 风险与取舍

| 风险 / 取舍 | 说明 | 处置 |
| --- | --- | --- |
| collection-per-body 上限 | 单后端几百个集合后 ES 状态与 Qdrant 内存压力上升 | 诊断区显示每连接体数；超阈值提示"拆到另一连接" |
| 域绑多个体 | 召回 fan-out 变多，延迟随体数上升 | v1 上限 4；超出提示"合并知识体" |
| 原文双份占用 | 切片 JSON + 原始字节 ≈ 2× | 新体默认开、体内可关（决策点 D3） |
| 未绑定体占资源 | 删域保留会累积 | 不自动删；KPI 显示未绑定体数与容量；30 天未绑定只提醒 |
| 名字唯一约束 | 改名撞名被拒 | 提示"已有同名知识体"，给 `slug` 后缀建议 |
| slug 与索引不一致 | 改 slug 后索引名仍是旧 slug | 卡片上标注"索引名不变（创建时生成）"，避免误解 |
| S3 兼容性差异 | COS/OSS/MinIO 签名细节 | 单驱动 + MinIO 集成测试；字段留 `extraHeaders`（不启用） |
| 旧 API 兼容期 | 脚本/外部集成用 `/kb/documents` | 映射默认体，Deprecated 两个版本 |
| 迁移中断 | 换落点搬一半 | "新集合建好再切指针"；旧集合保留到显式清理；原文"先搬后切" |
| 权限 | 删体是全局破坏性动作 | 需输名；审计记录 `keepRaw` 选择 |

## 15. 分阶段落地

| 阶段 | 内容 | 规模估算 | 完成标志（可验收） |
| --- | --- | --- | --- |
| **P0 身份与解绑** | `bodies.json` 抽取 + 迁移器（零拷贝登记）+ 检索按体解析 + 删域只解绑 + `retainedBodies` + 未绑定区（只读）+ 对账权威改造 | 4–6 天 | 删域后体仍在、文档数不变；新建不同名域绑定旧体能检索到；对账不再删保留的原文 |
| **P1 体级读写** | 体 CRUD（唯一名/冻结索引）+ 体内上传/删档/文档表 + 切片预览按体 + `/kb/*` 降级为默认体兼容 | 4–6 天 | 一个体被两个域绑定后，两域检索到同一批文档（共用真正生效） |
| **P2 页面重做** | 新知识库页 + 体抽屉（文档/健康/设置）+ 撤三张卡 + 域页多体绑定与瘦身 + 删域文案 | 4–6 天 | 日常动线「建体 → 传文档 → 绑域 → 检索」全程在知识库页；域页只剩绑定 |
| **P3 重建与换落点** | 体级 rebuild（从原文）+ `PUT /routes`（三路各自迁移，进度/暂停/遗留清理）+ 健康三方对照 | 4–6 天 | 换向量模型点"重算向量"不重传；换关键字连接在卡片上完成，索引名不变 |
| **P4 原文落点** | 连接加 `raw`（local/s3）+ `S3BlobStore` + 卡片上选原文落点 + 原文迁移（先搬后切）+ 原始字节归档 | 5–7 天 | 新体原文落 COS；换原文落点后从 COS 重算向量；本地零副本 |
| **P5 运维区** | 诊断、无主集合认领、遗留清理、合并知识体、容量汇总 | 3–4 天 | 运维不再靠 curl 猜索引名 |

P0 必须"体身份 + 删域改造"一次做完：只改删除而不引入体身份，得到的是"同路径域重建时
旧数据静默复活、且没有任何入口看得见它"——正是今天 `deleteIndices` 注释里警告的坑换个方向踩。

## 16. 需要拍板的决策

| # | 决策 | 推荐 | 影响 |
| --- | --- | --- | --- |
| D1 | 知识体是否就是数据实体（不再引入"知识库/存储组"第二层） | **是**（本稿已按此设计） | 若仍想要两层，本稿 §2/§5/§10 需要恢复一层 |
| D2 | 域能绑几个体 | **0..n，v1 上限 4** | 单选简单，但"多来源"是真实需求；多选让去重与延迟成为要盯的点 |
| D3 | 是否归档原始文件字节 | **新体默认开，体内可关** | 磁盘翻倍；换来可重切/可下载/迁移字节级校验 |
| D4 | 名字唯一性 | **强制唯一（slug 层）**，改名也校验 | 不唯一会让选择器出现两个同名项、共用时更难指认 |
| D5 | 旧 `/admin/kb/*` 兼容期 | **保留 2 个版本，映射默认体** | 直接 410 最干净，但会打掉脚本与外部集成 |
| D6 | 删域是否支持"顺带删体" | **不支持**（删体必须显式且输名） | 支持会回到"一个动作毁两样东西"的老问题 |

## 17. 验收场景（逐条可测）

1. 体 `products` 有 8 文档 → 删域 → 体出现在「未绑定」，文档 8、切片 96 不变；新建不同名域绑定该体 → 检索命中，无需重传。
2. 体 `products` 绑域 `a`、`b` → 两域检索都命中同一批文档且结果不重复（共用生效）。
3. 改名 `products` → `goods`：卡片显示"索引不变"，检索与文档计数不受影响；再建一个 `products` 被拒（唯一校验）。
4. 删体 `keepRaw=true` → 集合消失、原文在；运维区显示"无主原文"，可「从原文重建体」。
5. 换向量模型 → 体状态「维度不符」→ 点「从原文重算向量」→ 恢复就绪；关键字索引与文档不动。
6. 换关键字连接 es-text01 → es-text02 → 卡片上完成迁移，索引名不变；旧集合标"遗留"待清理。
7. 换原文落点 本地盘 → COS：先搬后切，校验通过才切；切换后上传落 COS，重算向量从 COS 读。
8. 删域时 ES 不可达 → 解绑成功、域删除成功（今天会被拒）。
9. 删域后对账连跑 3 轮 → 保留体的原文档案一条不少（P0 核心断言）。
10. 旧脚本 `POST /admin/kb/documents` → 仍能上传到默认体，响应带 `deprecated` 提示。
11. 体缺向量集合 → 页面显示「部分损坏」，修复动作可点，不显示「就绪」。
