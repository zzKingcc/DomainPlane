# TXT 入库：清洗与切片设计

> 本文只描述 `.txt` 这一条管线。格式扩展点是 `DocumentProcessStrategyFactory` 与各策略实现本身：md / docx / doc / pdf / excel 已按同一接口新增实现，规则见 [`MULTI-FORMAT-INGESTION-DESIGN.md`](MULTI-FORMAT-INGESTION-DESIGN.md)。
>
> **状态：已落地**（`ingestion/txt/`：`TxtSplitter` / `TxtNormalizer` / `TxtCleaner` / `OutlineReader` / `Chunker`），回归样例见 `TxtSplitterTest`。

## 一句话

txt 入库只做四件事：**统一字符集 → 删噪声行 → 认标题 → 按句子切片**。切片长度是"预算"，切点永远落在标题或句子上。

```
txt 字节
 ├─ 1 统一字符集       TxtNormalizer   探测编码 → 一律转成 UTF-8，统一换行、去行尾空白
 ├─ 2 清洗             TxtCleaner      删页眉页脚 / 页码 / 分隔线，压空行
 ├─ 3 认标题           OutlineReader   哪些行是标题、当前在哪个标题下
 └─ 4 切片             Chunker         按句子打包，相邻切片重叠 1 句
→ TextSegment[]（text + metadata）→ 既有链路：去重 → 向量化 → 写索引
```

入口是 `TxtSplitter`（实现 `DocumentSplitter`），串起上面四步；第 4 步之后的去重、向量化、写索引完全沿用现有代码。

## 一份示例走完全程

左边是原始 txt，右边是最终切出来的东西。带删除线的行在清洗阶段被删掉。

```
会员服务手册                      ✗ 页眉（与末行重复）
第 1 页                          ✗ 页码
```

| # | section_path | 正文 |
|---|---|---|
| 1 | `第一章 会员规则 > 一、注册` | 会员注册需提供手机号。注册后即生效。 |
| 2 | `第一章 会员规则 > （一）实名` | 实名认证需上传身份证，48 小时内审核。2024 年新增实名用户 12800 人。 |
| 3 | `第一章 会员规则 > 二、退换货` | 退货运费由谁承担，视商品而定。 |

## 第 1 步 统一字符集、规范化（`TxtNormalizer`）

**目标：不管上传的文件是什么编码，入库后全系统只有 UTF-8。** 转码只在这一步做一次 —— 后面的清洗、切片、写索引、导出，全都不再关心编码。

1. **探测编码**（顺序固定，不做多编码并存）：
   - 有 BOM → 按 BOM 读（UTF-8 / UTF-16）；
   - 没有 BOM → 先按**严格 UTF-8** 试，失败就按 **GB18030** 读。中文存量 txt 里有大量 GBK 文件，硬按 UTF-8 读会得到乱码知识 —— 那比直接报错更糟；
   - 两条都不成立 → **拒绝该文件**并报「无法判定编码」，不猜、不静默。
2. **转成 UTF-8**，作为内部唯一字符集往后传。实际识别的编码写进上传返回值（`encoding`）。
3. 换行统一成 `\n`，去掉行尾空格，**保留行首缩进**（后面判段落形态要用）。
4. 删掉控制字符（`\u0000` 一类），但**保留 `\f`** —— 下一步要靠它找跨页重复行。

## 第 2 步 清洗（`TxtCleaner`）

原则：**只删能确定是噪声的行，宁少勿多。** 删掉一行正文的代价，远大于留下一行噪声。

| 删什么 | 判据 | 为什么安全 |
|---|---|---|
| 页码 | 整行是 `第 X 页`、`Page X of Y`、`- X -`、纯数字 | 例外：`第 X 条 / 章 / 节 / 款` 是正文条款，**不删** |
| 跨页重复的短行 | **短于 40 字 + 不以句末标点结尾 + 不是标题形态**，且出现次数达标：有 `\f` 时只统计「每页前 2 行 / 后 2 行」，门槛 = `max(2, 页数一半)`；无 `\f` 时全文 ≥ 2 次 | 页眉页脚天然重复且是标签不是句子；三个护栏保证只删确定是噪声的 |
| 纯符号行 | 只由 `-=*_~#^` 组成且长度 ≥ 3 | 分隔线没有信息 |
| 连续重复行 | 同一行连着出现 ≥ 2 次且短于 40 字 | 排版噪声 |

两条注意事项：

- **纯数字行不能无条件删**。孤立的 `12800` 很可能是正文数据，所以纯数字行只在「同一内容出现过 2 次」或「上一行是标题、下一行是空行」时才删。
- 服务端是无人值守的批量上传，**没有"人工确认"这一步** —— 所以只删能确定的。需要人眼核对的抽样，看上传完自动导出的切片预览文件（见「怎么验证」）。

删掉的行数写进日志和上传返回值（不用看明细也能发现异常）；其余一律保留。最后把连续空行压成一个。

## 第 3 步 认标题（`OutlineReader`）

标题 = 命中下面任一形态 **且** 行长 ≤ 40 字 **且** 不以句末标点结尾。

| 形态 | 例子 |
|---|---|
| 章 | `第一章 会员规则`、`第 2 节 参数配置` |
| 中文序号 | `一、注册` |
| 括号序号 | `（一）实名`、`(1) 条件` |
| 数字编号 | `1. 注册条件`、`1.2 参数配置` |
| 方括号 | `【注意】` |
| 字母序号 | `A. 安装` |

**数字编号必须带分隔符（`.` `、` `．`）才算标题** —— 这是全场最重要的一条。如果只要求"数字开头"，`2024 年新增实名用户 12800 人。` 会被当成标题，把正文切碎。代价是 `1 注册条件`（数字后只有空格）会漏判，这是刻意接受的：漏一个标题的影响远小于误切正文。

**层级只分两级**：`第 X 章 / 节 / 部分` 是第一级，其余全是第二级。纯文本里编号常常混着用（一会儿 `一、`、一会儿 `（一）`、一会儿 `1.1`），往下猜第三、第四级必然出错。

维护一个路径栈：遇到第一级标题就重置下层，遇到第二级标题就替换第二层。得到的路径形如 `第一章 会员规则 > 一、注册`。

完全没有标题的文档不做特殊处理：整篇算一个 section，路径取文件名。

## 第 4 步 切片（`Chunker`）

```
顺着内容往下走：
  遇到标题      → 更新路径，开新切片（不跨标题合并）
  遇到正文      → 切成句子，累加到 400 字就输出一片
  输出下一片时  → 重复上一片的最后 1 句，作为重叠
  最后一片太短  → 并进前一片
```

**400 是上限，不是目标长度。** 切片尽量填满，但下面几种情况会提前结束：

- **撞到标题** → 立刻断开。一个 section 只有 3 句话，就切出 3 句话的片子（可能 80 字）。**结构边界优先于长度**，不跨标题拼接。
- **整个 section 不到 400 字** → 就一片，长度 = 实际字数。
- **文档本身就很短**（比如 20 字）→ 一片，20 字。`min-chars` 只在"前面有片可并"时才合并，**第一篇不丢**。

所以实际长度是「**≤ 400，常见 200~400**」，短文档天然出短片。想强行凑到 400 只能跨标题拼，反而让模型看不出层级。

**怎么切句子**：在 `。！？；` 和换行处切。英文的 `.!?;` 只在后面跟空格或位于行尾时才算终止符 —— 否则 `1.5`、`v1.0-beta.1`、`api.example.com` 会被切坏。`：` 和 `，` 不作为切点。

**兜底**：如果单独一句就超过 400 字（一段没有标点的长文本），先在 `，` `：` 处找断点，再不行才硬切。正常文档不该走到这一步。

## 切片元数据

| 字段 | 例子 | 用途 |
|---|---|---|
| `text` | `第一章 会员规则 > 一、注册` + 空行 + 正文 | 给模型看的文本；同时喂 BM25 与向量，两条召回通道吃的是同一份内容 |
| `metadata.section_path` | `第一章 会员规则 > 一、注册` | BM25 单独加权、预览展示 |
| `metadata.section_title` | `一、注册` | 末级标题 |
| `metadata.chunk_seq` / `chunk_total` | `2` / `3` | 预览显示「2/3」；将来做上下文回捞 |
| `metadata.content_hash` | `SHA256(text)` | 去重。**只算切片正文、不含文件名** —— 这样改了文件名重传也不会重复入库 |
| 其余 | `doc_id` / `file_name` / `upload_time` / `domain` | 与现状一致 |

ES mapping 要跟着补：`metadata` 加 `dynamic: false`，上面这些字段**全部显式声明**。顺带修一个现有问题：`metadata.doc_id` 现在没声明，被动态映射成了 `text`，而删除/统计用的是 `term(metadata.doc_id)` 查询 —— 很可能根本查不到。

另外 `text` 挂一个 `text.standard` 子字段（standard 分词器）：ik 会把英文词、数字、订单号切碎，标准分词器留一条退路。BM25 查询侧按 `text^1.0` / `text.standard^0.8` / `metadata.section_path^1.5` / `metadata.section_title^2.0` 加权。

> ⚠️ mapping 是**建索引时定型**的，存量索引不会自动长出新增的字段/子字段。老索引必须重建后重新上传 —— 否则新查询里那几个字段命中恒为空（`multi_match` 对未映射字段静默跳过，不报错）。

## 配置

只留三项可调，其余全部写死在代码里（改就重新构建）。

| 配置 | 默认 | 说明 |
|---|---|---|
| `domainplane.rag.chunking.max-chars` | 400 | 单切片**长度上限**（不是固定长度）。400 个中文字约合 400 token，对上限 512 token 的向量模型也安全 |
| `domainplane.rag.chunking.overlap-sentences` | 1 | 相邻切片重叠几句 |
| `domainplane.rag.chunking.min-chars` | 60 | 尾片短于该值就并进前一片 |

写死的常量：页码正则与白名单、跨页重复阈值（≥ 页数一半 / ≥ 3 次）、页眉页脚候选行长 < 40、标题行长 ≤ 40、标题层级两级、空行压缩阈值。

导出目录是**存储位置**（`domainplane.export.path`），与配置 / 日志目录同级，不算切片参数 —— 见「怎么验证」。

## 怎么验证

1. **上传返回值**：`chunks`（切片数）、`sections`（标题数）、`dropped`（删了几行）、`encoding`（实际识别的编码）。删行明细进日志。
2. **切片预览 = 导出一个 txt 文件**（不做在线查看、不做抽屉）：
   - 上传完成后，把该文档的全部切片写成 `<原文件名>.<docId 前 8 位>.chunks.txt`，内容 = 头部信息（文件名 / docId / 域 / 切片数 / 导出时间）+ 逐片「序号 + `section_path` + 正文」，**UTF-8** 编码。
   - 目录是**固定位置**，与配置 / 日志目录同级：Windows `%ProgramData%\DomainPlane\chunks`、Linux `/var/lib/domainplane/chunks`，可用 `DOMAINPLANE_EXPORT_PATH` 覆盖。
   - **导出的是索引里真正入库的切片**（按 `chunk_seq` 排序），不是重切一遍 —— 所见即所存。
   - 覆盖重传或删除文档时，同步删掉旧的导出文件。
   - 管控台文档列表**只显示这个文件路径**（可复制），点不点得开由用户自己决定。
3. **单测样例**（固定进代码防回归）：
   - 规范编号文档 → 路径与切片数正确
   - 无空行的整段长文本 → 按句子切，不拦腰截断
   - 含页码 / 页眉 / 分隔线 → 全部删掉，且 `2024 年…` 不被当标题
   - GBK 编码文件 → 转成 UTF-8 正常读出，无乱码
   - 两种编码都判不出的文件 → 拒绝并报错，不入库

## 父子块

**要解决的问题**：小块检索准（向量在小范围更聚焦），但喂给模型时上下文不全；大块上下文全，但检索不准。父子块的做法是「小块检索、大块喂模型」—— 子块命中后把它的父块（整个小节）一起交出去。

**当前不做真父子块**，代价是：要么多存一份父块（索引体积翻倍），要么命中后再回捞（多一次查询）。txt 结构清楚，`section_path` 已经写进 `text` 里，模型看得到"这段话在第几章第几节"。

**替代方案：邻接扩展。** 切片自带 `section_path` / `chunk_seq` / `chunk_total`，命中切片后按「`section_path` 相同 且 `chunk_seq ± 1`」回捞邻居，拼进上下文再喂模型。**只改检索后处理，不动索引、不重灌数据。**

真父子块（新增 `parent_id`、写入时按小节聚合父块）等邻接扩展不够用时再做。

## 不做

- **不做语义切分**（按 embedding 相似度找边界）：每次导入多一轮 embedding 调用、结果不可复现、出问题难排查；结构和句子规则已经够用。
- **不判表格和代码块**：txt 里只能靠猜，收益低。
- **不做父子块**：见上一节「父子块」——用 `chunk_seq ± 1` 邻接扩展替代。
- **不落盘原始文件**：只落盘切片预览 txt（见「怎么验证」），原始上传文件不留 —— 溯源靠 docId + 切片序号 + 日志。
- **不用 OpenNLP 英文句模型**：现有兜底链的句子层是英文模型、词层按空格切，对中文基本失效，最后退化成按字符硬切。
