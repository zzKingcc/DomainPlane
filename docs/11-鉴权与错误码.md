# 鉴权与错误码

两块内容：**凭证怎么发、怎么验、失效条件是什么**；**错误码怎么分段、两套文案怎么用、什么该重试**。

---

## 1. 凭证：无状态 HMAC

```
payload   = {"sub":"domainplane","iat":1730000000}
signature = Base64URL(HMAC-SHA256(payload, derivedKey))     // 无填充
token     = payload + "." + signature
```

派生密钥不是固定的主密钥，而是按账号算出来的：

```
derivedKey = HMAC-SHA256(masterKey, passwordHash)
masterKey  = 32 字节随机，落盘在 accounts.json
```

这条链带来三个性质：

| 性质 | 机制 | 后果 |
| --- | --- | --- |
| 无状态 | 服务端不存 session，验签即通过 | 多进程共享同一份 `accounts.json` 就能互认 |
| 改密即全端失效 | `passwordHash` 变了 → `derivedKey` 变 → 旧签名全废 | 不需要"踢下线"接口 |
| 无 TTL | payload 里只有 `iat`，不校验过期 | 凭证长期有效，退出登录只清客户端 |

"无 TTL"是取舍不是遗漏：加过期就要加刷新，而刷新需要服务端状态，与"单实例、无会话表"的整体设计冲突。代价是凭证泄露后只能靠改密码收场。

## 2. 两种载体，两套范围

| 载体 | 头 / 名 | 覆盖路径 | 谁在用 |
| --- | --- | --- | --- |
| Header | `X-DomainPlane-Credential` | `/api/agent/**`（除 `/api/agent/login`） | SDK、脚本、工具实例 |
| Cookie | `domainplane_admin`（HttpOnly, SameSite=Lax） | `/admin/**` | 管控台页面 |

拦截器是同一个（`CredentialAuthInterceptor`），按路径挂两次。`/admin/**` 的规则是 Cookie 优先、Header 回退——所以 SDK 用 Header 调 `/admin/kb/**` 也能过，知识库 SDK 就是靠这个走通。

### 放行白名单

```
# /api/agent/**（除 /api/agent/login）
/api/agent/login

# /admin/** 免检
/admin/login              /admin/init           /admin/session
/admin.html               /login.html           /console/**
/favicon.ico              /error
```

跨域预检（`OPTIONS`）在拦截器里无条件放行；跨域本身默认全关，需要时用 `domainplane.cors.allowed-origins`（逗号分隔完整来源）显式开启，`allowCredentials=true` 因此不能配通配来源。

未初始化时进一步收窄：**只放行 `/api/agent/health`**。避免"服务起来了但什么都调不动，又看不出为什么"——这时唯一的合法动作是打开管控台完成初始化。

账号文件**曾经可读、运行期读不到**（被删 / 卷卸载 / 权限变更）是另一档：全站返回 `10007 AUTH_STORE_CORRUPTED`，不按"未初始化"放行。否则初始化入口免检，等于允许任何人在此状态下重建管理员账号。

### 首次初始化

`POST /admin/init` 在账号文件不存在时免鉴权，所以默认**只允许本机**（回环地址；带 `X-Forwarded-For` 时取首跳判断）。

要远程初始化必须显式打开 `domainplane.auth.allow-remote-init=true`。这个开关不要常开——它等于"谁先到谁当管理员"。

## 3. 默认口令的限制范围

默认口令（`domainplane` / `domainplane`）下会被拒的是：**Cookie 载体的、非 `GET/HEAD/OPTIONS` 的、除 `/admin/password` 以外的请求**。

| 请求 | 结果 |
| --- | --- |
| 页面浏览（GET） | 放行 |
| 页面内的写操作（POST/PUT/DELETE） | `10008 AUTH_DEFAULT_CREDENTIAL` |
| `POST /admin/password` | 放行（否则改不了密码） |
| SDK 用 Header 调的接口 | 不受限 |

最后一行不是漏洞，是有意的：限制的目的是"逼管理员改密"，而 SDK 是业务侧调用，与管理员口令状态无关。

## 4. 错误码：61 条，十一段

| 段 | 含义 | 条数 | 码值 |
| --- | --- | --- | --- |
| 0 | 成功 | 1 | `0` |
| 10xxx | 权限 / 鉴权 / 域 | 13 | 10000–10012 |
| 20xxx | 限流与容量 | 4 | 20000–20003 |
| 30xxx | 编排与会话 | 5 | 30000–30004 |
| 40xxx | 客户端 / 入参 | 8 | 40000–40006、40400 |
| 50xxx | 系统 | 2 | 50000–50001 |
| 60xxx | 知识库 | 10 | 60000–60009 |
| 70xxx | 记忆 / 检查点 | 5 | 70000–70004 |
| 80xxx | 工具 | 4 | 80000–80003 |
| 90xxx | 模型 / 外部依赖 | 7 | 90000、90003–90008 |
| 91xxx | 多模态端点 | 2 | 91000–91001 |

客户端另有一套 `95xxx`（`ClientErrorCode`，95000–95009），只在 SDK 内部用，不来自服务端。

1 + 13 + 4 + 5 + 8 + 2 + 10 + 5 + 4 + 7 + 2 = 61 条（含 `OK(0)`），与枚举 `values()` 一致。

上表按**枚举定义**计数，不等于"对外可能出现的码"。已确认无任何 main 抛点（或只在测试里构造）的死码：

| 码 | 说明 |
| --- | --- |
| `30004 SESSION_MEMORY_FULL` | 记忆封顶语义移除后失去意义（见 05 篇） |
| `60008 KNOWLEDGE_STORE_UNAVAILABLE` | 存储故障一律走 `60000` |
| `60001 KNOWLEDGE_SEARCH_ERROR` | 检索链路故障也走 `60000` |
| `10009 DOMAIN_REQUIRED` | 没有"必须显式指定 domain"的分支 |
| `70000 CHAT_MEMORY_ERROR` | 记忆故障细分到 70001/70002/70003 |
| `20000 RATE_LIMITED`、`20003 CONCURRENT_LIMIT` | 限流与"并发会话上限"都未实现；容量饱和只有一个出口 `20002` |
| `80000 TOOL_ERROR`、`80002 TOOL_DUPLICATE`、`80003 TOOL_EXECUTION_FAILED` | 工具失败以"失败结果回给模型"呈现，不走 ErrorCode（`80001 TOOL_NOT_FOUND` 只取文案拼进失败结果，也不作为码抛出） |

## 5. 两套文案，别混用

每个码带五样东西：`code`、`message`、`userMessage`、`httpStatus`、`retryable`（外加一个给文档用的 `action`）。

| 文案 | 给谁 | 允许写什么 |
| --- | --- | --- |
| `message` | 运维 / 日志 | 可以有内部术语（"图检查点"里的"图"指编排状态图） |
| `userMessage` | 终端用户 | 只说"发生了什么 + 你能做什么"，不含实现细节 |

对外出口一律取 `userMessage`：

- SSE 的 `ERROR` 帧
- HTTP 响应体的 `error` 字段

反面例子就在代码注释里：`90005` 的抛出点 message 写的是"请先在管控台××页填写"——那是给管理员的路标，终端用户够不着。所以事件体只出"服务暂未就绪，请联系管理员或稍后再试"，具体缺什么写进日志。

例外是知识库上传的两个码（`60002` / `60009`）：它们只从文档上传出口出现（管控台与 KB SDK），不进 SSE 对话链路，读它的人就是能去改配置的管理员——所以对外文案可以直接点名"向量模型 / 存储配置"和该去哪一页。这里写含糊了代价很具体：`60002` 曾经的对外文案是"文档没能导入，请换一种格式或稍后重试"，现场把它读成了"文件格式不对"，而真因是没配向量模型。

`70004` 的对外文案刻意不提"图"：这个"图"是 langgraph4j 的状态图，在带图片的会话里写"图检查点失败"必然被读成"图片坏了"。

## 6. `retryable` 怎么用

| 值 | 调用方该做什么 | 典型码 |
| --- | --- | --- |
| `true` | 退避后重试 | 20002、70004、90000、90003 |
| `false` | 直接提示，不要重发 | 上游明确拒绝的三类（90006/90007/90008）、参数错、域不可用 |

这条字段是有教训的：早期上游欠费/鉴权失败全被塌进 `ORCHESTRATION_FAILED`（可重试），前端会无意义地反复重发同一个必然失败的请求，而真因（如 `Insufficient Balance`）被通用文案盖掉。现在由 `UpstreamLlmFailure` 按上游异常类型 + 原文语义定性，认不出来才退回通用码。

不可重试的几类会把上游原文带进事件体（"（上游：Insufficient Balance）"）；可重试的不带，因为上游原文多是英文网络措辞，不如码的对外文案好用。

## 7. 客户端码（95000 段）

| 码 | 枚举名 | 含义 |
| --- | --- | --- |
| 95000 | `UNEXPECTED` | 未归类的客户端失败（兜底，文案带排障细节） |
| 95001 | `CONNECTION_REFUSED` | 连不上：地址/端口错、服务没起、DNS 解析失败 |
| 95002 | `TIMEOUT` | 等不到响应：读超时、网关挂起 |
| 95003 | `CREDENTIAL_REJECTED` | 凭证被拒：账号密码错、密码改过、凭证过期 |
| 95004 | `SERVER_NOT_INITIALIZED` | 服务端账号尚未初始化（登录回 409） |
| 95005 | `ACCESS_DENIED` | 被访问控制挡下（登录或调用回 403） |
| 95006 | `RESPONSE_UNREADABLE` | 响应读不出来：空响应、结构对不上、字段解析失败 |
| 95007 | `STREAM_TRUNCATED` | 事件流在终止事件前结束——答案是半截，不能当成功交付 |
| 95008 | `INVALID_ARGUMENT` | 调用方参数不合法，发请求之前就被拦下 |
| 95009 | `SERVER_REJECTED` | 服务端回了业务错误，具体码/文案挂在 `ServerRejectedException` 上 |

SDK 的翻译规则：响应体 `code != 0` → `ServerRejectedException`（原样保留服务端码/文案/retryable，不二次包装）；HTTP 401/403 → `CREDENTIAL_REJECTED`；HTTP 409（登录）→ `SERVER_NOT_INITIALIZED`；超时/连接失败 → 对应码。

**没有自动重试，也没有同调用内重登。** 凭证按需换取并进程内缓存，`invalidate()` 只是把缓存清空、由下一次业务调用的 `get()` 重新登录——当前 main 里除定义本身外没有 `invalidate()` 调用点。重试策略留给调用方，因为平台不知道这次调用是否幂等。

## 8. 边界

- 凭证无过期、无刷新、无吊销列表。改密是唯一吊销手段。
- 没有登录限流。错误口令可以无限尝试。
- 工具实例的 `/domainplane/invoke` 不做鉴权（内网假设）。
- 管控台 Cookie 不设 `Max-Age`，是**会话级**：关掉浏览器即失效。但凭证本身无 TTL，所以"关浏览器"只是丢 Cookie，不代表凭证作废——拿到同一张凭证头依然能通过校验。
