# DomainPlane 管控台 · 工程化修补方案

> 定位：**不换栈、不动后端的原地工程化**。前几轮调研结论（amis / HTMX / Vaadin / JeecgBoot、中间件控制台四大家族）指向同一个判断——管控台现状属于「服务端直出」家族，与 XXL-Job、Kafdrop、RabbitMQ Management 同族，是被时间验证的活法；RocketMQ 重写控制台的触发点是 AI 功能与复杂交互，不是页面多。本方案只修补这一族的工程化欠账。
>
> **v2 修订（2026-10-19 二稿）**：补齐 P0 产出物与每阶段 done 定义；信封形态由「两套」修正为「三类 + 裸对象」（2.1 附实测表）；TypeScript 从「半吊子渐进」改为明确结论；产物改由 Maven 构建、不入 git；P4 补 Spring Boot 3 的实际配置方式；估时加止损点。
>
> **v3 修订（2026-10-19 三稿）**：确定视觉方案采用 **Tabler UI Kit 1.6.1**，新增独立的 **V 轨（第 9 章）**，与 P 轨正交、不混同一次提交。五不动的第 5 条相应松绑为「视觉替换只走 V 轨」。V 轨包含准入检查（浏览器下限）、命名冲突审计、token 换皮、按组件替换四步。

## 1. 目标与边界

**要做**：把「裸静态三件套」升级为「有构建、有模块边界、有 lint、有冒烟回归」的静态前端工程，Java 侧零改动。

**五不动**：

1. 不动后端接口与响应信封（P2 只收敛前端判断，不动 Controller）
2. 不动 `CredentialAuthInterceptor`（`/admin/**` Cookie 拦截，excludes `login/init/session` + 静态资源）
3. 不动同源策略（凭证是 HttpOnly Cookie，CORS 默认全关是有意设计）
4. 不动部署形态（静态资源仍由 Spring Boot 从 classpath 提供，`mvn package` 直接出包）
5. ~~不动页面 DOM 结构与 `console.css` 视觉~~ → **视觉替换改走 V 轨（第 9 章）**。P 轨（工程化）仍然不动 DOM 与视觉；V 轨单独承担样式接入，两条轨道的提交不混在一起

## 2. 现状盘点（2026-10-19 实测）

| 层 | 文件 | 行数 | 角色 |
|---|---|---|---|
| 共享库 | `static/console/assets/console.js` | 307 | IIFE 零依赖：`request/jsonRequest/escapeHtml/sanitizeError/renderSidebar/ready/guardAuth/refreshModelsWarn` |
| 样式 | `static/console/assets/console.css` | 680 | CSS 变量驱动，手写 |
| 页面 | `models.html` | 1770 | 内联 `<script>`，全局 `Console.*` |
| | `mcp.html` / `infra.html` / `domains.html` | 553 / 516 / 708 | 同上 |
| | `prompts/instances/knowledge/account/login/overview` | 301/290/249/135/180/124 | 同上 |
| | `static/admin.html` | 12 | 跳转入口 |

合计约 5300 行，全部内联脚本、ES5 风格、无构建无 lint 无测试。

**已有的好底子**（修补的地基，不是重写的理由）：`sanitizeError` 凭据清洗、登录守卫去重（`sessionPromise` 共享）、跨源访问警告、侧栏单点渲染（`NAV` 数组）。

**实测发现的四个真问题**：

1. **内联脚本不可维护**：`models.html` 单文件 1770 行，改一行要全文翻；页面逻辑无法被 lint / 单测 / 静态检查覆盖
2. **信封形态有三类，不是两类**（详见 2.1）：`code` 类判断 22 处、`success` 类判断 7 处，散在 6 个文件里；同一份 `console.js` 罩不住，每个新页面都要重新发明一次错误处理
3. **部分页面根本不判成功**：`instances.html:257` 拿到响应直接 `alert(r.message)`，成功与失败的唯一区别是文案——后端返回 `success:false` 时页面照样走成功分支
4. **无回归网**：12 个页面 + 登录态守卫 + 侧栏提示点，全凭手点；共享库 `console.js` 一改，影响面无法评估

### 2.1 信封形态实测表（P2 的前置事实，已核对后端）

| 形态 | 标识键 | 代表性接口 | 后端出处 | 前端现状 |
|---|---|---|---|---|
| **A · 纯 `code`** | `code:0` 成功 / 非 0 失败，常配 `error`/`detail` | `/admin/domains/{id}/tool-call-echo`、`/admin/provider-presets`、`/admin/mcp-connections/{name}/tools` | `AdminDomainController:329`、`AdminProviderPresetController:41`、`AdminMcpController:108` | `r && r.code && r.code !== 0` |
| **B · `code` + `success` 双写** | 两个键都给 | `/admin/kb/documents`、`/admin/kb/rebuild`、`/admin/model-profiles/{tuning,return-thinking,context-window}`、`/admin/provider-connections`、`/admin/mcp-connections` | `AdminController:903,925,938,955`、`AdminModelProfileController:621,827,856,874`、`AdminProviderConnectionController:97,118,140` | 全部只判 `code`，`success` 冗余未用 |
| **C · 纯 `success`** | `success:true/false` + `message`/`error`/`detail`，**无 `code`** | `/admin/settings`(POST)、`/admin/settings/test`、`/admin/models`、`/admin/instances/{id}/{mute,restore,offline}`、`/admin/infra`(POST)、`/admin/infra/test`、`/admin/prompts`(POST) | `AdminController:232,284,427,483,514,796,813,830,1032,1068,1080,1218` | `data.success` / `r.success`（共 7 处） |
| **D · 裸对象** | 无任何标识，直接是数据体 | `/admin/session`、`/admin/settings`(GET)、`/admin/domains`(GET)、`/admin/instances`(GET) | `AdminController:139,591,727` | 直接读字段，不判 |

**这张表推翻了原稿的两个说法，也决定了 P2 的写法**：

- 原稿说「两套信封并存」，实际是三类 + 一类裸对象。**B 类最阴**：后端两个键都写，前端只用其中一个，改哪边都不会立刻炸，但两边语义迟早分叉。
- 原稿设想的「业务失败一律 reject」**直接落地两头都不对**。C 类接口没有 `code` 字段，于是：
  - 沿用现状写法 `r.code && r.code !== 0` → `undefined` 短路 → C 类失败被**静默吞掉**（漏报）
  - 改成 `if (r.code !== 0) throw` → `undefined !== 0` 为真 → C 类全部**误报失败**（误报）

  两种都错，所以 `normalize` 必须按 code → success → 裸对象三级降级，不能一条规则套全场。

## 3. 方案总览（P 轨五阶段 + V 轨五阶段，各自可独立上线）

| 阶段 | 内容 | 工作量 | 风险 | 止损点 |
|---|---|---|---|---|
| P0 | 基线快照 + 页面/信封清单入档 | 0.5d | 无 | — |
| P1 | 最小构建（esbuild），脚本外提 | 1.5d | 低 | **必做**，做完即有价值 |
| P2 | 模块化 + api 层收敛三类信封 | 3-4d | 中 | 只做 1 页验证再决定全量 |
| P3 | ESLint/Prettier + playwright 冒烟 | 1.5d | 低 | 与 P1 合并先做 |
| P4 | 运维中间件 iframe 拼装（可选） | 0.5d | 低 | 随时可砍 |

**执行顺序建议改为 P0 → P1 + P3 并行 → 只迁 1 个小页验证 → 再决定 P2 全量。** 原稿是「全都要」的线性排期，没有止损点；P1+P3 约 2.5-3d，跑通后就能判断 P2 那 3-4d 值不值得投。

**V 轨（视觉，见第 9 章）与 P 轨正交**，可随时插入，但同一时段只做一条：

| 阶段 | 内容 | 工作量 | 风险 | 止损点 |
|---|---|---|---|---|
| V0 | 准入检查 + 命名冲突审计 | 0.5d | 无 | **前置**，不通过就不动 |
| V1 | 令牌换皮（HTML 零改动） | 1d | 低 | 做完即是一层底子，但视觉变化有限 |
| V2 | 按组件替换（跨页批量） | 2-3d | 中 | 每类组件一个 commit，可停 |
| V3 | 侧栏与布局 | 1d | 中 | 单点改造，回滚成本低 |
| V4 | 交互 JS（可选） | 1d | 中高 | **默认不做** |

V 轨的最小可用组合是 **V0 + V1（约 1.5d）**，产出是「底座对齐」：配色、阴影、边框、字体已是 Tabler 色系，但组件形状仍是自写样式。**要看到 Tabler 的样子必须走 V2。** 它与 P1+P3 可以前后脚做，互不阻塞。

## 4. P0 · 基线快照（产出物定义）

原稿只写了「0.5d」，没说交付什么。P0 必须产出四样东西，否则后面每一步都没法判断「有没有搬坏」：

1. **页面清单**：12 个页面 × URL × 关键 DOM 锚点（如 `#domainList`、`#mcpList`），直接喂给 P3 冒烟
2. **信封形态对照表**：2.1 的完整版，逐接口列（形态 / 标识键 / 前端文件:行号 / 后端文件:行号）。这是 P2 唯一的施工图
3. **基线截图**：每页一张，作为「DOM 与视觉五不动」的视觉基线
4. **接口调用清单**：页面 → 接口映射，标出被多页共用的接口（改 `console.js` 时的影响面）

**done 定义**：四份清单落在 `docs/console-baseline/`；抽样 3 个接口用 `curl` 带登录 Cookie 实打一遍，确认对照表不是纸上猜的。

## 5. P1 · 最小构建

```
domainplane-server/
├── frontend/                        # 源码（不进 jar）
│   ├── package.json                 # 依赖：esbuild + eslint + prettier
│   ├── build.mjs                    # 多 entry 构建
│   └── src/
│       ├── console.js               # 现有 console.js 平移（保留全局 Console 出口）
│       ├── core/{request,guard,dom}.js
│       ├── ui/sidebar.js
│       └── pages/{domains,models,mcp,...}.js
└── src/main/resources/static/console/
    ├── *.html                       # 只改 script 引用这一行
    └── assets/console.css           # 保留（手写，不参与构建）
# 构建产物：target/classes/static/console/assets/{console.js,page-*.js}（不入源码目录、不入 git）
```

页面 HTML 只改一行：`<script>…页面逻辑…</script>` → `<script src="assets/page-domains.js"></script>`。

**为什么是 esbuild 不是 vite**：12 个静态页 + 同源部署，不需要 dev server / HMR / 插件生态；esbuild 单依赖、构建 <1s、产物可控。将来真要拆 SPA 时，`core/` 与各页的纯逻辑模块可直接搬进 vite 工程，只重写 DOM 耦合层。

**为什么源码放 `frontend/` 不放 `static/`**：避免源码打进 jar。

### 5.1 TypeScript：本轮不引入（结论，不是可选项）

原稿写的「新代码 `.ts` + 老代码 `@ts-nocheck` + 不开 `strict`」是**成本全额、收益约等于 0**的组合：`@ts-nocheck` 一贴、`any` 一开、`strict` 一关，TS 就只剩「能写类型注解」，实际承担的只是 ESM 打包职责——而那是 esbuild 本来就干的事。

改为 **JS + JSDoc + 按文件开 `// @ts-check` + `tsc --noEmit` 检查**：

- 平移时不改一行业务逻辑，只补 JSDoc 注释
- 类型收益一分不少（编辑器补全、参数校验、`Console.request` 返回结构）
- 省掉 tsconfig 编译链、sourcemap 对不齐、产物路径这些纯成本
- 将来真要全量 TS，JSDoc 版能直接 `tsc --allowJs` 迁过去，不返工

**done 定义**：打出的 jar 里 `static/console/*.html` 已无内联业务脚本（只剩 `src=` 引用）；逐页与 P0 基线截图比对无差异。

### 5.2 产物不入 git，构建挂 Maven（改原稿结论）

原稿选「产物入 git + 提交前跑 build」，把一致性押在人的纪律上；风险表里自己也把「源码与产物漂移」列为首要风险，却给了最弱的对策。

改法：`frontend-maven-plugin` 在 `domainplane-server` 模块的 `prepare-package` 阶段执行 `node build.mjs`，产物写入 jar；`static/console/assets/*.js` 进 `.gitignore`。

三个顾虑逐个消解：

- **「部署链路会变」**——不变。插件自带 node 下载安装，`mvn package` 照样一条命令出包
- **「CI 要装 node」**——不用，插件管；只有首次构建需要能访问 node 分发源（内网可配镜像）
- **「IDE 里看不到产物」**——本地开发跑 `node build.mjs --watch`，与 Maven 无关

代价是首次构建多一次 node 下载，以及本地直接 `java -jar` 前要先打过一次包。**漂移从「靠人记得」变成「不可能发生」**，这个交换值得。

## 6. P2 · 四个真问题的修法

**6.1 内联脚本外提**：一页一个 `page-*.js` entry，先机械平移（`Console.renderSidebar(key)` / `Console.ready(load)` 调用点原样保留），冒烟全绿后才允许重构内部。`models.html` 分三批平移：渲染层 → 弹窗层 → 事件层，每批一个 commit。

**6.2 api 层收敛三类信封（重写）**

不能「非 0 即 reject」——理由见 2.1。正确做法是**先归一化，再给两个出口**：

```js
// core/request.js —— 只做归一化，不改变任何既有语义
// 返回 { ok, code?, message, data }
function normalize(raw) {
    if (raw && typeof raw.code === 'number') {          // A / B 类：以 code 为准
        return { ok: raw.code === 0, code: raw.code, message: pick(raw), data: raw };
    }
    if (raw && typeof raw.success === 'boolean') {      // C 类：以 success 为准
        return { ok: raw.success, message: pick(raw), data: raw };
    }
    return { ok: true, message: '', data: raw };        // D 类裸对象：视为成功
}
// pick(raw) = sanitizeError(raw.detail || raw.error || raw.message)
```

页面侧两个出口，**由页面自己选，不强行统一**：

- `api.get(path)` / `api.post(path, body)` → 返回 `data`，失败 `reject`（新代码用这个）
- `api.raw(path)` → 返回归一化后的完整对象（`instances.html` 这种要自己拼文案的用这个）

三条硬约束：

- **`code === 10002` 仍走 `redirectToLogin`**，不与 10003 混淆——`console.js:41-47` 的注释写清了原因（两者 HTTP 都是 401，只看状态码会让登录页输错密码被当成会话失效），平移时注释原样保留
- **文案不包装**：`detail` 优先于 `error`，再优于 `message`；`sanitizeError` 必须过一遍
- **B 类不动后端**：双写接口前端统一按 `code` 判（与现状一致），`success` 键留着不管——动它就是动后端，越界

**done 定义**：全站 `code !== 0` / `success` 判断只出现在 `core/request.js` 一处（页面文件 grep 结果为 0）；`instances.html` 的「不判成功」缺欠由 `api.post` 的 reject 路径顺带修掉。

**6.3 样式去重**：各页 `<style>` 里的 `pick-card / tag / modal` 片段确认与 `console.css` 重复后合并，页面只留真正 page-only 的规则。

**6.4 成功判断缺失**：`instances.html` 等页面从 `api.raw` 改 `api.post`，失败时走 `catch` 而不是继续 `alert` 后 `load()`。

## 7. P3 · 质量护栏

- **ESLint（flat config）最小集**：`no-unused-vars / eqeqeq / no-undef`；**Prettier** 与现状风格对齐（4 空格、单引号）
- **冒烟 `tools/smoke.mjs`（playwright）**，启停方式固定，不留二义：
  1. `DOMAINPLANE_SERVER_PORT=19527` 启动 `target/*.jar`，**不用 9527**（避免撞上开发者已跑的实例，也避免连到旧包）
  2. 配置目录指向一次性临时目录——冒烟要写 `settings/prompts/infra`，绝不能落到真实配置上
  3. `POST /admin/login` 取 Cookie → 逐页断言：HTTP 200、无 `pageerror`、sidebar 渲染 9 个 `nav-item`、P0 清单里的关键元素存在
  4. 两条链路用例：未登录访问内页 → 跳登录页；清 Cookie 后调接口 → 跳登录页
  5. `finally` 里 kill 进程 + 删临时目录；端口占用直接 fail，不 fallback
- 冒烟同时是「搬页面没搬坏」的回归网：每平移一页跑一次，全绿才进下一页

**done 定义**：干净环境（只有 JDK）下 `npm run smoke` 退出码 0；故意改坏一个选择器时能红。

## 8. P4 · 运维中间件拼装（可选，infra.html）

沿用芋道模式（iframe + URL 配置化），不占前端工作量。以下按 Spring Boot 3 的实际配置方式写，不是「挂个路径」：

**actuator**

```yaml
management:
  endpoints:
    web:
      base-path: /admin/actuator      # 改的是 base-path，不是拼 URL
      exposure:
        include: health,info
  endpoint:
    health:
      show-details: never             # 保持默认，不吐组件明细
```

配套改 `WebMvcConfig.ADMIN_EXCLUDES` 加 `"/admin/actuator/**"`——actuator 端点不走 Cookie 鉴权，若还挂在 `/admin/**` 拦截下会被一律 401。exclude 后 `health/info` 匿名可读，这是**有意接受**的取舍（不含凭据与业务数据）；要更严就把 base-path 改成随机串，靠不可猜替代鉴权。**不要**停在「既 exclude 又以为还有鉴权」这种状态。

**springdoc-openapi + Knife4j**

```yaml
springdoc:
  api-docs:
    path: /admin/api-docs           # 默认 /v3/api-docs 不在 /admin/** 下，等于裸奔
  swagger-ui:
    path: /admin/swagger-ui.html
```

两个路径都要进 `ADMIN_EXCLUDES`（swagger-ui 会连带请求 `/admin/swagger-ui/**` 下的静态资源，exclude 要写通配），否则文档页自己就被拦。

**明确不引入**：Spring Boot Admin（独立 server 对单机管控台过重）、Druid（不换连接池）、Sentinel/Nacos 那类自带完整控制台的中间件（那是另一个工程，拼 iframe 即可）。

**done 定义**：infra.html 两个 iframe 能打开，actuator 只回 `health/info`、其余端点 404；`/admin/settings` 未登录仍 401。

## 9. V 轨 · Tabler 样式接入

**为什么单开一条轨**：工程化和换皮是两件事。塞进同一次提交，出问题时既分不清是「文件搬坏了」还是「样式换坏了」。V 轨的提交只含 CSS / class 属性 / 侧栏结构，不夹杂脚本外提。

### 9.1 选型落定

| 项 | 结论 |
|---|---|
| 包 | `@tabler/core@1.6.1`，MIT |
| CSS | `dist/css/tabler.min.css`（UI kit 全量，Bootstrap 5 已在包内，**不要再引 bootstrap.css**） |
| 令牌 | `dist/css/tabler-props.css`（纯 CSS 变量，独立可选）—— V1 的主力 |
| JS | `dist/js/tabler.min.js`（含 Bootstrap JS + Popper）—— **V4 之前不引** |
| 不引 | `dist/libs/**`（ApexCharts 等第三方：体积大，ApexCharts 5 起已非纯 MIT，商用需按其营收门槛付费） |

本地化：文件放 `static/console/assets/vendor/`，**入 git**。这与「自研产物不入 git」不矛盾——第三方固化产物需要可离线、可审计、版本可回溯。

### 9.2 三条准入红线（V0 不过就不动手）

1. **浏览器下限**。Tabler 1.6.1 的 CSS 用了 `light-dark()` / `color-mix()` / `:has()` / `@property`，**且不提供降级**。实际下限：Chrome/Edge ≥ 123、Firefox ≥ 128、Safari / iOS ≥ 17.5。私有化交付的客户环境必须先确认；做不到就退回「只借 Tabler 的配色与间距数值，不引 tabler.min.css」。
2. **全局 reset 必须拆**。`console.css:21` 的 `* { margin:0; padding:0 }` 与 `body { font-size:14px }` 会压平 Tabler 组件内部排版（Tabler 靠 reboot + 变量控制间距）。引 tabler.css 前先删这两条，交给 Tabler 的 reboot。
3. **裸元素选择器必须收口**。`button`、`table`、`th/td`、`input:not([type=checkbox])`、`select`、`textarea`（`console.css:151/184/427/630` 一带）会盖住所有 `.btn / .table / .form-control`。要么删掉交给 Tabler，要么用 `:where()` 把这些规则压到最低优先级。

### 9.3 命名冲突审计（V0 交付物）

**已确证同名不同义**——直接引 tabler.css 会立刻错乱，必须先加前缀（建议 `dp-`）：

| 现有类 | `console.css` 里的行为 | Tabler / Bootstrap 同名含义 | 处理 |
|---|---|---|---|
| `.card` | 单层容器，`padding:20px`、`radius 8`、`margin-bottom:20` | flex 列容器，内边距在 `.card-body` 上 | 改名 `.dp-card` |
| `.card-body` | `display:flex; gap:18px` | `flex:1 1 auto; padding` | 改名 `.dp-card-body` |
| `.row` | `grid` 两列表单 | flex 行 + 负 margin 栅格 | 改名 `.dp-row` |
| `.nav` | 纵向 flex 列表 | `flex-wrap:wrap` 导航容器 | 改名 `.dp-nav` |
| `.nav-item` | 按钮式 `<a>` | 列表项 | 改名 `.dp-nav-item` |

改名量实测：`.card*` 命中 76 行（9 个文件）、`.row` 命中 24 行（5 个文件）。机械替换，grep 可验证。

**待核对**（V0 时用 DevTools 在 preview.tabler.io 上逐个查是否命中）：`.tag` `.chip` `.stat` `.empty-box` `.seg` `.mbadge` `.count-badge`。
**已确认不冲突**：现有模态是 `.modal-mask / .modal-panel / .modal-head / .modal-close`，与 Tabler 的 `.modal / .modal-dialog / .modal-content` 不同名。

**顺序不能反**：先改名 → 再引 tabler.css → 再映射 token。先引 CSS，12 页会在冲突类上当场错乱。

### 9.4 V1 · 令牌换皮（HTML diff 必须为 0）

**先划清 V1 能得到什么**：配色、阴影、边框色、字体栈。Tabler 的组件外观（卡片头部、表格节奏、按钮尺寸）来自 min.css 的类规则，V1 拿不到——那是 V2 的事。**不要把 V1 当换皮验收**，它只是底座对齐。

**只引 props、不引 min.css**（已实测确认）：`tabler-props.css` 只有基础令牌（色板 / 字号 / 圆角 / 阴影），`--tblr-body-bg`、`--tblr-border-color`、`--tblr-bg-surface` 这类语义层变量**只在 `tabler.min.css` 里**。所以由 `console-tokens.css` 按 light 模式取值补齐 6 个。

这个取舍换来两件事：① 不引 min.css 就没有 reboot 副作用（`ol/ul` 缩进、`a` 下划线等 13 条裸元素规则全部不生效）；② 浏览器下限从 Chrome 123 / Safari 17.5 降到 **Chrome 111 / Safari 16.2**（只剩 `oklch` 与 `color-mix` 两个依赖）。

映射表（已用 `assets/vendor/tabler-props.css` 实测核对，不再有「待核对」项）：

| 现有变量 | 映射目标 | 实测值 |
|---|---|---|
| `--primary` | `--tblr-primary` | `oklch(54.6% 0.1724 254.2deg)` |
| `--muted` | `--tblr-secondary` | `oklch(55.55% 0 0deg)` |
| `--green` / `--amber` / `--red` | `--tblr-success` / `warning` / `danger` | oklch 色板 |
| `--border` | `--tblr-border-color` | `light-dark(gray-200, …)` |
| `--bg` / `--card` | `--tblr-body-bg` / `--tblr-bg-surface` | `gray-50` / `#fff` |
| `--primary-dim` | `color-mix(in oklab, var(--tblr-primary) 8%, #fff)` | 原来的 `#eff6ff` 是实色，直接用 `--tblr-primary-lt` 会变半透明，故自算 |
| 卡片阴影 | `--tblr-shadow-card` | `0 1px 2px 0 color-mix(…)` |
| 输入框阴影 | `--tblr-shadow-input` | 同上 |
| 字体栈 | `--tblr-font-sans-serif` | `system-ui, -apple-system, …, Segoe UI, Roboto` |

**只选一个方向**：现有变量指向 `--tblr-*`。反向再定义会让两套变量互指成环。

**不要用 `--tblr-*-rgb`**：1.6 起是静态值（不跟随 `--tblr-primary` 覆盖），2.0 移除。要透明色用 `color-mix(in oklab, var(--tblr-primary) 20%, transparent)`。

**done**：`console-tokens.css` 里引用的变量 0 缺失（已有自检脚本）；12 页与基线截图比对无意外位移；`*.html` 的 git diff 为空。

### 9.5 V2 · 按组件替换（不是按页面）

按页面推进会得到 12 种按钮；按组件推，同类一次到位。

| 序 | 组件 | 做法 |
|---|---|---|
| 1 | 按钮 | 删 `button` 元素规则 → `.btn` + `btn-primary/secondary/danger`；`.ghost/.sec/.danger` 三个修饰映射到 `btn-outline-*` |
| 2 | 表单 | `.field` → `.mb-3` + `.form-label`；`input/select/textarea` → `.form-control / .form-select` |
| 3 | 表格 | `table/th/td` → `.table` + `.table-vcenter`；`.table-wrap` 可留（替代 `.table-responsive`） |
| 4 | 徽标 | `.tag/.chip/.mbadge/.count-badge` → `.badge` + 语义色 |
| 5 | 空状态 | `.empty-box` → `.empty` |

**卡片（`.dp-card`）不进 V2**——这是本节唯一的例外，必须单独决策：Tabler 的卡片视觉建立在 `.card > .card-body` 两层结构上，现有 `.dp-card` 是单层带 padding。只改名不改结构，拿不到 Tabler 卡片的圆角/边框/阴影；要拿就得动 DOM，违反五不动。**结论：卡片只借 token，视觉继续自维护。**

**模态**同理：结构不动，只把边框/圆角/阴影换成 `--tblr-*`，不引 JS。

纪律：每类组件一个 commit；删旧 CSS 规则前先 grep 确认无引用（HTML / JS 里的类名算引用，`.md` 里的说明不算）。

**done**：`console.css` 里该类组件的手写规则已删除，12 页该类组件外观一致。

### 9.6 V3 · 侧栏与布局

最佳切入点：侧栏 HTML 由 `console.js:147-171` **单点生成**（`renderSidebar` + `NAV` 数组），改一处即全站生效，回归面最小。

- 改：`.sidebar / .brand / .nav / .nav-item / .sidebar-foot` 五块，允许小幅调整结构（集中一处，风险可控）
- 不改：`.layout / .main` 保持自写。Tabler 的 `.page / .page-wrapper` 会牵动 12 页最外层，收益不值这个改动面

**done**：9 个 `nav-item` 正常渲染、active 高亮正确、`warnAnchor` 的提示点仍在、窄屏（<860px）转横排不塌。

### 9.7 V4 · 交互 JS（默认不做）

引 `tabler.min.js` = 引入 Bootstrap JS + Popper。收益是 modal / dropdown / tooltip；代价是：

- 与现有手写模态（`hidden` 属性 + `.modal-mask`）并存 → 两套交互逻辑
- `data-bs-toggle` 与现有 `addEventListener` 绑定重复，一次点击触发两次
- 破坏「零依赖 IIFE」，页面多一个 30KB+ 脚本

**结论：除非要做当前没有的 dropdown / tooltip / tab，否则不引。** 现有模态跑得好，不需要为了「用上 Tabler」而换掉它。

### 9.8 与 P 轨的接口

- V1 不依赖 P1 的构建：`console-tokens.css` 是手写 CSS，可直接放 `static/`；后续也可纳入 esbuild 的 css entry
- P3 冒烟是 V 轨每步的回归网，但冒烟只断言元素存在——**视觉回归靠人工比对 P0 基线截图**，V2 每类组件改完存一组图
- P2（信封）与 V 轨零耦合，可并行

### 9.9 工作量与建议

V0 0.5d + V1 1d + V2 2-3d + V3 1d = **4.5-5.5d**（不含 V4）。

V0+V1 已完成（见 `docs/console-v0-audit.md`）。**V2 才是真正换皮的那一步**，建议先挑一个页面（`instances.html` 最简单）把按钮 + 表单两类组件换掉，看效果是否符合预期，再决定是否全量推。

## 10. 迁移顺序与回滚

`console.js` → `login/overview/account` → `domains/instances/prompts/knowledge` → `mcp` → `models`（1770 行最后动）。

每阶段独立 commit；回滚 = revert 该阶段涉及目录；冒烟全绿才进下一阶段。

**纪律**：任何阶段停下来，系统都保持可部署状态；不停在「构建装了但产物没进 git」这类中间态——本轮已用 Maven 构建把这类中间态从流程里删掉（5.2）。

## 11. 风险与纪律

| 风险 | 对策 |
|---|---|
| 源码与产物漂移 | `prepare-package` 强制生成（5.2），产物不入 git |
| 平移笔误 | 冒烟兜底；models 分批平移，每批一个 commit |
| **信封归一化后漏判** | C 类接口无 `code`；`normalize` 按 code → success → 裸对象三级降级，禁止只判 `code` |
| 冒烟污染真实配置 | 独立端口 + 一次性配置目录（第 7 节第 2、3 条） |
| 过度工程诱惑 | 明确**不引入**：vite/dev-server/HMR、组件框架、状态管理、微前端、SPA 路由、全量 TypeScript；V4 的 Bootstrap JS 默认也不引 |
| **Tabler 浏览器下限**（Chrome/Edge 123、Safari 17.5） | V0 先确认交付环境；不达标就只借配色与间距数值，不引 `tabler.min.css` |
| **同名类冲突**（`.card/.card-body/.row/.nav/.nav-item`） | V0 改名加 `dp-` 前缀；顺序是「先改名、再引 CSS」，不可反 |
| **全局 reset 压平 Tabler 排版** | 删 `*{margin:0;padding:0}` 与 `body{font-size:14px}`，交给 Tabler reboot |
| **两轨混在同一次提交** | V 轨提交只含 CSS / class 属性 / 侧栏结构，不夹脚本外提 |

**估时修正**：原稿 5-6 人日偏乐观。`models.html` 1770 行三批平移 + 每批冒烟，P1+P2 实际接近翻倍；P1+P3 先行约 2.5-3d，跑通再决策 P2。
