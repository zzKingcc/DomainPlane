添加模型

决定用哪套协议发请求：除「OpenAI 兼容」外的协议在鉴权头与请求体上都不同， 选错会直接跑不通。DeepSeek / 硅基流动 / OpenRouter / 百炼兼容模式 / vLLM / LM Studio 都选「OpenAI 兼容」。
选中后自动填好下方「服务商协议」与「服务商地址」，密钥仍需自己填。
点右侧按钮从「连接库」选用 —— 一条连接＝服务商地址 +（可选）密钥，选中后两项一起填入 （页面右上角可维护）；也可直接手填。
本地 Ollama：协议选「Ollama」时地址填 http://localhost:11434（不要带 /v1， 程序会自己拼 /api/chat），无需密钥， 模型名取 ollama list 里的名字（带 tag，如 qwen2.5:7b）。
从连接库选用时会自动带入；也可以直接粘贴。
点右侧按钮拉取候选（仅候选池）。
识别结果 尚未读取
只读提供商的 /models，不发任何试探请求（向量档案会多发一条极短的 /embeddings 实测维度）
服务商未必公开全部信息：布尔能力（流式 / 工具调用）在 OpenAI 规范的 /models 里根本没有，会一直显示"未读到"。 此类档案仍可保存，但绑到域上时工具会静默不生效。
未声明时按默认温度发给服务商 —— 不设这一项的话各家端点各给各的 （常见 0.7 / 1.0），换个服务商行为就变了且没有提示。
留空即不限制：不向服务商发送 max_tokens，由模型与上下文长度决定； 只有填了值才会对单次输出设上限。
开启（发给服务商 enable_thinking）
关掉能让回答更快，也不再产生用户看不到的思考开支 （实测思考可占输出的 95%）。
输出（交平台解析）
展示思考的通道尚未接入，目前只决定平台解不解析，不改变页面展示。
向量维度必须与 ES 索引 mapping 一致；改维度后必须重建知识库索引， 否则新旧向量长度不符，写入会被 ES 拒绝。

服务商连接库

按唯一名称存放「服务商地址 + 密钥」。模型档案表单的服务商地址输入框右侧有下拉， 选中一条即把地址与密钥一起填入。列表里密钥只显示脱敏值。
自建端点（Ollama / vLLM / LM Studio）也走 OpenAI 规范， 地址通常需要带 /v1。
落盘位置：—。 删除只影响这个库 —— 已保存的模型档案各自存的是独立副本，不会被牵连。
