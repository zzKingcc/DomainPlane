ES 版本支持范围 9.x 已验证 8.x 大概率可用 7.17 存疑 7.x 及更早 / OpenSearch 不承诺
为什么不按版本号拦截？缺 IK 分词器会怎样？
  • 版本号不等于能力。平台真正依赖的只有少数接口： info / ping / count / search / indices.* / bulk，以及 index: true 的 dense_vector。而且版本号可能合法地拿不到（只读账号没有 cluster monitor 权限）——"读不到就拒绝"等于逼你换成高权限账号。
  • 9.x：与平台内置客户端（Elasticsearch Java Client 9.4.4）同主版本，官方兼容矩阵保证。
  • 8.x：上面那些接口在 8.x 全部具备（index: true 的 dense_vector 正是 8.0 起的特性），但官方矩阵只保证同主版本， 8.x 未经实测 —— 以「测试连接」和一次知识库重建的实测结果为准。
  • 7.17 及更低：dense_vector 不支持 index: true， 维度上限也只有 1024，索引 mapping 会创建失败。
  • IK 分词器是插件，任何版本的 ES 都要单独安装。缺它的后果最隐蔽： IK mapping 创建失败后会回退到 ES 默认分词器 —— 索引照样建、灌库照样成功， 只有中文检索质量下降，而且不报错。 点「测试连接」会直接告诉你 IK 是否可用；换 ES 实例后务必点一次。
  • ES 8.x 起默认启用 HTTPS 与安全认证：协议要填 https 且必须带账号； 对方若用自签证书，当前会报 TLS 握手失败（暂不支持导入自签证书）。

Redis 支持范围 2.6 及以上全部支持 集群模式需用 0 号库
为什么 Redis 不判版本、只看拓扑？
  • 平台只用到 GET / SET / PING / INFO / DBSIZE，Redis 2.6 以上全都支持， 版本号没有判读价值，只做展示。
  • 真正的断点是拓扑：集群模式与多数云托管只提供 0 号库， 填别的库号会直接失败，而且报错看不出是"这个实例没有多库"。 「测试连接」会报出实例拓扑与库号范围。
  • 数据靠 domainplane: key 前缀隔离，与业务共用同一个库也不冲突。
必填。不填则视为未配置：服务照常启动，但会话记忆与中断断点在首次使用时失败。
库号，默认 0。平台数据靠 domainplane: key 前缀隔离，与业务同库也不冲突； 集群模式或云托管只提供 0 号库时，保持默认即可。 ⚠️ 换地址或换库号等于换数据源：历史会话与未完成的断点留在旧库，不会迁移。
