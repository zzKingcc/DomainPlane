## 维护约定

1. **设计只维护一份**：`设计文档.md` 是唯一设计说明，不新建第二份。评审、分析、计划都是它的**外围**，不得重复描述机制。
2. **计划完成即转记录**：一份计划做完后压缩成"决策 + 结果 + 遗留 + 坑"，删除施工过程。施工过程归 git 提交信息。
3. **快照不留**：页面清单、接口清单、行号对照这类"某一刻的扫描结果"，用过就删——它们必然过期，且能用脚本重生成。
4. **只写可验证的事实**：推测项单列「观察点」，不混进正文。
5. **数字带口径与日期**：类数 / 行数按 `src/main/java` 下 `.java` 的**非空白行**（含注释）统计；与其他口径（物理行）不可混用。凡聚合数字都标测于哪天。
6. **交叉引用用相对路径**，重命名文档时必须同步全仓 grep 修正。
7. **版本号只改一处源头**：`pom.xml` 的 `<version>` 是唯一源头；改版时同步派生位置——`docs/assets/badge-version.svg`（顶部徽章的 `aria-label` / `<title>` / 显示文本 / 画布宽度四处）、`README.md` 示例里的 Maven 坐标、`Dockerfile` 的 `COPY … .jar` 文件名。`domainplane-server/pom.xml` 的 `finalName` 取 `${project.version}`，无需手改。
8. **徽章用仓库内 SVG，不用外链**：本项目部署在内网、构建机无法访问 shields.io（实测超时），外链徽章会渲染成坏图。徽章文件在 `docs/assets/`，改版只改 SVG，不加 `img.shields.io` 地址。
